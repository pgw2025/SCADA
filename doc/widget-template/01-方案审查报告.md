# 01 · 方案审查报告（v1.0 → v2.0 修正）

> 审查对象：上一轮给出的「方案 A+B：模板入库 + SVG 模板渲染引擎」
> 审查方式：对照实际代码逐项核实（文件 / 行号见下文）
> 结论：**总体架构成立，但存在 13 项必须修正的问题与 10 项优化点**，本报告逐项给出修正方案。

---

## 一、必须修正的问题（正确性 / 阻塞性）

### A1. 内置种子数量错误：是 24 条，不是 22 条

v1.0 方案多处写「22 个组件」。核实 [widgetRegistry.ts](../../Client/src/widgetRegistry.ts#L113-L517)：

- 注册键共 **24 个**：22 个唯一 renderType + 复合键变体 4 个（`title-header-tech-desktop` / `title-header-tech-mobile` / `nav-menu-desktop` / `nav-menu-mobile`，其 `type` 分别为 `title-header` / `nav-menu`）。
- 唯一 renderType 共 **22 个**。

**修正**：种子表 24 条（详见 [05-数据协议与种子清单.md](05-数据协议与种子清单.md)）；`SortOrder` 按注册表声明顺序编码，保证 `title-header` 泛化匹配优先命中 desktop（与现行为一致）。

### A2. 遗漏 legacy 类型 `button`

[HMIWidget.vue](../../Client/src/components/HMIWidget.vue#L51) 的 `widgetMap` 含 `button: ButtonWidget`，但 [widgetRegistry](../../Client/src/widgetRegistry.ts#L113-L517) **没有** `button` 注册项（旧版本组件，已从图库移除但 widgetMap 保留兼容）。存量页面可能仍存有 `type='button'` 的组件。

**修正**：`builtinRenderers` 映射必须保留 `button → ButtonWidget`（23 个 SFC 映射，其中 22 个对应种子模板、1 个为 legacy 兼容），但**不进种子表、不进组件库列表**（与现状一致）。回归验收中增加「存量 button 组件渲染正常」用例。

### A3. 模板实体遗漏 `IconColor` 字段

[WidgetDef](../../Client/src/widgetRegistry.ts#L54-L66) 含 `iconColor: string`（Tailwind 类，如 `text-amber-500`），[WidgetLibrary.vue L126](../../Client/src/components/WidgetLibrary.vue#L126) 以 `:class="widget.iconColor"` 应用。v1.0 的实体 / DTO / 导入导出格式 / 种子数据均未包含此字段 → 动态化后所有 lucide 图标丢失颜色。

**修正**：`HmiWidgetTemplate` 增加 `IconColor` 列（`MaxLength(64)`，可空字符串）；DTO、导入导出协议、种子表同步补充。

### A4. `ComponentType` 联合类型阻塞编译（关键决策 D9）

以下位置均为强类型 `ComponentType`：

- [types.ts L144](../../Client/src/types.ts#L144)：`HMIComponent.type: ComponentType`
- [ScadaTopologyView.vue L479](../../Client/src/components/ScadaTopologyView.vue#L479)：`handleAddWidget(type: ComponentType, …)`
- [WidgetLibrary.vue L13](../../Client/src/components/WidgetLibrary.vue#L13)：emit 签名 `(e: 'addWidget', type: ComponentType, …)`
- [widgetRegistry.ts L56](../../Client/src/widgetRegistry.ts#L56)：`WidgetDef.type: ComponentType`

自定义 SVG 模板的 renderType 不在 22 个联合成员内 → **拖拽落布链路 TypeScript 编译失败**。

**修正（D9）**：
- `HMIComponent.type`、`WidgetDef.type`、`handleAddWidget` / `handleAddWidgetAt` 参数、`WidgetLibrary` emit 签名统一放宽为 `string`；
- `ComponentType` 联合类型保留导出（作为内置类型的字面量提示，供 switch/比较继续获得智能补全）；
- 全局 `=== 'xxx'` 字符串比较（InspectorPanel ×11、CanvasPanel ×10、HMIWidget 排除列表）**不受影响**，无需改动；
- 配套 D10：自定义 SVG 模板 `TemplateKey = RenderType`（同一值），落库 `HmiComponent.Type` 即 templateKey，`getWidgetDef` 精确命中，`defDefaults` 兜底正确。

### A5. `WidgetLibrary.vue` 的列表 key 用了 `name`

[WidgetLibrary.vue L119](../../Client/src/components/WidgetLibrary.vue#L119) `:key="widget.name"`。动态模板允许同名（用户可建两个「定制泵」）→ Vue key 冲突告警 / 渲染错乱。

**修正**：key 改为 `widget.key`（templateKey，全局唯一）。

### A6. `WidgetLibrary.vue` 缺少 svg / emoji 图标渲染分支

现模板只有 `iconKind === 'lucide'` 与三种 `div` 变体分支（L126-L130）。模板新增 `IconKind='svg' / 'emoji'` 时**无渲染分支，图标空白**。

**修正**：新增两个分支：
- `svg`：`<span v-html="sanitizeSvg(widget.iconKey)">`（小图标也走清洗，复用前端清洗函数）；
- `emoji`：`<span>{{ widget.iconKey }}</span>`（`IconColor` 仍作 class 应用）。

### A7. `widgetList` 从静态数组变为 computed 引用方式必须同步调整

[WidgetLibrary.vue L34](../../Client/src/components/WidgetLibrary.vue#L34) 现为 `widgetList.filter(…)`（模块级数组直接使用）。改造后 `widgetList` 为 `computed` ref，此处必须改为 `widgetList.value.filter(…)`，且 script 中其他直接引用处需逐一核查（v1.0 只在示例代码里体现，未列为明确改动点）。

**修正**：执行步骤中列为独立检查项；同时核查全部 `widgetRegistry` 依赖方（A8）。

### A8. widgetRegistry 转发层必须保留全部既有导出（否则 9 个文件编译失败）

`rg` 核实依赖方共 9 个文件、以下具名导入：

| 依赖文件 | 导入符号 |
|---|---|
| CanvasPanel.vue | `isControlWidget` |
| InspectorPanel.vue | `getWidgetDef` |
| inspector/TrendChartInspector.vue | `TREND_SERIES_PALETTE` |
| inspector/NavMenuInspector.vue | `MENU_ICON_OPTIONS`, `getMenuIcon` |
| ScadaTopologyView.vue | `getWidgetDef` |
| LayersPanel.vue | `getWidgetDef` |
| widgets/useWidgetBase.ts | `getWidgetDef` |
| WidgetLibrary.vue | `widgetList`, `WidgetDef` |
| widgets/NavMenuWidget.vue | `getWidgetDef`, `getMenuIcon` |

**修正**：转发层（新 `widgetRegistry.ts`）必须 re-export：`WidgetCategory`、`WidgetDef`、`widgetList`、`getWidgetDef`、`MENU_ICON_OPTIONS`、`getMenuIcon`、`CONTROL_WIDGET_TYPES`、`isControlWidget`、`TREND_SERIES_PALETTE`（内部实现迁移至 `builtinSeeds.ts` / `builtinRenderers.ts` / `widgetTemplates.ts`）。执行前用 `rg "from '.*widgetRegistry'"` 再复核一遍防止遗漏。

### A9. 后端 `DeleteAsync` 静默失败

v1.0 中 `IsSystem=true` 时 `DeleteAsync` 静默跳过并返回 204 → 前端误认为删除成功。

**修正**：`IsSystem` 模板删除时抛 `BusinessException("系统内置模板不可删除")`，由全局异常中间件转为 400 + `ApiResponse`；前端 `extractApiError` 直接展示文案。

### A10. 导入 rename 后缀的长度截断风险

v1.0 rename 策略：`$"{key}-imported-{Guid:N}"[..64]`。Guid 32 位 + `-imported-` 9 位 = 41 位后缀；若 key 本身较长，截断到 64 可能切掉 Guid 尾部导致唯一性丢失（极小概率但仍可构造）。

**修正**：后缀改为 `-{短随机码}`（8 位 Base36/时间戳），若超长则先截 key 再拼后缀，保证后缀完整。

### A11. 遗漏侧边栏菜单入口（仅加了路由）

v1.0 只在 `router/index.ts` 加路由。项目的导航菜单在 [App.vue](../../Client/src/App.vue)（`controller-management` / `connection-management` 等入口均在此）。

**修正**：执行计划中增加「App.vue 侧边栏新增『组件模板管理』入口（ADMIN_ROLES 可见）」的独立步骤。

### A12. SVG 清洗存在三类绕过

v1.0 前后端清洗遗漏：

1. **内联 `style` 的 `url(...)`**：`style="background:url(http://evil/x.png)"` 可外联加载（隐私泄露 + 内网探测）；
2. **多行属性值绕过**：`href="htt\np://…"` 这类跨行值，正则未用 `RegexOptions.Singleline` 时 `.*?` 不跨行匹配 → 白名单校验被绕过；
3. **URL 白名单过宽**：`https?://` 全放行，`<use href="http://…">` 可引用外部 SVG 资源。

**修正**：
- 白名单收紧为 `#`（锚点）、`data:image/`（内嵌）、`/`（本站相对路径）三类；外部 http(s) 一律剥离（模板作者可把图片转 data-URI 内嵌）；
- 前后端正则统一加 `RegexOptions.Singleline`；
- 增加 `style` 属性内 `url()` 清洗（非白名单 URL 的 `url(...)` 置空）；
- 已知边界（登记不修）：`<animate attributeName="href">` 动画钓鱼场景，风险低，接受。

### A13. `DefaultPropsJson` / `PropSchemaJson` 无 JSON 合法性校验

后端 Create/Update 直接收字符串，坏 JSON 入库后前端 `JSON.parse` 抛错 → 组件库 / 属性面板崩坏。

**修正**：`ValidateAsync` 中对两个 JSON 字段做 `JsonDocument.Parse` 校验，非法即抛 `BusinessException`；前端管理页保存前同样 try-parse 并提示。

## 二、设计优化建议（非阻塞，但建议采纳）

| # | 优化点 | 理由 |
|---|---|---|
| B1 | **阶段重划**：v1.0 的 3 阶段粒度过粗（阶段 1 同时动后端 + 前端 + 种子），重划为 P0～P6 共 7 阶段 | 每阶段可独立构建、验证、回退；P1~P3 即满足原始需求 |
| B2 | **种子 JSON 用脚本生成而非手写**：执行时写一次性 Node 脚本 import 现有 `widgetRegistry`，序列化 24 条 defaultProps 求值结果输出 C# 种子代码 | 避免手写 24 份 JSON 的笔误（`var-display` 的 `thresholdMin/Max` 为 **null**、`image` 无 baseProps、`multi-var-dashboard` 含演示 items——这些特例极易写错） |
| B3 | **批量导入导出（D11）**：导出支持勾选多条打成一个 `templates[]` 文件；导入兼容单对象与数组 | 实际迁移场景都是整库搬迁 |
| B4 | **组件缺失兜底卡升级**：`HMIWidget` 未知类型提示中给出「前往模板管理」入口（编辑态） | 模板误删后的可恢复路径 |
| B5 | **SVG 轨默认 props 预填**：管理页新建 SVG 模板时，`DefaultPropsJson` 预填绑定上下文默认值（activeColor/inactiveColor/unit/threshold 等） | 降低模板作者心智负担 |
| B6 | **模板变更即时生效**：管理页保存成功后本地刷新 store 即可；不做 SignalR 推送（登记为已知限制：多用户并发下其他会话需刷新页面才看到新模板） | 避免过度工程 |
| B7 | **Store 风格**：模板源采用模块级单例（`widgetTemplates.ts`）而非 Pinia | 与 `widgetRegistry` 既有模块级导出风格一致，转发层最薄；依赖方均为直接 import |
| B8 | **首帧闪变说明**：store 异步加载完成前组件库用本地种子渲染，到达后替换；因种子与 DB 初始数据一致，视觉无差异 | 明确时序预期，避免实施时过度设计 Suspense |
| B9 | **HMIWidget 通用浮签**：[HMIWidget.vue L83](../../Client/src/components/HMIWidget.vue#L83) 的 showValue 排除列表为硬编码，自定义 SVG 模板不在列表内 → 若模板 defaultProps 含 `showValue: true` 会显示浮签 | 行为可接受（浮签本就是通用能力），登记为已知行为；SVG 模板默认 props 不预填 showValue 即无感知 |
| B10 | **导入大小限制**：`SvgTemplate` 列限长 256KB，前端上传前校验文件 ≤ 1MB | 防超大文件拖垮 DB 与渲染 |

## 三、修正后的方案差异摘要（v1.0 → v2.0）

| 维度 | v1.0 | v2.0（本套文档） |
|---|---|---|
| 内置种子 | 22 条 | **24 条**（+ legacy `button` 仅保留渲染映射） |
| 模板字段 | 缺 IconColor | 增加 `IconColor` |
| 组件类型 | 未处理 ComponentType 阻塞 | D9：类型放宽为 string + D10：SVG 模板键唯一 |
| 删除语义 | IsSystem 静默跳过 | 抛 BusinessException |
| rename 后缀 | Guid 截断风险 | 8 位短随机码 |
| SVG 清洗 | 基础三条正则 | + style url() 清洗、Singleline、白名单收紧 |
| JSON 校验 | 无 | 前后端双重 parse 校验 |
| 菜单入口 | 仅路由 | + App.vue 侧边栏入口 |
| 阶段划分 | 3 阶段 | 7 阶段（P0~P6） |
| 导入导出 | 单模板 | 单 + 批量（templates[]） |
| 列表 key | widget.name（隐患） | widget.key |
| 图标形态 | svg/emoji 无渲染分支 | 补全 4 种分支 |

- 后端成功返回裸 DTO（`Ok(dto)`）、错误统一 `ApiResponse`；前端 `http` 实例已统一注入 Token 与 401 处理，`r.data` 直取 ✓

- 种子幂等模式（按 key 去重插入）与 `CreateDefaultProtocolsAsync` 等现有种子一致 ✓
