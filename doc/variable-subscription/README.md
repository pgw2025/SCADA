# 变量订阅更新（Variable Subscription）方案文档

## 1. 背景与目标

当前系统所有协议的变量采集统一走**自主轮询**：`DeviceWorker` 按变量级 `NextPollTime` 收集到期变量，调用驱动的 `ReadBatchAsync`/`ReadAsync` 拉取。OPC UA 驱动中虽已存在完整的 `SubscribeAsync`/`UnsubscribeAsync` 实现，但全库无任何调用方，属于闲置代码。

本方案将订阅更新功能补完并投入使用，实现：

- **用户可在设备变量列表中自由切换每个变量的更新方式**：自主轮询（Polling）/ 订阅推送（Subscription）；
- 订阅推送的值变化走与轮询**完全一致的消费管线**（工程换算 → 内存态 → 变化总线 → 通知推送 → 历史存储 → 实时快照 → 报警判定），两套来源行为不漂移；
- 订阅生命周期与连接共享架构（`ConnectionSession`）对齐：挂载即订阅、卸载即退订、会话重建自动重订；
- 首版范围：仅 OPC UA 驱动支持订阅（`SupportsSubscription`），S7/虚拟驱动声明不支持并在前后端禁用该选项。

## 4. 核心设计决策（速览）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 订阅身份 = `DataPointMapping.Id`（InstanceId），回调签名 `Action<int, object?, VariableQuality>` | 连接共享会话下多设备同名变量不冲突；回调不持有运行时对象引用，避免重载窗口内更新"已死"对象 |
| D2 | 值消费管线抽取为进程级单例 `VariableValueProcessor`，轮询/订阅两个入口共用核心 | 消除双管线漂移；管线生命周期独立于 `DeviceWorker` 实例 |
| D3 | 订阅协调归口 `ConnectionSession`：路由表 + 去抖 `ScheduleSync()` 差量同步 | 订阅生命周期与会话（驱动）天然绑定；多设备挂载/卸载合并为一次驱动往返 |
| D4 | 订阅失败**不回退轮询**：置质量 Bad + Warning + 退避重试 | v1 的"回退轮询"因 Worker 只收集轮询变量而不可实现；避免隐式降级造成行为不可预期 |
| D5 | Worker 空转分支删除无条件 `Connected` 赋值，改为 `IsAliveAsync` 周期探测看门狗 | 修复"纯订阅设备断线永远显示在线"；连接死亡检测以驱动状态为准，不用值陈旧度（OPC UA 只在值变化时发布通知，静态值长时间无回调是正常的） |
| D6 | 订阅回调打点 `LastCommunicationTime` + 清零失败计数 + 订阅健康证据参与轮次判定 | 防止混合设备因轮询变量坏地址误触发整条共享连接的重建 |
| D7 | 通知改经每设备有界通道 + 单消费者泵推送 | 订阅回调高频到达时避免每条通知一个并发 IO 任务导致堆积 |
| D8 | 协议能力查询放驱动工厂（`SupportsSubscription(protocolKey)`）而非驱动实例属性 | AppService 校验时无需实例化驱动 |
