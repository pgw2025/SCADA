## 阶段四：订阅协调器与生命周期接线（集成核心）

### Step 4.1 ConnectionSession 订阅协调器

**涉及文件**
- `Server/ScadaServer.Runtime/Connections/ConnectionSession.cs`
- `Server/ScadaServer.Runtime/RuntimeManager.cs`（会话构造传参）

**具体任务**
1. `ConnectionSession` 构造函数追加 `IVariableValueProcessor` 参数（`GetOrCreateSessionAsync` 处传入，注意 RuntimeManager 为协调器提供处理器实例）。
2. 新增路由表：`ConcurrentDictionary<int instanceId, (int DeviceId, VariableRuntime Vr)> _subscriptionRoutes`（Vr 引用仅用于构造驱动订阅调用与退订匹配；回调路由不依赖它，见下）。
3. 新增去抖调度 `ScheduleSync()`（决策 D3）：
   - `Interlocked` 交换标志防重入；`Task.Delay(100ms)` 合并窗口（P2-8）后执行 `SyncSubscriptionsAsync`；
   - 执行前检查会话 `_disposed`；
   - **调用方绝不在会话锁内 await 同步结果**——ScheduleSync 永远 fire-and-forget。
4. `SyncSubscriptionsAsync` 差量同步（全程**不持会话 `_lifecycleLock`**，驱动 IO 在锁外，P2-7 纪律）：
   - 快照期望集：遍历 `_mounted`，收集 `IsEnabled && UpdateMode == Subscription` 的 `(deviceId, vr)`；
   - 计算 `toAdd = 期望 - 路由`、`toRemove = 路由 - 期望`；
   - `toRemove` 非空 → `await driver.UnsubscribeAsync(...)`（传路由表中的 Vr 快照）；
   - `toAdd` 非空 → `await driver.SubscribeAsync(toAdd, OnSubscriptionValue)`；
   - 成功后更新路由表；快照竞争（同步期间挂载/卸载变化）由下一次去抖同步收敛。
5. `OnSubscriptionValue(int instanceId, object? value, VariableQuality quality)` 回调（P2-9 线程纪律，全程 try-catch）：
   - 路由表查 `instanceId` → 无（已退订）直接返回；
   - `_mounted` 查设备运行时 → 无（已卸载）返回；
   - `runtime.Variables` 查 `instanceId` → 无（重载窗口/变量已删）返回；
   - **通讯打点**（P1-2）：`runtime.LastCommunicationTime = now`；`runtime.ConsecutiveFailureCount = 0`；若 `ConnectionState == Error` 置回 `Connected`（状态自愈）；
   - `_processor.ApplySubscribedAsync(...)` fire-and-forget（处理器内部全链路异常兜底）。
6. 订阅失败处理（决策 D4）：`SubscribeAsync` 抛异常 → catch 后将本次 toAdd 变量置 `Quality = CommunicationError`（锁内写值）+ 记 Warning（连接上下文 + 变量数）+ 记录失败时间戳 → 以退避间隔（初始 30s，失败翻倍，上限 5min）调度下一次 `ScheduleSync`。不回退轮询。

**验收标准**：编译通过；手工验证：单设备切一变量为订阅后，模拟服务器改值 → 前端实时值/历史/报警全部更新。
