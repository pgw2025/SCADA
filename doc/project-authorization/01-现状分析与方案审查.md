# 01 · 现状分析与方案审查

> 本文记录组态工程授权功能的现状调研事实（文件、行号以 2026-09-05 代码为准），以及 v1 方案审查发现的 3 个问题与修订决策。是后续详细设计与执行计划的依据。

## 1. 现状代码事实

## 2. v1 方案审查：发现的问题

> v1 方案（数据模型 + GetListAsync 过滤 + GetTreeAsync 校验 + 授权端点 + 前端弹窗）主体可行，但存在以下问题，**P1 不修则授权形同虚设**。

### P1-1 授权边界不完整，存在 API 绕过（严重）

v1 只保护了 `ScadaProject` 端点，同一份数据还有旁路：

| 端点 | 现状授权 | 绕过效果 |
|---|---|---|
| `GET /api/ScadaPage`（`ScadaPageController.cs` L38） | 仅登录 | Operator 可按 `projectId` 枚举任意工程的页面数据 |
| `GET /api/ScadaPage/{id}`、`GET /api/HmiComponent`（L19） | 仅登录 | 组件数据（含 `BindVariableKey` 绑定变量）可被读取 |
| `GET /api/ScadaPage/{id}/export`（L82） | 仅登录 | **走 `ExportPageAsync` 直接查页面仓储，完全不经过 `GetTreeAsync`，v1 的授权校验拦不住**——未授权用户可导出任意画面完整 JSON |

**修订**：这些端点是组态编辑器数据面（编辑器前端路由本就是 `ADMIN_ROLES`；播放器只用 `/ScadaProject/{id}/full` + 图片 + SignalR）。统一加 `[Authorize(Policy = "RequireAdmin")]` 封堵（→ D5）。无需在 Page/Component 的 AppService 内做授权级联校验（侵入大、无必要）。

### P1-2 前端同页签跨账号切换绕过授权（严重）

SPA 登录/登出不刷新页面，以下事实链导致 v1 下「admin 登出 → operator 同页签登录」可看到 admin 的完整列表：

1. `performLogout` 不清 scadaStore；
2. `initializeProjectSummaries` 的模块级标志 `_summariesInitialized` 登出后残留 → 再次登录**直接 return，不重新请求后端**，卡片列表仍是上个账号的全量数据；
3. `selectProject` 的 `findProject` 命中本地缓存 `scadaProjects` 时**直接返回，不经过后端** → 点击卡片即可打开未授权工程的缓存副本；
4. `initializeProjectSummaries` 失败时还会用本地缓存**回退填充**列表。

**修订**：① 新增 `resetScadaStore()` 在登出/登录成功时调用（→ D6）；② `selectProject` 对非 Admin 跳过缓存强制回源（→ D7，同时覆盖「授权被撤销后已打开标签页」场景）。

### P2-1 工程导出权限语义未定义（设计决策遗漏）

`GET /api/ScadaProject/{id}/export` 现无 `RequireAdmin`。v1 下未授权者会被 `GetTreeAsync` 拦成 404，但**被授权的 Operator 将能导出整个工程 JSON**（全部画面、组件、变量绑定关系）。

**修订**：授权语义定为「可见可打开」；导出（工程导出 + 画面导出）统一 Admin 专属，与 Import 已有的 `RequireAdmin` 对称（→ D4）。

### P3 实现细节提醒

| # | 提醒 | 说明 |
|---|---|---|
| 1 | 复合主键实体不能挂 `IRepository<T,K>` 泛型注册 | `ScadaProjectAuthorizationRepository` 直接注入 `ScadaDbContext` 实现；注册时避免被泛型扫描误收 |
| 2 | `ICurrentUser` 实现需容忍无 HttpContext | 后台服务/测试环境下 `HttpContext` 为 null：返回 `UserId=0`、`IsAdmin=false`、`Username=null` |
| 3 | 空授权列表短路 | `ids.Count == 0` 时直接返回空列表，避免 `Contains(空集合)` 生成恒 false SQL |
| 4 | 弹窗用户列表过滤 Admin | `fetchSystemUsers` 结果剔除 `role === 'Admin'`（其默认可见全部，为其授权是噪音）；后端保存时同步剔除（双保险） |
| 5 | JWT 时效 | token 内 `role`/`id` claim 最长 8h 有效，期间**降级角色不即时生效**；授权记录本身每次实时查库不受影响——属既有机制，说明即可 |
| 6 | `dotnet ef` 迁移命令 | 需 `--project ScadaServer.Infrastructure --startup-project ScadaServer.WebApi` 双指定 |

## 3. 范围外边界（知晓即可，不在本方案处理）

| 项 | 现状 | 说明 |
|---|---|---|
| HmiImage 文件流 | `GET /api/HmiImage/file/{fileName}` 为 `[AllowAnonymous]` | 文件名为 GUID 不可枚举，知道 URL 才能取图；如需收紧另行立项 |
| SignalR hub | `/hubs/scada` 仅验证登录 | 自写客户端仍可订阅变量实时值，属"数据面权限"，与"工程可见性"不同维度 |
| 页面级/组件级粒度 | 无 | 本方案授权粒度 = 工程；如未来需要页面级授权，中间表结构可扩展（加 PageId 列） |

## 4. 修订决策对照表（v1 → v2）

| # | v1 | v2（本方案） |
|---|---|---|
| 授权边界 | 仅 ScadaProject 端点 | + ScadaPage/HmiComponent GET、画面导出、工程导出统一 `RequireAdmin`（P1-1、P2-1） |
| 前端缓存 | 未考虑 | `resetScadaStore()` 登出/登录接线 + 非 Admin 播放器强制回源（P1-2） |
| 导出语义 | 未定义 | Admin 专属（D4） |
| 其余 | 数据模型 / 404 语义 / 级联清理 / 弹窗位置 | 维持不变（v1 正确） |
