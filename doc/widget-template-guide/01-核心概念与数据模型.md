# 01 · 核心概念与数据模型

> 本文讲清楚「一个模板到底是什么」「落布之后发生了什么」「改模板会影响谁」。
> 理解了这三点，后面写 `defaultPropsJson` / `propSchemaJson` 就不会踩语义坑。

---

## 1. 模板 = 一行数据库记录

组件库里看到的每一项都是 `HmiWidgetTemplates` 表的一行。
实体定义：`Server/ScadaServer.Domain/Entities/HmiWidgetTemplate.cs`

### 1.1 字段字典

| 字段 | 类型 | 必填 | 约束 / 白名单 | 说明 |
|---|---|---|---|---|
| `Id` | int | — | 自增主键 | 创建时服务端生成 |
| `TemplateKey` | string(64) | ✅ | **唯一索引** | 注册键。画布组件匹配的第一优先级 |
| `RenderType` | string(64) | ✅ | — | builtin 轨 = SFC 映射键；**svg 轨必须等于 TemplateKey** |
| `Name` | string(100) | ✅ | — | 组件库显示名 |
| `Category` | string(32) | ✅ | `equipment` / `sensors` / `structures` / `headers` | 组件库分组 |
| `Description` | string(500) | — | — | 组件库悬停描述 |
| `DefaultWidth` | int | ✅ | 1~4096 | 落布初始宽 |
| `DefaultHeight` | int | ✅ | 1~4096 | 落布初始高 |
| `IconKind` | string(16) | ✅ | `lucide` / `div` / `svg` / `emoji` | 组件库图标形态 |
| `IconKey` | string(2000) | — | 见 §1.2 | 图标内容 |
| `IconColor` | string(64) | — | Tailwind 类，如 `text-amber-500` | **仅 lucide / emoji 生效** |
| `RenderKind` | string(16) | ✅ | `builtin` / `svg` | 渲染轨 |
| `SvgTemplate` | text | 条件 | svg 轨必填；builtin 轨强制 `null` | SVG 源码，入库前清洗 |
| `DefaultPropsJson` | text | — | 合法 JSON，默认 `{}` | 落布时的属性快照来源 |
| `PropSchemaJson` | text | — | 合法 JSON，默认 `[]` | 属性面板表单定义 |
| `IsSystem` | bool | — | — | 系统内置不可删 |
| `SortOrder` | int | — | 升序，同序按 Id | 组件库排序 |
| `CreatedAtUtc` / `UpdatedAtUtc` | DateTime | — | UTC | 服务端维护 |

> 白名单校验发生在 `HmiWidgetTemplateAppService.ValidateAsync`，
> 非法值抛 `BusinessException`（前端 toast 直接显示中文原因）。
> 两个 JSON 字段只做 **合法性** 校验（`JsonDocument.Parse`），**不校验结构** —— 结构错了只有前端渲染时才暴露。

### 1.2 四种图标形态

| IconKind | IconKey 填什么 | IconColor |
|---|---|---|
| `lucide` | lucide 图标名，如 `battery-charging`、`gauge`、`activity` | ✅ 生效 |
| `div` | 内置三变体之一：`div-h` / `div-v` / `div-led` | ❌ |
| `svg` | 一段 SVG 源码（同样过清洗） | ❌ |
| `emoji` | 一个 emoji 字符，如 🔥 | ✅ 生效 |

`lucide` 名字写错不会报错，会回退成 `box` 图标（`iconComp` 兜底）。
全部可用图标名见 `Client/src/lucideIcons.ts`。

> **IconKey 里的 SVG 也会被清洗**（`SvgSanitizer` 同样作用于它吗？—— 注意：`MapToEntity` 只清洗 `SvgTemplate`，
> **IconKey 不清洗**，且列宽 2000 字符。写图标时请自觉不放脚本，别指望有第二道防线）。

## 2. 两条渲染轨

### 2.1 builtin 轨

- `RenderType` 查 `builtinRenderers` 表（`Client/src/builtinRenderers.ts`），命中对应 SFC。
- 可用键（23 个）：
  `boiler` `pump` `valve` `tank` `pipe-h` `pipe-v` `gauge-dial` `gauge-level` `digital-val`
  `var-display` `trend-chart` `conveyor` `text` `led` `button` `switch` `sys-time`
  `rounded-btn` `motor` `image` `title-header` `nav-menu` `multi-var-dashboard`
- 分发逻辑（`Client/src/components/HMIWidget.vue`）：
  ```ts
  const def = getWidgetDef(component.type);
  if (def?.renderKind === 'svg') return SvgTemplateWidget;
  return builtinRenderers[def?.type ?? component.type] ?? null;
  ```
- **关键推论**：`RenderType` 填 `tank`，你的新模板就复用 TankWidget 的全部渲染行为。
  这是「预设变体」模式的基础 —— 零代码做出新图元。

### 2.2 svg 轨

- 走通用渲染器 `SvgTemplateWidget.vue`：`sanitizeSvg(模板源码)` → `bindSvgTemplate(占位符替换)` → `v-html`。
- 容器是 `pointer-events-none`：**SVG 轨不接受任何点击**，做不了按钮/开关。控制类需求只能走 builtin 轨。
- 硬约束：`RenderType` 必须等于 `TemplateKey`（后端 `ValidateAsync` + 前端 `save()` 双校验）。
  目的是让「组件 type」与「模板」一一对应，避免 builtin 轨那种一对多匹配带来的歧义。
- 模板根节点约定 `<svg width="100%" height="100%" viewBox="…">`，在画布内等比缩放。
  默认 `preserveAspectRatio="xMidYMid meet"`（等比居中留白）；需要拉伸填满时显式写 `preserveAspectRatio="none"`。

### 2.3 缺失兜底

`RenderType` 既不匹配模板、也不在 `builtinRenderers` 里 → 渲染「组件缺失: xxx」卡片。
组件仍可选中、可编辑属性、`PropsJson` 保留，重新导入同键模板后自动恢复。

## 3. 两级匹配（为什么老页面的 `title-header` 还能用）

`Client/src/widgetTemplates.ts` → `getWidgetDef(typeOrKey)`：

```
① store 按 templateKey 精确
② store 按 renderType 泛化（取 sortOrder 最小者，列表已排序）
③ 本地兜底种子 BUILTIN_SEEDS 按 key
④ 本地兜底种子按 type
```

| 画布组件 type | 命中路径 | 结果 |
|---|---|---|
| `boiler` | ① | boiler 模板 |
| `title-header`（存量页面） | ② | `title-header-tech-desktop`（sortOrder 210，小于 mobile 的 220） |
| `my-tank`（svg 新模板） | ① | 你的模板 |
| `button`（legacy，无 DB 模板） | ③/④ 兜底种子 | ButtonWidget |
| `xyz` | 全不中 | 组件缺失卡 |

> **⚠ 对模板作者的直接影响**：如果你新建一个 builtin 轨模板，`RenderType` 填了 `title-header`，
> 且 `SortOrder` 比 210 还小，那么**所有存量 `title-header` 组件都会改用你的模板**。
> 想做新变体又不想抢老组件，把 `SortOrder` 设大（≥ 300）。

## 4. 落布：从模板到组件

拖拽/点击组件库项时（`WidgetLibrary.vue`）：

```
payload = { type: def.type, w: def.defaultWidth, h: def.defaultHeight,
            name: def.name, x, y, extraProps: def.defaultProps() }
                                                  ↑ JSON.parse(defaultPropsJson)
```

落库后：

```
HmiComponent.Type      = def.type          // builtin → renderType；svg → templateKey
HmiComponent.PropsJson = extraProps        // 深拷贝快照
HmiComponent.Label     = def.name          // 注意：不是 props.label
```

**也就是说**：`defaultPropsJson` 会被整段复制到每个组件实例上，之后与模板「解耦」——
但这个解耦是有条件的，见下一节。

---

## 5. 快照语义的真实边界

这是全篇最容易误解的一条。先说结论：

> **改模板默认值，对已落布组件的影响，取决于「该键在组件 `PropsJson` 里是否存在」，
> 而不是「你改没改模板」。**

### 5.1 取值链路（`useWidgetBase.propOr`）

```ts
const defDefaults = computed(() => getWidgetDef(component.type)?.defaultProps() ?? {});
//                                              ↑ 每次都读「当前」模板的 defaultPropsJson

const propOr = (key, hard) => {
  const v = component.props[key];
  if (v !== undefined && v !== null && v !== '') return v;   // ① 组件自己的值
  return defDefaults[key] ?? hard;                            // ② 模板当前默认值 → ③ 代码硬兜底
};
```

注意 `defDefaults` 是 **computed** 且读的是运行时模板源 —— 模板一改，它就变。

### 5.2 三种情形

| 场景 | 键在组件 props 里？ | 改模板默认值后 |
|---|---|---|
| 落布时快照进来的键 | ✅ 存在 | **不受影响**（走分支 ①） |
| 模板后来**新增**的键 | ❌ 不存在 | **立刻生效**（走分支 ②） |
| 组件上被「清空」的键（空串/null） | 值被判空 | **立刻生效**（被判空后掉到分支 ②） |

### 5.3 由此推出的三条实践

1. **给模板加新属性是安全的** —— 存量组件会自动拿到你的新默认值，不会显示空白。
2. **改已有属性的默认值，对存量组件无效** —— 想让老组件跟着变，只能手工改组件或等「应用默认值」功能（当前未实现）。
3. **判空规则是 `undefined / null / ''`**，但 **`0` 和 `false` 是有效值**。
   所以 `minValue: 0` 能正常生效，`fontSize: 0` 也生效（会变成 0 号字）。
   而 `unit: ''` 会被判空 → 掉到模板默认值 → 再掉到 `''`，看不出区别，但语义上确实绕了一圈。

### 5.4 不被快照的三样东西

| 项 | 是否快照 | 改了之后 |
|---|---|---|
| `DefaultPropsJson` | ✅ 快照（且受 §5.2 约束） | 部分生效 |
| `SvgTemplate` | ❌ | **实时生效**（渲染时读模板） |
| `PropSchemaJson` | ❌ | **实时生效**（属性面板立即变） |
| 名称 / 描述 / 图标 / 分类 / 排序 / 默认尺寸 | — | 只影响组件库展示与新落布 |

> 所以：**改 SVG 源码 = 改所有存量实例的皮肤**，这是 svg 轨最方便也最危险的地方。
> 上线前一定在管理页的「实时预览」里确认（预览上下文是固定示例值，见 [02 §7](./02-SVG占位符完全手册.md#7-预览与真实运行的差异)）。

## 6. 导入 / 导出

### 6.1 文件格式

```json
{
  "format": "scada-widget-template",
  "version": 1,
  "template": { "…模板对象…" }
}
```

批量：

```json
{
  "format": "scada-widget-template",
  "version": 1,
  "templates": [ { "…" }, { "…" } ]
}
```

模板对象为 camelCase（示例值）：

```json
{
  "id": 0,
  "templateKey": "my-tank-level",
  "renderType": "my-tank-level",
  "name": "液位罐",
  "category": "equipment",
  "description": "带刻度的竖式液位罐",
  "defaultWidth": 120,
  "defaultHeight": 160,
  "iconKind": "svg",
  "iconKey": "<svg …>…</svg>",
  "iconColor": "",
  "renderKind": "svg",
  "svgTemplate": "<svg …>…</svg>",
  "defaultPropsJson": "{\"activeColor\":\"#10b981\"}",
  "propSchemaJson": "[{\"key\":\"activeColor\",\"label\":\"液体颜色\",\"type\":\"color\"}]",
  "isSystem": false,
  "sortOrder": 300
}
```

### 6.2 导入时前端的宽松解析

管理页 `onPickFile` 兼容四种形态：

```
数组                        → 直接当模板数组
{ templates: [...] }        → 取 templates
{ template: {...} }         → 取 template
{ 其它对象 }                → 当单条模板
```

字段读取用 `pick(raw, 'templateKey', 'TemplateKey')` —— **PascalCase 与 camelCase 都认**。

### 6.3 冲突处理

| 策略 | 后端行为 |
|---|---|
| `overwrite` | 用传入 DTO 覆盖同键记录；**`IsSystem` 保留库内现值**（不会把内置模板变成用户模板） |
| `rename` | 追加 8 位随机后缀（Base64(Guid) 去 `+/` 取前 8 位小写），超长时先截断到 55 字符；新记录 `IsSystem=false` |
| `skip` | 跳过冲突项，其余照常创建 |
| 无冲突新建 | `IsSystem` **强制 false**，杜绝伪造文件把模板伪装成系统内置 |

响应：`{ ok, id, mode: "create" | "overwrite" | "renamed" | "skipped", newKey? }`

> **注意**：`import-bundle`（批量接口）在后端固定走 `rename` 语义，
> 「批量覆盖」是前端拆成多条 `import` 单条调用实现的。

### 6.4 版本演进约定

- `version` 当前为 `1`。未来不兼容变更递增版本号，导入端做分支兼容。
- 未知字段忽略（向前兼容）。
- `isSystem` 一律不信文件值。

## 7. 最小心智模型图

```
┌─────────────── HmiWidgetTemplates（一行 = 一个图元）───────────────┐
│  TemplateKey ──┐                                                   │
│  RenderType  ──┼──→ builtin 轨 ──→ builtinRenderers[renderType] ──→ SFC │
│  RenderKind  ──┘                                                   │
│                 └──→ svg 轨     ──→ SvgTemplateWidget ──→ v-html   │
│                                                                     │
│  DefaultPropsJson ──(落布深拷贝)──→ HmiComponent.PropsJson          │
│                   └─(运行时兜底)──→ useWidgetBase.propOr 分支②      │
│                                                                     │
│  PropSchemaJson   ──(实时)────────→ InspectorPanel 属性表单         │
│  SvgTemplate      ──(实时)────────→ 画布所有实例                    │
└─────────────────────────────────────────────────────────────────────┘
```
