## 1. 风险表

| # | 风险 | 触发场景 | 缓解措施 | 责任阶段 |
|---|---|---|---|---|
| R1 | 共享后重连风暴（多设备并发触发重建/互相拖累） | 同连接多设备同时检测到断线 | 闸门（Interlocked 去重）+ 探测确认（`IsAliveAsync`）+ `ReconnectIntervalMs` 退避 + 单测覆盖并发触发 | P3 |
| R2 | 批读改变故障隔离语义（单变量失败拖垮整轮） | S7 错误标记判别遗漏 / 批读整体异常 | 标记→null 适配 + 整体异常降级逐变量读；`anySuccess`/`LastError`/质量跃迁语义用例固化 | P5 |
| R3 | 会话对象并发竞争（挂载表/状态扇出/驱动替换） | 设备启停与会话重建同时发生 | `_lifecycleLock` 串行化生命周期操作；挂载表用 `ConcurrentDictionary`；驱动引用 volatile 快照 | P2/P3 |
| R4 | S7 单连接吞吐不足（`_plcLock` 串行 + N 设备排队） | 高采集率 + 多设备共享 | P5 批读补偿（合并地址分组合并 IO）；若仍不足 → 已知限制记录（03 文档 §7 不做跨设备合批），后续优化项 | P5 |
| R5 | OPC UA 休眠订阅路径被误伤 | 驱动签名切换牵连 | 订阅接口与实现零改动（D10）；P1 回归确认编译面无牵连 | P1 |
| R6 | 配置热重建窗口内在途写入 | `ReloadConnectionAsync` 与写入并发 | 重建先行取消 Worker + 扇出 Error（写入门禁拦截）；写超时兜底已存在（`_deviceWriteTimeoutMs`） | P4 |
| R7 | 历史数据 `ConnectionId == null` 的过渡设备 | 老库存在无连接设备 | 保持现状「警告+跳过」语义，改造不改此路径；P0.3 审计确认数量 | P0/P2 |
| R8 | 重连窗口快照 404 回归（曾修复过的缺陷形态复发） | 会话重建期间快照请求 | 会话级重连**不移除设备运行时**（根因消除）；`_reconnecting` 保留至 P6 有证据后删 | P3/P6 |
| R9 | 真实 PLC（192.168.1.60）不可达导致验证缺口 | 拔线/恢复场景需真机 | 虚拟驱动 + FakeDriver 单测覆盖逻辑路径；真机项列入「手工验收记录」待环境可用补测（沿用 runtime-refactor 的基线缺口处理惯例） | 全程 |
| R10 | Worker 持旧驱动引用读写（驱动已替换/释放） | 会话换驱动瞬间 | 重建顺序硬约束：先取消 Worker 并等待退出，再 Dispose 旧驱动（D5）；驱动转发属性瞬时快照语义 + 驱动自身锁内终态复检兜底 | P3 |
| R11 | 批读后通知时序变化（同轮变量同时间戳） | 前端/历史对时间戳敏感 | 采样时间戳取采集时刻（现状已如此，批读取同一 `now`，语义合法）；回归 N-5 快照比对 | P5 |
| R12 | 共享会话下一台设备的坏地址拉低他设备变量质量 | 地址错误异常被计入轮次失败 | `IsAliveAsync` 探测在会话层拦截「假断线」；设备级失败只影响本设备状态 | P3 |

## 2. 回归矩阵

### 2.1 既有基线（沿用 runtime-refactor 行为基线，全量复跑）

| 编号 | 场景 | 通过标准 |
|---|---|---|
| N-1 | 初始连接失败：LastError 非空、占位重连 | 与基线一致（注意：历史基线曾因占位路径 LastError=null 记为缺口，本次会话化后口径见 03 文档 §4.2，如实记录） |
| N-2 | 进程级 ReconnectCount 不复位 | 会话重建计数进程级累计、不复位、不随设备启停清零 |
| N-3 | 报警状态与 AlarmRecords 对齐 | 重连/重载后 HasAlarm 与活跃报警数一致（设备运行时存活后该项应**更强**：不再依赖重建时回填） |
| N-4 | RunState 持久化与重启恢复 | RunState/RunStateChangedAt 跨重启保持；会话重建不触碰 RunState |
| N-5 | 快照冒烟 25 项 | 字段全量比对改造前基线（DTO 零变化） |
| R-2 | 完整重连环（connected→disconnected→reconnected→Online） | 真机项；虚拟/Fake 路径先行，真机列入手工记录 |
| R-3 | 推送计数时序 | 变量变化推送次数与基线一致（批读改造后重点复测） |
| R-10 | 值写入链路 | 正常写/失败写/审计记录齐全 |

### 2.2 新增共享场景（S-1～S-8，本改造核心验收）

| 编号 | 场景 | 通过标准 |
|---|---|---|
| S-1 | 两设备引用同一 DeviceConnection 启动 | 日志仅**一次**驱动 ConnectAsync；两设备独立采集、值按 `device_key+variable_key` 正确归属 |
| S-2 | 共享连接拔线→恢复 | 组内全部设备**同时**转 Fault/Error；恢复后**同时**回 Online；日志仅**一次**重建序列（闸门生效）；ReconnectCount +1（非 +N） |
| S-3 | 单设备禁用/停止 | 同连接其他设备采集与连接不受影响；被禁设备变量停止更新 |
| S-4 | 末位设备禁用/删除→再启用 | 驱动 Dispose 恰一次；再启用后会话重建并恢复采集 |
| S-5 | ConfigJson 热编辑（如改 IP） | 旧驱动 Dispose + 新驱动按新参数建连，**无需重启服务**；`IsEnabled` false→true 同理 |
| S-6 | 共享会话写入矩阵 | 正常写/只读变量拒/越限拒/禁用变量拒/超时兜底，结果与基线一致 |
| S-7 | 坏地址设备不拖垮健康兄弟 | 设备 A 全部变量地址非法：A 呈 Error，同连接设备 B 采集与连接状态不受影响、无重建（探测路径） |
| S-8 | 物理连接数验证 | 同连接 N 设备仅 1 条 TCP/会话（PLC 侧连接计数或驱动日志证据；对照 P0.2 记录的「改造前 2 条」） |

### 2.3 性能验收（P5）

| 项 | 方法 | 记录格式 |

## 4. 回退策略

| 里程碑 | 回退方式 |
|---|---|
| M1（P1 接口层） | 独立 commit，revert 即回旧行为（每设备独立连接） |
| M2（P2 会话层） | 单 commit revert；注意 P2 自身包含 `Driver` 转发属性改造，revert 后需全量构建验证 |
| M3+（P3 起） | 逐阶段 commit revert；数据库无迁移，回退无数据风险 |
| 紧急热修 | 不提供运行时开关（双轨漂移，见 03 文档 §7）；紧急情况按阶段 revert |
