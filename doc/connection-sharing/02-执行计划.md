## P1 · IRuntimeConnection 接口层（行为不变的签名切换）

> 目标：接口先立起来，**每设备仍独立驱动独立建连**，行为与现状完全等价。本阶段结束系统可正常上线运行。

### 步骤 1.1 新建 IRuntimeConnection 接口

- 新建 `Server/ScadaServer.Domain/Interfaces/IRuntimeConnection.cs`，成员仅三个：`ConnectionId`（int）、`Key`（string，日志定位）、`ConfigJson`（string）。定义在 Domain 层维持依赖方向 `Domain ← Infrastructure(驱动) ← Runtime(实现)`（与 `IRuntimeDevice` 同构）；
- `IRuntimeDevice` 原样保留（Worker/运行时仍使用）。

**验收**：编译通过；接口无多余成员（对照 01 文档 §5「驱动真实依赖面」）。

### 步骤 1.2 驱动 ConnectAsync 签名切换（3 个驱动）

- `IProtocolDriver.ConnectAsync(IRuntimeDevice device)` → `ConnectAsync(IRuntimeConnection connection)`；
- `S7Driver`：`device.ConfigJson`→`connection.ConfigJson`；`device.Key`（日志上下文）→`connection.Key`；`_deviceKey` 字段更名 `_connectionKey`（含全部日志引用）；
- `OpcUaDriver`：`device.ConfigJson`→`connection.ConfigJson`；日志 `device.Key`→`connection.Key`；
- `VirtualDriver`：`device.Id`→`connection.ConnectionId`，`device.ConfigJson`→`connection.ConfigJson`；
- 更新接口 XML 注释：连接参数真相源为 `DeviceConnection`，驱动不再感知设备。

**验收**：构建绿；`rg "IRuntimeDevice" Server/ScadaServer.Infrastructure/Communication` 仅剩注释/无实参使用。

### 步骤 1.3 RuntimeManager 临时适配层

- `BuildAndRegisterDeviceAsync` 中：`CreateDriver` 后用 `DeviceConnectionContext`（新建的轻量 `IRuntimeConnection` 实现，从 `device.Connection` 取值）调用 `driver.ConnectAsync(connectionContext)`；
- 其余逻辑（失败占位、状态初始化、变量构建）零改动。

**验收**：全量行为基线回归**零偏差**（P0 基线表对照）；此 commit 可独立上线/回退。

## P2 · ConnectionSession 会话层（驱动共享落地）

> 目标：一个 `DeviceConnection` 一条物理连接。本阶段结束后重连路径暂时沿用设备级旧逻辑（已知不完整，P3 修复），因此**验收重点放在「正常路径 + 单设备启停」**。

### 步骤 2.1 ConnectionSession 核心

- 新建 `Server/ScadaServer.Runtime/Connections/ConnectionSession.cs`：实现 `IRuntimeConnection`；持有 `DeviceConnection` 实体、协议 Key、`IProtocolDriver` 实例、挂载设备表（`ConcurrentDictionary<int, DeviceRuntime>`）；
- 状态扇出：会话 `ConnectionState` setter → 遍历挂载设备写 `runtime.ConnectionState`（复用既有 `ConnectionStateChanged` 事件 → RuntimeManager 推送/持久化链路，**不改推送层**）；
- 生命周期：`MountAsync(deviceRuntime)` / `UnmountAsync(deviceId)`（末位离场：停 Worker → Dispose 驱动 → 从 RuntimeManager 会话表移除）；
- 详细状态机与并发规则见 03 文档 §3。

**验收**：单元测试（FakeDriver）——挂载/卸载/状态扇出/末位销毁/重复挂载幂等。

### 步骤 2.2 RuntimeManager 接入会话

- `RuntimeManager` 新增 `ConnectionSessions`（`ConcurrentDictionary<int, ConnectionSession>`，key=ConnectionId）；
- 启动路径 `StartAsync`：加载启用设备后**按 ConnectionId 分组** → 每组先建会话（一次 `CreateDriver`+`ConnectAsync`）→ 再逐设备挂载；连接失败时组内设备全部按现有占位逻辑注册为待重连；
- `BuildAndRegisterDeviceAsync`：删除 `CreateDriver` 调用，改为「获取或创建会话 → 挂载设备」；`DeviceRuntime` 新增 `Session` 属性，`Driver` 改为转发属性 `=> Session?.Driver`（Worker/写链路的 `Driver` 消费点零改动，见 D8）；
- 连接失败路径：会话创建失败 → 设备注册占位运行时（`NeedsReconnect=true`），语义同现状。

**验收**：S-1（两设备共享连接：日志仅一次 ConnectAsync）；S-3（单设备禁用不影响同连接其他设备）；构建绿 + 既有基线场景通过。

### 步骤 2.3 设备启停/删除路径接入

- `RemoveDeviceAsync`：`DisposeAsync 驱动` 改为 `UnmountAsync`（末位才销毁）；
- `RegisterDeviceAsync` / `ReloadDeviceAsync`：设备重载 = 卸载 + 重新挂载（会话若在则复用，不在则重建）；
- `StopAsync`（服务关停）：先停全部 Worker（沿用调度器 StopAsync 顺序），再逐会话 Dispose 驱动。

**验收**：S-4（末位设备禁用/删除 → 驱动 Dispose 日志恰一次；重新启用 → 会话重建）；S-3 复测。

### 步骤 2.4 会话层单元测试

- `ScadaServer.Runtime.Tests`（或既有测试工程）新增 `ConnectionSessionTests`：FakeDriver 下验证挂载计数、扇出、末位销毁、并发挂载/卸载安全。

**产出**：可回归的会话层测试基建。

## P3 · 会话级重连归口

> 目标：修复「共享后重连」的核心缺口（01 文档问题 B）。这是全计划风险最集中的一阶段，按步骤小步推进。

### 步骤 3.1 驱动增加 IsAliveAsync 探测

- `IProtocolDriver` 新增成员 `Task<bool> IsAliveAsync()`：
  - S7：锁内复检终态后返回 `_plc?.IsConnected ?? false`；
  - OpcUa：`AcquireSessionForIoAsync` 可用性检查的轻量化版本（或 `_session?.Connected`）；
  - Virtual：恒 true；
- 语义：**探测仅用于重连判定**，不作为读写前置条件（避免每轮多一次往返）。

**验收**：三驱动实现 + 单测；正常读写路径无行为变化。

### 步骤 3.2 会话重连（闸门 + 探测 + 重建）

- `ConnectionSession.ReconnectAsync()`：`Interlocked` 闸门（同一时刻至多一次重建）；
- 流程（顺序为硬约束，见 D5）：闸门 → 扇出 Error + 取消挂载 Worker + 等待 WorkerTask 退出 → Dispose 旧驱动 → `CreateDriver` + `ConnectAsync(本会话)` → 成功：换驱动、扇出 Connected、复位各设备 `NeedsReconnect`/`ConsecutiveFailureCount`（调度器自然重派 Worker）；失败：保持待重连，按 `ReconnectIntervalMs` 排期重试；
- **设备运行时不重建**：变量值、报警计数、RunState、LastError 全部存活（D4）；
- `RuntimeManager.ReconnectDeviceAsync(deviceId)` 改为转发：设备 → 所在会话 → `session.ReconnectAsync()`（调度器调用方零改动，多设备触发被闸门去重）。

**验收**：单测（FakeDriver 模拟断连/恢复）；日志验证多设备并发触发仅一次重建序列。

### 步骤 3.3 Worker 断线信号上抛

- `DeviceWorker` 断线判定点（`ConsecutiveFailureCount >= 3` 处）增加一行：`_runtime.Session?.SignalConnectionFailureAsync()`（fire-and-forget，异常兜底）；
- 会话侧 `SignalConnectionFailureAsync`：聚合计数 + 触发重连检查 = 先 `IsAliveAsync` 探测：**活** → 判定为设备级问题（如地址全错），复位聚合计数、设备保持 Error、**不重建**（修复现状 flapping）；**死** → 进入 3.2 重建路径；
- Worker 原有 `NeedsReconnect=true + break` 逻辑保留（作为扇出失败的兜底退出）。

**验收**：坏地址设备（VirtualDriver 模拟）不再触发健康连接重建；拔线场景两设备一起转 Fault。

### 步骤 3.4 连接级配置消费（D7）

- 启动/挂载时：`DeviceConnection.IsEnabled == false` → 不建会话，挂载设备注册为离线占位（沿用连接失败占位语义）；
- 会话重连退避：`ReconnectIntervalMs`（缺省回退现有 5s）；
- `DeviceConnectionAppService` 已有的字段编辑能力与本步骤形成闭环（热重建在 P4 步骤 4.2 接线）。

**验收**：`IsEnabled=false` 连接下设备不采集、快照显示离线；改 `ReconnectIntervalMs` 后重连节奏变化。

## P4 · 写入链路与配置热更新

### 步骤 4.1 WriteVariableAsync 门禁改造

- `runtime.Driver == null` 检查保留（转发属性在无会话/无驱动时为 null，语义自洽）；
- `runtime.ConnectionState != Connected` 门禁保留——其值由会话扇出驱动；
- 写入调用 `runtime.Driver.WriteAsync(...)` 经转发属性落到会话当前驱动；写超时与审计链路零改动；
- 补充：会话重建窗口内的写入按「设备未连接」拒绝（扇出已置 Error），无需额外代码——写验收用例覆盖。

**验收**：S-6（共享会话下写入矩阵：正常写/只读变量/越限/禁用变量/超时，结果与基线一致）。

### 步骤 4.2 配置热更新接线（D6）

- `DeviceConnectionAppService.UpdateAsync` 末尾：若 `ConfigJson` 或 `ReconnectIntervalMs` 变更 → 调 `RuntimeManager.ReloadConnectionAsync(connectionId)`（内部 = 会话 `ReconnectAsync`，复用 3.2 闸门）；`IsEnabled` false→true → 建会话挂载设备，true→false → 卸载全部设备并销毁会话；
- 注意保持应用层→运行时单向调用（与 `RegisterDeviceAsync` 现有模式一致）。

**验收**：S-5（改 IP 热重建：旧驱动 Dispose + 新驱动按新 IP 建连，无需重启服务）。

### 步骤 4.3 日志契约更新（D12）

- 会话/驱动层通讯错误日志上下文：`Connection`（Key/IP/协议参数）+ 触发设备 Key；
- 更新项目 memory 中「日志含 Device/IP/…」约束条目的表述（实施完成后执行）。

**验收**：抽检断连/重建日志字段齐全。

## P5 · 批读性能补偿（可与 P2 起并行，亦可单独先行）

### 步骤 5.1 ReadBatchAsync 契约精读与适配层

- 精读三驱动 `ReadBatchAsync` 返回契约：S7 以**错误标记对象**（非 null）表示单变量失败（`S7Driver.cs:355` 注释）——需确认标记类型与判别方式；
- Worker 侧写适配：标记/失败 → 映射为 `null`（走 Worker 现有 null 无效路径），保证「单变量失败不拖垮整轮」语义不变。

**产出**：契约确认记录（写入 commit message）。

### 步骤 5.2 Worker 采集循环批读改造

- `due` 变量集合一次 `ReadBatchAsync(due)`（经 `runtime.Driver` 转发属性）；
- 降级路径：`ReadBatchAsync` 整体抛异常 → 回退现有逐变量 `ReadAsync` 循环（保留故障隔离与 `LastError`）；
- 内存态更新收敛：批读结果在**单次** `runtime.Lock` 获取内完成全部变量赋值（替代现有逐变量加锁）；工程换算/历史/快照/报警/通知逐变量后处理逻辑不变；
- 计时与 `anySuccess` 统计口径保持（批读整体计时）。

**验收**：值/历史/报警/推送与逐变量路径全等（N-5 快照、R-2/R-3 计数复测）；坏地址单变量只影响自身。

### 步骤 5.3 吞吐对照

- 虚拟设备压测（大变量量、短周期）记录批读前后单轮耗时；
- 真实 PLC 手测项（若 192.168.1.60 可达）：同表两设备共享连接 + 批读的实测吞吐，写入 04 文档「手工验收记录」。
