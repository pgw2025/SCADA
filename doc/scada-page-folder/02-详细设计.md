## 2. id 映射规则（前端 uid ↔ 后端 int）

沿用现有「组件 `layerId` 字符串 uid、页面 `id` 双轨」的既有惯例，文件夹引入后约定：

| 概念 | 前端（内存） | 后端（DB/DTO） |
|---|---|---|
| 文件夹自身 id | `id: string`（`folder-<uid>`） | `Id: int`（serverId） |
| 页面所属文件夹 | `pg.folderId?: string`（文件夹 uid） | `ScadaPage.FolderId: int?` |
| 文件夹父级 | `folder.parentFolderId?: string`（父夹 uid） | `ParentFolderId: int?` |
| 排序 | `sortOrder: number` | `SortOrder: int` |

- **加载**：`fromProjectFullDto` 先解析 `folders` → 建 `Map<serverId(int), uid(string)>`，再解析 `pages`，把后端 `FolderId(int)` 通过该 map 转成前端 `folderId(string)`；同理把 `ParentFolderId(int?)` 转成 `parentFolderId(string?)`。
- **保存**：`toPageDto` 由调用方传入解析好的 `folderId: number|null`（而非字符串）；`persistPageUpdate` 里用 `proj.folders` 建 `Map<uid, serverId>` 反查。
- **未落库文件夹**：新建文件夹必须先 `ensureFolderSaved` 拿到 serverId，页面才能 `folderId` 指向其 uid——与"组件依赖 `ensurePageSaved` 先落库"同构。

## 4. 删除文件夹：reparent（默认）

`DeleteAsync(id, "reparent")` 事务算法（在 `ExecuteInTransactionAsync` 内）：

```
folder = folderRepo.GetById(id); if null return;
parentId = folder.ParentFolderId;

// 1) 直接子文件夹上提一级（按其原 SortOrder 升序处理）
foreach (sub in folderRepo.GetList(f => f.ParentFolderId == id).OrderBy(f => f.SortOrder))
    sub.ParentFolderId = parentId; folderRepo.Update(sub);

// 2) 直接画面上提一级（原 SortOrder 升序）
foreach (p in pageRepo.GetList(p => p.FolderId == id).OrderBy(p => p.SortOrder))
    p.FolderId = parentId; pageRepo.Update(p);

// 3) 删除空文件夹
folderRepo.Delete(folder);

// 4) 对目标父级做分段连续重排（文件夹段、画面段各自从 1 起）
RenormalizeOrder(parentId, folder.Platform);
```

- **只动直接子项**：孙目录内部结构与其父一起上移，不遍历改动。
- **RenormalizeOrder(parentId, platform)**：取该父级下全部文件夹按 `SortOrder, Id` 排序赋 1..N；取该父级下全部画面按 `SortOrder, Id` 排序赋 1..N。既消除上提造成的排序空洞，也保证确定性。

## 5. 删除文件夹：cascade（可选）

`DeleteAsync(id, "cascade")` 事务算法：

```
affectedFolderIds = CollectSubtreeFolderIds(id);   // DFS 收集子孙（含 id）
affectedPageIds   = pageRepo.GetList(p => affectedFolderIds.Contains(p.FolderId.Value)).Select(Id);

// 顺序：先删画面(含组件) → 逆深度删子夹 → 删根夹（避免带引用删父）
foreach (pageId in affectedPageIds) await pageAppService.DeleteByIdInTransaction(pageId);
foreach (fid in affectedFolderIds.OrderByDescending(深度)) folderRepo.DeleteById(fid);
```

- 画面删除复用 `ScadaPageAppService.DeleteAsync` 的「事务内删组件再删页面」逻辑（可抽一个无独立事务的内部方法供级联复用，避免嵌套事务）。
- **guard**：cascade 前校验"删除后工程页面总数 ≥ 1"，否则抛 `ArgumentException`（前端已拦，后端兜底）。

## 6. API 契约

| 方法 | 路径 | 请求体/参数 | 返回 | 说明 |
|---|---|---|---|---|
| GET | `/api/ScadaPageFolder?projectId=` | query | `List<ScadaPageFolderDto>` | 按工程查（可选） |
| POST | `/api/ScadaPageFolder` | `{projectId,name,platform,parentFolderId?}` | 新 id | 创建，SortOrder 取同父级文件夹段最大值+1 |
| PUT | `/api/ScadaPageFolder` | `{id,name?,parentFolderId?}` | 204 | 重命名/移动；跨端/移入自己后代 → 400 |
| DELETE | `/api/ScadaPageFolder/{id}?mode=reparent\|cascade` | query mode | 204 | 默认 reparent |
| POST | `/api/ScadaPageFolder/reorder` | `{platform,parentFolderId?,folders:[{id,sortOrder}],pages:[{id,sortOrder}]}` | 204 | 同父级**分段全量**覆盖排序 |

- `reorder` 分 `folders` / `pages` 两段提交，天然表达"文件夹段在前、画面段在后"的语义，避免混合序列歧义。
- 跨端/循环移动校验：`PUT` 与 `reorder` 校验 `platform` 一致、`parentFolderId` 不得指向自身或自身后代（否则 400）。

## 8. 边界与约束

- 存量画面 `FolderId=NULL` 落根级；旧工程零迁移成本。
- Popup 画面 `folderId` 恒空、不参与文件夹树。
- 首页唯一性、`Platform` 过滤、组件绑定、剪贴板、导入导出均不感知文件夹。
- 命名唯一（同 ProjectId+Platform+ParentFolderId）由应用层校验，根级重名不建库级唯一索引（MySQL 唯一索引对 NULL 放行）。
- 删除/移动/排序均在 `ExecuteInTransactionAsync` 内，规避 MySQL 重试策略下的用户事务异常。
