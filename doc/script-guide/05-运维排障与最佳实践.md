# 05 · 运维排障与最佳实践

> 脚本不跑、跑了没效果、报错、变慢——按本文的清单逐项排查。

---

## 一、执行结果码全表

执行记录表（`ScriptExecutionRecords`）与前端控制台里的 `Result` 列，取值如下：

| Result | 含义 | 是否计入失败计数 | 常见 Error 文本 |
|---|---|---|---|
| `Success` | 钩子执行完毕且未抛异常 | **否（并清零）** | — |
| `Error` | 执行中抛异常（含语法/引用/类型错误、递归超限） | **是** | 异常 message（截断 2000 字符入库） |
| `Timeout` | 脚本执行超过 `TimeoutMs` | **是** | Jint 超时信息 |
| `Timeout` | 挂死看门狗触发（>120s） | 是（并强制熔断） | `执行挂死（Ns），已被看门狗强制熔断` |
| `Skipped` | 未真正执行 | **否** | 见下表 |
| `Error` | 派发链路异常（落库/推送失败等） | 见代码路径 | `派发链路异常：...` |

### `Skipped` 的五种具体原因（看 Error 列区分）

| Error 前缀 | 原因 | 处理 |
|---|---|---|
| `[BUSY] 上一次执行尚未结束，本次触发被跳过` | 同一脚本上次还没跑完 | 调大间隔 / 优化脚本；不是错误，不影响熔断 |
| `[TRIPPED] 脚本已熔断，本次被跳过` | 连续失败 ≥3 次 | 修脚本 → 保存（自动复位）或点「复位熔断」 |
| `执行队列已满，本次触发被丢弃` | 派发队列（默认 256）满了 | 加大 `Scripting:QueueCapacity`/`Consumers`，或降低脚本耗时与触发频率 |
| `脚本引擎未运行` | 引擎停止中/未启动 | 检查服务状态 |
| `[STOP] 服务停止，本次触发未执行` | 停机排空时的残留项 | 正常关闭现象 |

> **注意**：实体注释里提到 `Tripped` 也是一种 Result，
> 但**实际代码写入的是 `Skipped` + `[TRIPPED]` 前缀**（见 `ScriptEngineHost.DispatchAsync`）。
> 查记录时不要按 `Result='Tripped'` 过滤，要按 Error 前缀。

## 二、输出缓冲里的标记前缀（排障第一现场）

脚本输出（`log()` 内容 + 系统追加的标记）会出现在执行记录的 `Output` 列与前端控制台。
看到这些前缀就知道发生了什么：

| 前缀 | 来源 | 含义 |
|---|---|---|
| `[DENIED] read X.Y：设备 [X] 不在读授权列表` | `read()` / `getQuality()` | **读授权缺失** —— 把 `X` 加进 ScopeRead |
| `[DENIED] write X.Y：不在写授权列表（需精确到 设备键.变量键）` | `write()` | **写授权缺失** —— 把 `X.Y` 加进 ScopeWrite |
| `[WRITE-FAIL] X.Y: 原因` | `write()` | 授权通过但写入失败：变量只读 / 已禁用 / 超限 / 设备未连接 / 超时 |
| `[DRY-RUN] 写入 X.Y = v` | 试运行模式的 `write()` | 正常现象，**没有真实写入** |
| `[SKIP] 未声明 run() 钩子` | 引擎 | 钩子函数缺失或名字写错 |
| `[SKIP] 未声明 onChange(ev) 钩子` | 引擎 | 同上 |

**排查口诀**：
- 看到 `[DENIED]` → 授权问题；
- 看到 `[WRITE-FAIL]` → 变量属性或设备状态问题；
- 既没 `[DENIED]` 又没输出 → 钩子没写、或脚本根本没被调度到。

## 三、四种典型故障的排查流程

### 3.1 「脚本保存成功，但从来没跑过」

```
执行记录里一条都没有？
  │
  ├─ Active（启用）勾选了吗？        → 未启用不进调度、不订阅 OnChange
  ├─ 触发类型配对了字段吗？
  │    Periodic → 填了执行间隔吗（≥1）？
  │    Schedule → Cron 表达式合法吗？非法时脚本静默不进调度，只写服务端日志
  │    OnChange → 监听设备键 + 变量键都填了吗？与真实键值完全一致吗（大小写敏感）？
  ├─ 脚本处于熔断态（列表上显示"熔断"标签）？
  └─ 服务重启后是否调用过 ReloadAsync？（CRUD 会自动触发；手动改数据库不会）
```

### 3.2 「每次都 Success，但没有任何效果」

```
  ├─ 输出里有 [DENIED] 吗？           → 授权缺失（最常见！）
  ├─ 输出里有 [SKIP] 未声明钩子 吗？  → 钩子名写错（run / onChange）
  ├─ 逻辑写在顶层而不是钩子里了吗？   → 顶层 log 看不到、顶层逻辑虽然会跑但不该这么写
  ├─ read() 返回 null 吗？            → 设备键/变量键拼错，或设备不在运行中
  ├─ 条件分支根本没进去吗？           → 在分支前 log 出判断依据的实际值
  └─ 是不是只点了"试运行"？           → 试运行的 write() 不会真实下发
```

### 3.3 「报错 Error，甚至熔断了」

```
看执行记录的 Error 列：
  │
  ├─ "console is not defined"        → 用了 console.log，改成 log()
  ├─ "setTimeout is not defined"     → 沙箱没有定时器，改用周期触发
  ├─ "fetch is not defined"          → 沙箱没有网络能力
  ├─ "xxx is not defined"            → 严格模式下变量未声明就赋值（漏了 var）
  ├─ 递归超限                        → 递归深度 >100，改迭代
  ├─ 超时                            → 调大 TimeoutMs；检查是否有密集 write（每个最坏 6s）
  └─ 其它 JS 异常                    → 把可疑段用 try/catch 包起来，log 出上下文

熔断了怎么办：
  ① 先去执行记录看 Error，别急着改代码（一保存 FailureCount 就清零，现场没了）
  ② 修好后保存（自动复位熔断）或点「复位熔断」
  ③ 想验证修复效果：用「运行」（手动运行可绕过熔断）
```

### 3.4 「执行变慢 / 大量 Skipped」

```
  ├─ 大量 [BUSY]           → 脚本耗时 > 触发间隔。调大间隔，或优化脚本
  ├─ 大量"执行队列已满"     → 消费能力不足。调大 Scripting:Consumers，
  │                          或降低脚本数量/频率；同时检查是否有脚本接近挂死
  ├─ 写桥超时计数上升       → 设备写入慢。检查网络与驱动；
  │                          Scripting:WriteBridgeTimeoutMs 应 ≥ 设备写超时
  └─ 看门狗报"执行挂死"     → 有脚本阻塞超过 120s。检查是否有未知阻塞源（DB 挂起等），
                              被占用的消费线程无法回收，可能需要重启服务
```

**服务端观测日志**（每 60s 一次，**仅在有异常信号时输出**，正常运行零噪音）：

```
脚本派发观测：队列深度={深度}/{容量}，累计丢弃={次数}，写桥超时={次数}，在途执行={数}，消费线程={数}
```

> 告警建议：队列深度持续超过容量 **50%** 且不回落 → 消费能力不足。

## 四、配置项速查

| 配置键 | 默认值 | 范围 | 作用 |
|---|---|---|---|
| `Scripting:Consumers` | 2 | 1 – 16 | 专用消费线程数。脚本多/耗时长就调大 |
| `Scripting:QueueCapacity` | 256 | 8 – 10000 | 派发队列容量。队满丢弃触发 |
| `Scripting:WriteBridgeTimeoutMs` | 6000 | 500 – 60000 | 单次 `write()` 同步等待上界。**应 ≥ 设备写超时**，让驱动层的超时文案先返回 |

脚本级参数（编辑器里配）：`TimeoutMs`（500–30000，默认 2000）、`CooldownMs`（100–60000，默认 500）、
`IntervalSeconds`（≥1）、`DeadBand`。

**几个引擎内置的固定阈值**（不可配置）：

| 阈值 | 值 | 说明 |
|---|---|---|
| 递归深度上限 | 100 | `LimitRecursion(100)` |
| 熔断连续失败阈值 | 3 | 达到即 `Tripped=true` |
| 调度 Tick | 250ms | 周期/Cron 的调度精度上限 |
| 挂死看门狗 | 120s | 在途执行超时强制熔断并释放租约 |
| Manual/Test 等待上界 | 120s | 含排队与执行；超时返回 Timeout |
| 执行记录 Error 截断 | 2000 字符（实体 4000） | 超长截断 |
| 执行记录 Output 截断 | 8000 字符 | 超长截断 |
| 队满告警限流间隔 | 30s | 防止刷屏 |
| 执行记录保留期 | 系统配置 `RetentionPeriodDays`，默认 90 天 | 每天 03:00 分批清理（批 2000 条，批间 200ms） |

## 五、可观测性：去哪里看

| 渠道 | 看什么 | 备注 |
|---|---|---|
| **前端控制台**（编辑页底部） | 实时输出、执行记录分页表（时间/触发/结果/耗时/执行人/错误） | 自动触发的执行结果经 **SignalR** 实时推送 |
| **执行记录表** `ScriptExecutionRecords` | 全量历史，可按 `result` 过滤 | `StartedAt` 为 **UTC**；`ScriptVersion` 是执行时的版本快照 |
| **服务端日志** | 调度异常、队满告警、写桥超时、挂死看门狗、观测统计 | 关键日志见下 |
| **列表页标签** | 脚本列表上直接显示「熔断」「停用」徽标 | 一眼看出哪些脚本有问题 |

**值得记住的服务端日志关键字**（按严重度）：

```
[Error]   脚本 {Id} 执行挂死（Ns 未完成...）        ← 看门狗触发，需立即处理
[Error]   脚本派发消费循环因未预期异常退出。        ← 全部脚本停摆
[Error]   脚本调度循环因未预期异常退出。            ← 调度停摆
[Warning] 脚本派发队列已满（容量 N），触发被丢弃    ← 消费能力不足（30s 限流）
[Warning] 脚本写桥写入超时：设备:变量（等待 Nms）   ← 设备写入慢
[Warning] 脚本 Cron [...] 计算下次运行时间失败       ← Cron 非法，脚本不进调度
[Info]    脚本引擎重载完成：共 N 项启用脚本，M 项进入调度。
[Info]    脚本派发观测：队列深度=...                ← 仅在有异常时输出
```

## 六、维护建议

### 命名与组织

- 脚本名带上设备或功能域：`锅炉-超温保护`、`LINE01-班次切换`，别叫 `脚本1`。
- **一个脚本管一件事**。500 行的巨型脚本会变慢、难排查，且一处失败整段熔断。
- 复用的工具函数（如 `num()` / `clamp()`）在每个脚本里各存一份——沙箱不支持模块导入。

### 变更管理

- **版本自动 +1**：每次保存都算一次发布。改线上脚本前先看执行记录确认当前状态。
- **保存会复位熔断**，所以出问题先取证再修改。
- 重大改动：先停用旧脚本 → 新建脚本试运行验证 → 再启用新的、停用旧的。

### 安全

- **最小权限授权**：只勾真正用到的设备/变量。全勾图省事 = 一次误写可能影响多台设备。
- **控制类脚本必须判质量**：`getQuality(...) === "Good"` 是底线。
- **输出必须限幅**：`clamp()` 之后再 `write()`。
- **安全联锁不要只靠脚本**：脚本不参与调度时（熔断/停用/服务重启）联锁就失效了。
  关键安全逻辑应放在设备侧或驱动层，脚本只做辅助。
- **删除变量会联动停用监听它的 OnChange 脚本**（并在 LastError 注明原因），
  但**不会**自动清理脚本里对它的 `read()` 调用——那些会静默返回 `null`。删变量后请人工复查。

### 性能

- 周期触发的间隔要 **大于** 脚本实际耗时，否则大量 `[BUSY]`。
- 一次执行里的 `write()` 次数要节制（每个最坏阻塞 6s）。
- 高频、单点、纯数学的换算 → 用**工程换算表达式**，不要占用脚本队列。

## 七、FAQ

**Q：`read()` 返回 null，但变量明明存在？**
A：三种可能对脚本表现完全一致——① 没勾读授权 ② 设备不在运行中 ③ 键名拼错（大小写敏感）。
用 `getQuality()` 区分：返回 `Unknown` 说明设备不存在或**未授权**；返回具体质量说明变量存在但当前值不可用。

**Q：为什么我的 `var counter = 0` 每次都是 0？**
A：每次执行都新建沙箱，脚本无状态。要持久化就 `write()` 存进变量（见示例 12、14）。

**Q：顶层的 `log()` 为什么看不到？**
A：钩子调用前输出缓冲会被清空。把所有 `log()` 和逻辑都放进 `run()` / `onChange()`。

**Q：试运行显示写入成功，为什么设备没动作？**
A：试运行是 dry-run，`write()` 只打印 `[DRY-RUN]` 并返回 `true`，不会真实下发。

**Q：手动运行可以，自动触发就不行？**
A：检查 ① Active 是否勾选 ② 触发类型的必填字段 ③ 是否熔断（手动运行会绕过熔断，所以手动能跑不代表调度能跑）。

**Q：写超时返回 false，但设备后来动作了？**
A：写桥超时（默认 6s）后引擎放弃等待，底层成为孤儿任务继续跑，可能最终成功。
以**写入审计日志**为准，不要盲目重试。

**Q：能不能在脚本里 sleep / 延时？**
A：不能，没有 `setTimeout`。需要延时逻辑就拆成「状态变量 + 周期触发」：
本轮设置状态并 return，下轮读状态继续（见示例 09）。

**Q：脚本能发邮件 / 调 HTTP 接口吗？**
A：不能。沙箱没有网络能力，这是刻意的安全边界。

**Q：OnChange 脚本疯狂触发怎么办？**
A：三件套——加大 `DeadBand`（模拟量建议量程的 0.5%–2%）、加大 `CooldownMs`、
在代码里加状态判断避免重复下发。特别注意**不要写回被监听的那个变量**（回声）。

**Q：执行记录会一直累积吗？**
A：不会。每天 03:00 按系统配置的保留期（默认 90 天）分批清理，批 2000 条、批间 200ms，避免长事务锁表。
