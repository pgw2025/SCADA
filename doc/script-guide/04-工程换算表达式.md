# 04 · 工程换算表达式

> 这是系统里的**第二类脚本能力**：写在变量配置里的单行数学表达式。
> 它与「系统脚本」**不是一回事**，能力小得多，但**快得多**——它跑在采集线程内，零调度延迟。
>
> 技术栈同样是 Jint 3.1.3，但沙箱更严：**只允许 18 个白名单函数**。

---

## 一、它是什么，该在什么时候用

### 定义

一个以 **`x` 代表驱动读到的原始值**的一元表达式，用于把原始值换算成工程值：

```
工程值 = f(原始值)        其中 f 就是你填的表达式，输入变量固定叫 x
```

### 配置位置（两层，可覆盖）

| 层级 | 字段 | 位置 |
|---|---|---|
| **模板级** | `DataPoint.ScaleExpression` | 变量模板（ModelVariable / DataPoint）的「量程换算表达式」 |
| **设备级覆盖** | `DataPointMapping.ScaleExpressionOverride` | 某个设备下该变量的「换算表达式覆盖」 |

**优先级：`ScaleExpressionOverride` 优先，为空才回退到模板的 `ScaleExpression`。**
两者都为空 → 恒等变换（工程值 = 原始值）。

### 选型对照：用表达式还是用脚本？

| 场景 | 该用 | 理由 |
|---|---|---|
| `x * 0.1`、把 4-20mA 原始码转成工程量 | **表达式** | 采集线程内同步求值，零延迟；每个变量独立配置 |
| 一个值参与计算，只涉及它自己 | **表达式** | 同上 |
| 需要**多个变量**参与计算（如温压补偿要用温度+压力） | 系统脚本 | 表达式只有一个输入 `x` |
| 需要**条件判断 / 分支 / 循环 / 写其它变量** | 系统脚本 | 表达式只是一个表达式 |
| 需要**下发控制** | 系统脚本 | 表达式不能写 |
| 需要**定时 / 事件驱动** | 系统脚本 | 表达式随采集被动触发 |

> 判断口诀：**单个值的纯数学变换 → 表达式；涉及业务逻辑 → 脚本。**

## 二、语法规则

### 可用元素

| 类别 | 允许 |
|---|---|
| 输入变量 | `x`（**唯一**变量名，小写，不能用别的字母） |
| 数字 | `0-9`、小数点 `.`、科学计数法 `1.5e-3`（`e`/`E` 允许） |
| 运算符 | `+` `-` `*` `/` `%`（取模） `(` `)` `,` |
| 空白 | 空格、制表符等 |
| 函数 | **仅 18 个白名单函数**（见下节），可带 `Math.` 前缀也可不带 |

### 长度

**≤ 200 字符**（与数据库 `[MaxLength(200)]` 一致，保存时校验）。

### 合法示例

```
x * 0.1
(x - 4000) / 160
x * 1.8 + 32
Math.round(x * 10) / 10
x * 1.5e-3
min(x, 100)
max(0, (x - 4000) / 160)
sqrt(x) * 12.5
```

### 非法示例与原因

| 表达式 | 为什么不行 |
|---|---|
| `y * 2` | 变量名必须是 `x`，`y` 是非法字符 |
| `Math.PI * x` | `Math.PI` 不带括号，**不会**被白名单函数识别 → 剩余字母 `PI` 触发字符白名单拦截 |
| `x * random()` | `random` 不在白名单（禁止不确定性函数） |
| `Date.now()` | `Date` 不在白名单 |
| `x > 100 ? 1 : 0` | 三元运算符 `?` `:` 不在字符白名单 |
| `if (x > 0) x else 0` | 表达式不是语句，不支持控制流 |
| `parseFloat(x)` | `parseFloat` 不在白名单 |
| `x * 0.1; log(x)` | 分号与函数调用都不允许；**表达式里也没有 `log()`** |

## 三、18 个白名单函数（完整清单）

保存时由 `ScaleExpressionValidator` 逐项校验，**不在表内的一律拒绝**：

| 函数 | 用途 | 示例 |
|---|---|---|
| `abs(x)` | 绝对值 | `abs(x)` |
| `min(a,b)` | 取较小值 | `min(x, 100)` |
| `max(a,b)` | 取较大值 | `max(0, x)` |
| `pow(a,b)` | 幂运算 | `pow(x, 2)` / `pow(10, x)` |
| `sqrt(x)` | 平方根 | `sqrt(x) * 12.5` |
| `exp(x)` | e 的 x 次方 | `exp(x / 10)` |
| `log(x)` | 自然对数 | `log(x)` |
| `log10(x)` | 常用对数 | `20 * log10(x)` |
| `round(x)` | 四舍五入 | `round(x * 10) / 10` |
| `floor(x)` | 向下取整 | `floor(x)` |
| `ceil(x)` | 向上取整 | `ceil(x)` |
| `sign(x)` | 符号（-1/0/1） | `sign(x) * sqrt(abs(x))` |
| `sin(x)` | 正弦（弧度） | `sin(x)` |
| `cos(x)` | 余弦（弧度） | `cos(x)` |
| `tan(x)` | 正切（弧度） | `tan(x)` |
| `asin(x)` | 反正弦 | `asin(x)` |
| `acos(x)` | 反余弦 | `acos(x)` |
| `atan(x)` | 反正切 | `atan(x)` |

**为什么只有这些？** 全部是**无副作用的一元/二元纯函数**。
刻意排除了 `random`（不确定性）、`Date.now`（时间依赖）、字符串解析、以及一些会引入
环境依赖的成员——因为表达式跑在采集热路径上，必须**对同一输入永远得到同一输出**。

**前缀可选**：`Math.round(x)` 与 `round(x)` 等价（校验器的正则允许可选的 `Math.` 前缀，包括带空格的 `Math . round(` 写法）。

## 四、保存时的三重校验

`ScaleExpressionValidator.Validate()` 返回 `null` 表示合法，否则返回中文错误原因（直接展示给前端）：

```
1) 长度检查           > 200 字符 → 拒绝
        ↓
2) 函数名白名单       把形如 "foo(" 或 "Math.foo(" 的调用提取出来，
                      命中白名单就替换成 "("，否则打上哨兵字符 → 拒绝
        ↓
3) 字符白名单         剥离函数调用后，剩余字符必须全部匹配 ^[0-9x\s+\-*/%().,eE]*$
        ↓
4) Jint 语法解析      包成 function __check(x) { return (expr); }
                      只定义不调用 → 只解析不执行，校验阶段绝不运行用户代码
```

> 第 4 步的"只解析不执行"很关键：**配置一个会除零的表达式，保存时不会报错**，
> 因为校验阶段根本没求值。除零要到运行时才会被拦截（见下节）。

## 五、运行时的求值机制与失败降级

### 编译与缓存

```
表达式字符串（不可变，天然适合做缓存 key）
   │
   ├─ 命中缓存 → 直接取已编译的 Jint Engine + 函数名
   │
   └─ 未命中 → 编译：
        new Engine(o => o.Strict()
                         .LimitRecursion(2)        // 递归深度 2
                         .MaxStatements(64)        // 最多 64 条语句
                         .TimeoutInterval(50ms))   // 求值超时 50ms
        engine.Execute("function __scale(x) { return (expr); }")
        ↓
        试探求值：engine.Invoke("__scale", 1)      // 用 x=1 试一次
        ├─ 抛异常 → 编译失败，不缓存，返回 false
        └─ 结果 NaN / Infinity → 编译失败，不缓存
        ↓
        写入缓存（缓存上限 4096 条，超限整体清空）
```

- **线程安全**：Jint 的 `Engine` 实例非线程安全，所以每个缓存项自带一把锁（`lock (compiled.Gate)`），
  求值时短临界区串行。表达式通常微秒级完成，不会成为瓶颈。
- **缓存不失效**：表达式不可变，配置改了就是新 key，旧项自然淘汰。

### 求值（`ToEngineering`）

```csharp
if (expression 为空)      return raw;      // 恒等
if (raw is bool)          return raw;      // 数字量不换算
if (!TryToNumber(raw))    return raw;      // 字符串等非数值原样透传
return TryEvaluate(expr, x, out y) ? y : raw;
```

**失败降级原则**：编译失败、求值失败、超时、结果 NaN/Infinity —— **一律返回原始值**，
绝不抛穿到采集循环。

> 这条原则的后果：**配错了表达式，你看到的不是报错，而是"值没变"**。
> 排查时如果某个变量的值始终等于原始值，去检查它的表达式是否被降级了，并查看服务端日志。

### 调用点与方向

| 方向 | 方法 | 调用位置 | 当前行为 |
|---|---|---|---|
| 采集（raw → 工程值） | `VariableScaling.ToEngineering` | `DeviceWorker` 读取成功后 | **生效**，走表达式 |
| 写入（工程值 → raw） | `VariableScaling.ToRaw` | `RuntimeManager.WriteVariableAsync` 下发驱动前 | **恒等透传**，不做反算 |

> ⚠️ **重要提醒：写入方向不做反算。**
> 如果某个变量配了换算表达式、且它是**可写**的，那么脚本或 HMI 写入的值会**原样下发给驱动**，
> 不会执行表达式的逆运算（任意公式没有自动反函数）。
> 所以在给可写变量配表达式时要格外小心——必要时在**脚本侧**手动做反算再 `write()`。

## 六、常用公式速查

| 场景 | 表达式 | 说明 |
|---|---|---|
| 4-20mA / 码值转工程量（0-100） | `(x - 4000) / 160` | 4000 对应 0，20000 对应 100 |
| 简单比例 | `x * 0.1` | 原始值 ÷ 10 |
| 摄氏转华氏 | `x * 1.8 + 32` | |
| 保留一位小数 | `round(x * 10) / 10` | 采集侧就取整，减轻存储与显示负担 |
| 差压开方流量 | `sqrt(x) * 12.5` | `x` 为差压 |
| 限幅输出 | `min(100, max(0, x))` | 用 `min`/`max` 嵌套实现 clamp |
| 取绝对值 | `abs(x)` | 双向计量 |
| 取两位小数 | `round(x * 100) / 100` | |
| 工程量取反（反向安装） | `-1 * x` 或 `0 - x` | |
| 热电偶 mV 近似换算 | `x * 24.4` | 示例，实际按标定表 |
| pH 换算 | `7 + (0 - x) * 1.5` | 示例 |
| 分贝 | `20 * log10(x)` | `x > 0` 时才有效，否则降级 |
| 死区归零 | `max(0, x - 5)` | 低于 5 视为 0 |

## 七、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 保存时提示"只允许使用白名单函数" | 用了非白名单函数 | 对照 §3 的 18 个函数改 |
| 保存时提示"包含非法字符" | 用了 `y`/`PI`/三元符等 | 只能用 `x`、数字、运算符、白名单函数 |
| 保存时提示"语法错误" | 括号不匹配等 | 检查括号 |
| 保存成功，但值没变化 | 运行时求值失败被降级 | 查服务端日志（Jint 异常不冒泡，只在缓存编译阶段静默失败） |
| 值变成 `NaN` 或无穷 | `x/0`、`log(负数)` | 求值器会拦截 NaN/Infinity 并返回原始值；用 `max()` 保护分母 |
| 数字量（bool）变量没换算 | 设计如此，bool 不参与换算 | 数字量不需要量程换算 |
| 写入的值没被反算 | 写入方向恒等透传（§5） | 在脚本侧手动反算后再写 |

## 八、与系统脚本的能力对比（一图看懂）

| 维度 | 工程换算表达式 | 系统脚本 |
|---|---|---|
| 输入 | 仅 `x`（当前变量的原始值） | 任意 `read()` 到的变量 |
| 可用函数 | **18 个白名单** | 宿主 4 个 + ECMAScript 标准库（约 300 成员） |
| 控制流 | 无（不能 if / for） | 完整 JS |
| 写变量 | 不能 | 可以（`write()`） |
| 触发方式 | 被动（每次采集成功后） | 手动 / 周期 / Cron / 变量变化 |
| 执行位置 | 采集线程内（同步） | 专用消费线程（经队列派发） |
| 延迟 | **零**（随采集即时完成） | 至少一个调度 Tick（约 250ms）+ 排队 |
| 超时 | 50ms | 500–30000ms（默认 2000） |
| 失败后果 | 降级为原始值，不影响采集 | 计入失败，3 次熔断 |
| 需要授权 | 不需要 | 需要 ScopeRead / ScopeWrite |
