## 一、这套系统里有「三套脚本能力」

很多人以为「系统脚本」就是全部，其实项目里有三处可编程入口，它们的**能力边界完全不同**，用错了会踩坑：

| 能力 | 载体 | 语言形态 | 可用函数 | 作用位置 | 文档 |
|---|---|---|---|---|---|
| **系统脚本** | `SystemScripts` 表 / 「系统脚本管理」页 | 完整 JS 函数（`run()` / `onChange(ev)`） | 宿主 4 个 + ECMAScript 标准库（约 200+ 成员） | 独立线程、异步派发执行 | [01-API参考](./01-API参考-可用函数全清单.md)、[02-编写指南](./02-编写指南-触发器与执行模型.md) |
| **工程换算表达式** | 变量模板 / 设备变量的「量程换算表达式」 | 单行表达式，输入变量固定为 `x` | **仅 18 个白名单 Math 函数** | 采集热路径内同步求值 | [04-工程换算表达式](./04-工程换算表达式.md) |
| **触发联动** | 计划任务 `execute_script`、事件联动 `runScript`、HMI 按钮 `targetScriptId` | 不写代码，只引用系统脚本 ID | — | 复用系统脚本的执行/熔断/审计链路 | [02-编写指南 §7](./02-编写指南-触发器与执行模型.md#七脚本的三条外部触发入口) |

一句话区分：

- **系统脚本** = 你要写逻辑、读多个变量、做判断、下发控制 → 用它。
- **工程换算表达式** = 只想把一个采集原始值做数学变换（`x * 1.0 / 10 - 40`）→ 用它，因为它跑在采集链路上，**零调度延迟**。
- **触发联动** = 让已有脚本在按钮点击 / 报警事件 / 计划任务时刻被调用 → 用它。

## 三、5 分钟上手

### 第 1 步：打开编辑器

左侧菜单 → **系统脚本管理**。界面分三块：左侧脚本列表、右侧元数据表单 + 代码编辑器、底部控制台与执行记录。

### 第 2 步：写一个最小脚本

```js
// 模板：服务端 Jint 沙箱执行
// 可选钩子 run()（手动/周期/定时）与 onChange(ev)（变量变化）
log("hello scada");
```

改成一个真正干活的：

```js
function run() {
  var t = read("TANK01", "Temperature");   // 读变量（需读授权）
  log("当前温度 =", t, "质量 =", getQuality("TANK01", "Temperature"));

  if (t !== null && t > 80) {
    var ok = write("TANK01", "CoolingPump", true);   // 写变量（需写授权）
    log("超温，启动冷却泵 →", ok ? "成功" : "失败");
  }
}
```

### 第 3 步：配置元数据（容易漏，漏了脚本就"静默不干活"）

| 你要的效果 | 触发类型 | 必填字段 | 授权 |
|---|---|---|---|
| 点按钮/接口才跑 | `手动` | — | ScopeRead / ScopeWrite |
| 每 N 秒跑一次 | `周期` | 执行间隔 ≥ 1 秒 | 同上 |
| 每天 8:00 跑 | `Cron 定时` | Cron 表达式（Asia/Shanghai） | 同上 |
| 某个变量一变就跑 | `变量变化` | 监听设备键 + 监听变量键 | 同上 |

**关键**：代码里调了 `read()`，就必须把对应**设备键**加进「读授权」；调了 `write()`，就必须把对应 **`设备键.变量键`** 加进「写授权」。**空授权 = 拒绝全部**，且此时函数不抛异常，只在输出里打一行 `[DENIED]`——这是最常见的"脚本没反应"原因。

### 第 4 步：三步验证再上线

编辑器右上三个按钮，按顺序点：

1. **校验** — 只做语法 + 元数据静态检查，不执行代码。有 `Error` 级问题会阻止保存。
2. **试运行** — dry-run。真实读变量，但**写操作只打印 `[DRY-RUN]` 不落盘**，不落库、不更新熔断状态。
3. **运行** — 真跑（需先保存）。结果、耗时、输出都会出现在控制台。

### 第 5 步：确认它被调度到了

保存/修改后引擎自动重载。看底部「执行记录」表：有记录说明调度到了，看 `Trigger` 列确认触发来源，看 `Result` 列确认结果。

## 四、心智模型：一次执行到底发生了什么

```
触发源（手动 / 周期 Tick / Cron 匹配 / 变量变化事件）
   │
   ▼
入队（有界队列，默认容量 256）──队满──► 丢弃，计日志（本次没跑）
   │
   ▼
专用消费线程出队（默认 2 条，与采集线程/HTTP 线程物理隔离）
   │
   ├─ 同一脚本上次还没跑完？──► Skipped（[BUSY]，不计失败）
   ├─ 已熔断（连续失败 ≥3）？──► Skipped（[TRIPPED]，手动/Test 可绕过）
   ▼
新建沙箱 → 执行顶层代码 → 调用 run() 或 onChange(ev)
   │                         │
   │                         ├─ read/getQuality ──► 鉴权 ──► 运行时内存值
   │                         └─ write ──► 鉴权 ──► 驱动写入（有界等待，默认 6s）
   ▼
落执行记录 + SignalR 推送到前端控制台
```

四个要记住的硬约束：

1. **每次执行都新建沙箱** → 脚本**无状态**，`var counter = 0` 写在函数外也没用，下次执行从零开始。要保留状态就写进变量（见示例 12、14）。
2. **顶层代码每次都会被执行，但它的 `log` 输出会被丢弃**（钩子调用前会清空输出缓冲）。所以顶层只放函数声明与常量，逻辑一律放钩子里。顶层的 `write()` **会真实执行**——这是危险的副作用。
3. **单脚本串行**：同一脚本的上一次执行没结束，新的触发直接丢弃，不会排队堆积。
4. **超时有两层**：脚本自身超时（默认 2000ms，范围 500–30000）+ 写桥超时（默认 6000ms，配置 `Scripting:WriteBridgeTimeoutMs`）。

## 五、术语表

| 术语 | 含义 |
|---|---|
| **设备键（deviceKey）** | 设备的唯一字符串标识（`Device.Key`）。**大小写敏感**，比较使用 `Ordinal`。 |
| **变量键（variableKey）** | 变量模板中的变量键（`ModelVariable.Key`），同设备下唯一。也是 SignalR 广播与 HMI 绑定的键。 |
| **ScopeRead** | 读授权，分号分隔的**设备键**列表，粒度到设备，不支持通配。 |
| **ScopeWrite** | 写授权，分号分隔的 **`设备键.变量键`** 列表，粒度到变量，禁止设备级通配。 |
| **熔断（Tripped）** | 连续失败 ≥ 3 次自动置位，调度器跳过该脚本。手动运行可绕过；保存或「复位熔断」可清除。 |
| **死区（DeadBand）** | 仅 OnChange 触发生效：`|新值 - 旧值| > DeadBand` 才触发。空 = 任意变化都触发。 |
| **冷却（CooldownMs）** | 仅 OnChange 触发生效：两次触发的最小间隔，抑制抖动与写回声。默认 500ms。 |
| **写回声** | 脚本写变量 → 触发 OnChange → 又写一次 → 死循环。用死区 + 冷却 + 状态判断来规避。 |
| **孤儿写入** | 写桥超时放弃等待后，底层驱动写入仍在继续的任务。最终结果以写入审计日志为准。 |
| **工程值** | 经过量程换算表达式变换后、存入运行时内存的值。`read()` 读到的就是工程值。 |

## 六、写在最前面的三条铁律

1. **没有授权就不会有数据，而且不会报错。** `read()` 越权返回 `null`，`write()` 越权返回 `false`，只在输出里留一行 `[DENIED]`。写完脚本第一件事是检查授权面板。
2. **脚本里没有 `console`。** 写 `console.log()` 会直接抛 `ReferenceError` 并计入失败次数，3 次就熔断。输出一律用 `log()`。
3. **不要用脚本做采集热路径上的事。** 高频换算请用变量的「工程换算表达式」（它在采集线程内同步求值，零调度延迟）；脚本走的是队列 + 专用线程，最快也要等一个 Tick（约 250ms）。
