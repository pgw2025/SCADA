## 阶段三：离线壳与缓存安全（5 步）

### 步骤 8：运行时缓存策略（白名单 + NetworkFirst）

**任务**：SW 运行时路由落地（D4 + 优化点 3/4）。

**涉及文件**：
- `Client/src/sw.ts`
- `Client/src/constants/pwaCache.ts`（新增：缓存名/白名单/排除清单常量，供 SW 与页面共用）

**具体改动**：
1. 以 `Client/swagger.json` 为准，逐项核对并编制 API 白名单/排除清单（详细设计 §3.3），写入 `pwaCache.ts`：
   - `CACHEABLE_API_PREFIXES`（设备/变量/报警记录/组态工程与页面/区域/看板等只读 GET）
   - `EXCLUDED_API_PREFIXES`（`/api/Auth`、`/api/Users`、`/api/NotificationConfig`、`/api/SystemLog`、`/open`、`/hubs`）
2. `sw.ts` 注册运行时路由（`registerRoute`）：
   - 导航请求：`NetworkFirst`，`cacheName: 'html-runtime'`，`networkTimeoutSeconds: 3`；
   - API GET 白名单：`NetworkFirst`，`cacheName: 'api-runtime'`，`networkTimeoutSeconds: 3`，`ExpirationPlugin(maxEntries 200, maxAgeSeconds 86400)`；
   - 白名单外 `/api`、`/open`、非 GET：不注册路由（SW 透传网络）。
3. 断网语义：NetworkFirst 超时+失败→回缓存→缓存亦无→导航回 `index.html`（precache）；API 无缓存→正常抛网络错误（由既有 http.ts 统一 toast，阶段六快照补充兜底）。

**验收标准**：DevTools Network 离线后刷新任意路由（如 `/alarm-management`）不白屏（壳可开，数据区显示既有错误/空态）；在线访问白名单 API 后再断网，`api-runtime` 缓存命中；`/api/Auth/me` 永不出现在缓存列表；POST 请求从不落缓存。

### 步骤 10：登出/换号/401 的缓存清理（跨账号安全防线二）

**任务**：三路径统一 `CLEAR_USER_DATA`（D5）。

**涉及文件**：
- `Client/src/services/pwaSecurity.ts`（新增：`clearUserData()`——postMessage 清 SW 缓存 + 清 IndexedDB 快照（阶段六实现快照部分，本步留接口））
- `Client/src/api/authApi.ts`（登出/登录成功路径）
- `Client/src/api/http.ts`（401 强登出路径）
- `Client/src/sw.ts`（已含 CLEAR_USER_DATA 处理器，本步联调）

**具体改动**：
1. `pwaSecurity.ts`：`clearUserData()` 依次执行：`navigator.serviceWorker.controller?.postMessage({type:'CLEAR_USER_DATA'})`（SW 侧删 `api-runtime`/`html-runtime`）；`snapshotDB.clearAll()`（阶段六落地，本步空实现+注释）；记录 debug 日志。
2. 接入三路径：
   - `authApi` 登出（用户主动）：清 token 后调 `clearUserData()`；
   - `authApi` 登录成功：若本次登录账号 ≠ 上次会话账号（userStore 既有信息/localStorage 记录的 lastUserId），调 `clearUserData()`（换号，防线二）；同账号登录不触发（避免正常重新登录把缓存清光）；
   - `http.ts` 401 拦截器：清 token 分支追加 `clearUserData()`（与现有 `addLog`/`showToast` 并列）。
3. `lastUserId` 持久化：localStorage 键 `scada_last_user_id`，登录成功写入、登出清除。

**验收标准**：admin 登录浏览管理页（api-runtime 有缓存）→登出→operator 登录→断网→管理类数据**不可见**、白名单业务数据为 operator 视角或空；`api-runtime` 缓存在登出瞬间被删（DevTools Cache Storage 验证）；401 强登出路径同样触发清理；同账号重新登录不清缓存。

## 阶段四：前端推送订阅（6 步）

### 步骤 13：pushService 基础（权限 + 订阅 + 上传）

**涉及文件**：

**具体改动**：
1. `pushService.ts`：
   - `ensurePermission()`：仅在用户手势调用链内执行 `Notification.requestPermission()`；返回 `granted`/`denied`/`default`；
   - `subscribe()`：拉取 `GET /api/push/vapid-public-key` → `pushManager.subscribe({ userVisibleOnly: true, applicationServerKey })` → `POST /api/push/subscriptions` → 存续订令牌到 IndexedDB（专用小库或并入快照库 meta 区）供 SW 续订用；
   - `unsubscribe()`：`subscription.unsubscribe()` + `DELETE /api/push/subscriptions`；
   - `getSubscriptionState()`：当前浏览器订阅 + 服务器绑定状态（`GET /me` 回显）；

**验收标准**：手势触发权限弹窗；授权后 DevTools → Application → Push 可见订阅；服务器收到 POST 且换绑逻辑正确（阶段五 API 就绪前可用本地 mock 先行，就绪后联调）；退订后订阅消失。

### 步骤 14：订阅生命周期（换绑 + 自动续订）

**具体改动**：

**验收标准**：
1. 冷启动降级：清空 IndexedDB（DevTools 删除库）→ 断网启动 → 应用正常进入（空态提示），不白屏不崩溃；
2. 快照损坏（手工篡改库内容）→ 读取失败降级正常；
3. 移动端（真机）：切后台/杀进程后快照保留（pagehide 落盘验证）；
4. 主线程性能：写入器活跃时页面交互无可感知卡顿；
5. 存储占用：variables store 量级核算（设备数×变量数），超预期时补 TTL/容量上限策略（记录结论，必要时调 maxEntries）。
