## 步骤 0.2：数据库与 InfluxDB 备份基线

**任务**：

1. 对 MySQL `scada` 库做全量逻辑备份：

   ```
   mysqldump -u root -p --single-transaction --routines scada > backup_scada_<date>.sql
   ```
2. 记录 InfluxDB 当前 bucket 的保留策略与样本数据量（用于阶段验证 tag 连续性）：

   ```
   influx query 'from(bucket:"<bucket>") |> range(start: -1h) |> group() |> count()'
   ```
3. 导出现有设备/变量键值快照（后续每个阶段的"键值不变"校验依据）：

   ```sql
   SELECT Id, `Key`, AreaId, ModelId FROM Devices ORDER BY Id;
   SELECT Id, ModelId, `Key` FROM ModelVariables ORDER BY Id;
   SELECT Id, DeviceId, ModelVariableId, Address FROM DeviceVariables ORDER BY Id;
   ```

**涉及文件**：无代码修改；备份 SQL/CSV 存放于本地（建议 `docs/db-refactor/_baseline/`，不入库 git 或加入 .gitignore）。

**验收**：备份文件可恢复（在测试库演练一次 restore）；键值快照三个 CSV 已留存。

## 步骤 0.4：迁移工作流约定

**任务**：与团队确认并遵守：

1. 每个结构迁移单独一个 EF Migration（`dotnet ef migrations add <Name>`），回填逻辑放在**同阶段后续单独迁移或迁移内** **`migrationBuilder.Sql`** **分步执行**——保证"先加可空列 → 回填 → 观察期 → 收紧约束"的节奏。
2. 每个迁移在开发库执行 `dotnet ef migrations script` 生成 SQL 评审，重点检查：无 `DROP`、无非空新增列无默认值、锁表风险评估（当前库规模小，风险低，但保持习惯）。
3. 迁移命名沿用现有风格（动宾结构，如 `AddAreaTreeFields`）。
4. Git 分支策略：每阶段一个分支 `feature/db-refactor/phase-N`，阶段内每步骤至少一个 commit。

**验收**：约定写入本文件（已完成），团队知悉。
