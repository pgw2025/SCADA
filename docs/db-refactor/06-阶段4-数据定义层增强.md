# 阶段 4：数据定义层增强（3-4 天，中低风险）

> 目标：把目标设计中数据定义层的字段补全到现有 `DataModels`（≈DataModel）与 `ModelVariables`（≈DataPoint），并给 `DeviceVariables`（≈DataPointMapping）补连接引用。**不改表名、不改 Key 值、不动运行时解析逻辑**（新增字段全部为可空/带默认值的增量）。
> 前置：阶段 0（与阶段 1/2/3 无强依赖；但步骤 4.1 中的 DeviceVariable.ConnectionId 回填依赖阶段 3 完成，故建议排在阶段 3 之后）。

---

## 设计要点

1. **表名不改**（决策 D2）：`ModelVariables` 语义即 DataPoint，`DeviceVariables` 语义即 DataPointMapping。名字映射固化在 [00-总览 §七](00-总览与可行性分析.md)。
2. **ModelVariable.Key 绝对不动**——它是 InfluxDB `variable_key` tag 的一部分（R1 红线）。
3. AccessMode 采用**字符串枚举列**（`Read`/`Write`/`ReadWrite`），与现 bool `IsReadOnly` 并存：写入时同步维护（IsReadOnly = AccessMode == Read），读取时旧代码继续用 IsReadOnly，新代码用 AccessMode。旧列删除放阶段 6。
4. 现有超出目标设计的字段（StoreMode/StoreIntervalMs/UpdateMode/ScaleExpression/DeadBand/Min/Max/ExtensionData）**全部保留**——它们承载本系统历史存储与工程换算的刚需，目标设计未覆盖但绝不能丢。

## 步骤 4.1：ModelVariable（DataPoint）字段补全

**任务**：
1. [ModelVariable.cs](../../Server/ScadaServer.Domain/Entities/ModelVariable.cs) 新增：
   - `AccessMode`(string(16), 默认 "Read"；派生属性 `IsReadOnly => AccessMode == "Read"` 替代原存储列的语义——实现上保留原列，见下)
   - `IsRequired`(bool, 默认 false)
   - `Sort`(int, 默认 0)
   - `IsEnabled`(bool, 默认 true)
2. 兼容策略：原 `IsReadOnly` 列**暂不删除**。写入路径（ModelVariableAppService / DeviceVariableAppService 的覆盖值合并逻辑）改为以 AccessMode 为权威，同步写 IsReadOnly（双向一致性单点维护在应用服务层）。
3. 迁移 `AddModelVariableDefinitionFields`：
   - 新列带默认；
   - 回填：`AccessMode = CASE WHEN IsReadOnly = 1 THEN 'Read' ELSE 'ReadWrite' END`；`Sort = Id`（保持现有展示顺序）；`IsEnabled = 1`。
4. ScadaDbContext 补列配置（长度/默认值），唯一索引 `(ModelId, Key)` 不变。

**验收**：存量变量 AccessMode 回填正确（抽查只读/可写样本）；`dotnet build` + 冒烟清单通过（运行时读 IsReadOnly 不受影响——两列同步维护）。

## 步骤 4.2：DataModel 字段补全

**任务**：
1. [DataModel.cs](../../Server/ScadaServer.Domain/Entities/DataModel.cs) 新增：
   - `Code`(string(100)?)——模型编码（回填取 Name，唯一索引 `ix_datamodels_code`，NULL 允许多条）
   - `Version`(string(20), 默认 "1.0")
   - `IsPublished`(bool, 默认 true)
2. 迁移 `AddDataModelDefinitionFields`（可空/默认 + 回填 `Code = Name`；**Code 唯一索引在回填迁移之后单独创建**，防止存量重名直接炸迁移——若存在重名 Name，回填规则追加去重后缀 `-2`/`-3`，并在日志中报告）。
3. `ProtocolId` 语义注释更新为"默认协议（新建设备时预选）"（P3-E），字段暂不改可空性。

**验收**：模型列表 API 返回新字段；重名模型回填后 Code 唯一。

## 步骤 4.3：DeviceVariable（DataPointMapping）补连接引用

**任务**：
1. [DeviceVariable.cs](../../Server/ScadaServer.Domain/Entities/DeviceVariable.cs) 新增：
   - `ConnectionId`(int? FK→DeviceConnections)——变量级连接覆盖（空 = 使用设备默认连接）
   - `RawDataType`(string(32)?)——记录性字段（回填写 ModelVariable.DataType 的字符串形式；**驱动仍按 DataTypeEnum 解释，本阶段不启用校验**）
2. 迁移 `AddDeviceVariableConnectionRef`：可空列 + 回填 `ConnectionId = 所属设备的 ConnectionId` + FK/索引 `ix_devicevariables_connectionid`。
3. 运行时**本阶段不读**这两个新列（设备级连接在阶段 3 已生效）；列的启用放阶段 6。

**验收**：回填后每条设备变量 ConnectionId = 其设备 ConnectionId；运行时零影响（冒烟全绿）。

## 步骤 4.4：API 与 DTO 扩展（后端）

**任务**：
1. [ModelVariableAppService.cs](../../Server/ScadaServer.Application/Services/ModelVariableAppService.cs)（29 处引用，重点文件）：
   - DTO 增加 AccessMode/IsRequired/Sort/IsEnabled；
   - 创建/更新入参校验 AccessMode ∈ {Read, Write, ReadWrite}（与 IsReadOnly 的同步单点在此）；
   - 导入/导出（variableApi 的 import/export 链路）补充新字段的双向映射。
2. [DataModelAppService.cs](../../Server/ScadaServer.Application/Services/DataModelAppService.cs)：DTO 增加 Code/Version/IsPublished；创建时 Code 必填且唯一校验。
3. [DeviceVariableAppService.cs](../../Server/ScadaServer.Application/Services/DeviceVariableAppService.cs)：DTO 透传新字段；写权限校验逻辑从 `IsReadOnly/Override` 组合改为基于 AccessMode（Override 组合语义保持：实例级覆盖优先）。
4. 对应 Controller（ModelVariableController/DataModelController/DeviceVariableController）出参补充新字段。

**验收**：API 层新旧字段并存且一致（IsReadOnly 与 AccessMode 永不矛盾）；导入导出往返无损。

## 步骤 4.5：前端表单

**任务**：
1. [variableApi.ts](../../Client/src/api/variableApi.ts) / [modelApi.ts](../../Client/src/api/modelApi.ts)：类型定义补新字段。
2. [DataModelView.vue](../../Client/src/components/DataModelView.vue)：模型表单增加 Code/Version/IsPublished。
3. [DeviceVariableView.vue](../../Client/src/components/DeviceVariableView.vue)（前端引用最重，24 处）：
   - 变量编辑表单：只读/可写开关改为 AccessMode 三选（Read/Write/ReadWrite）；
   - 列表列增加 AccessMode/IsRequired/IsEnabled。
4. 兼容：IsReadOnly 旧字段在类型中标 `@deprecated` 注释（前端 TS），一个版本周期后移除。

**验收**：前端 `npm run build` 通过；新字段编辑保存回显正确；旧数据展示不受影响；冒烟清单全绿。

全部为加列/加字段，回滚应用版本即可；列闲置无害。

| 风险 | 等级 | 对策 |

| AccessMode 与 IsReadOnly 双列失同步 → 写权限判断错乱 | 中 | 同步逻辑收敛在 ModelVariableAppService/DeviceVariableAppService 两个单点；步骤 4.4 验收含一致性抽查 SQL |
| DataModel.Code 回填重名 | 低 | 去重后缀规则 + 迁移日志报告 |
| 前端 DeviceVariableView 改动面大 | 中 | 拆两个 commit：纯类型/展示（无逻辑）与权限控件替换（含校验）分开提交 |
