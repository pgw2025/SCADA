## 步骤 6.1：只读巡检（删除前置门禁）

**任务**：执行并留档以下巡检 SQL，**任何一项不通过则对应清理步骤顺延**：

1. 双读路径依赖统计：`SELECT COUNT(*) FROM Devices WHERE ConnectionId IS NULL;`（必须 = 0，或这些是刻意不采集的设备）
2. JsonConfig 与 Connection 一致性：抽样比对 `Devices.JsonConfig` 与其 `Connection.ConfigJson`（双写期结束后应一致；不一致的行先修复）
3. 主模型一致性：`Device.ModelId` ↔ `DeviceDataModels (IsPrimary=1)` 严格一致
4. AccessMode/IsReadOnly 一致性：`COUNT(LEFT JOIN ... WHERE 矛盾)` = 0
5. 键值快照第三次比对：Devices.Key / ModelVariables.Key 与阶段 0 基线零差异

**验收**：巡检报告全部通过。

## 步骤 6.4：删除废弃列（可选，逐列评估）

**任务**（每列独立迁移，顺序执行，任何一步出问题可停）：
1. 迁移 `DropDeviceJsonConfig`：删除 `Devices.JsonConfig`（及 `Devices.Version` 评估——若 Version 仅服务于协议配置追踪，迁移到 `DeviceConnections.UpdatedAt` 即可，列可删）；
2. 迁移 `DropModelVariableIsReadOnly`：删除 `ModelVariables.IsReadOnly`（旧 bool 列；DeviceVariable.IsReadOnlyOverride 同步评估——可改为 `AccessModeOverride` string(16)?，迁移回填后删旧列）；
3. `DataModels.ProtocolId` 评估：改为可空（"默认协议"语义弱化）或维持现状（推荐维持，避免影响 DataModelView 创建流程）。

> 以上 3 项**均为可选优化**：如果对稳定性有顾虑，可以全部推迟——废弃列闲置的维护成本几乎为零。至少保留到阶段 7 回归完成后。

**验收**：每列删除后全量冒烟 + `dotnet build` 前端 `npm run build` 通过。
