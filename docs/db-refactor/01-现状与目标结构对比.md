## 一、现有代码结构总览

### 1.1 项目分层

```
Server/
├── ScadaServer.Domain/            # 实体、枚举、领域接口
│   ├── Entities/                  # Device/DataModel/ModelVariable/DeviceVariable/Protocol/Area/AlarmRecord/...
│   ├── Enums/
│   ├── Addresses/                 # AddressConfig 结构化地址
│   └── Interfaces/                # IRuntimeDevice 等
├── ScadaServer.Infrastructure/    # 持久化、通信、Influx
│   ├── Persistence/               # ScadaDbContext + Migrations(31个)
│   ├── Repositories/              # 27 个仓储
│   ├── Communication/             # ProtocolDriverFactory/S7Driver/OpcUaDriver/VirtualDriver
│   └── Influx/                    # InfluxStore
├── ScadaServer.Application/       # 应用服务（AppService）+ DTO
├── ScadaServer.Runtime/           # RuntimeManager/DeviceRuntime/DeviceWorker/AlarmRuleEngine
└── ScadaServer.WebApi/            # 30 个 API Controller + HostedServices(RealtimeSnapshotService 等)

Client/
├── src/api/                       # deviceApi/deviceVariableApi/modelApi/variableApi/databaseApi...
├── src/components/                # DeviceManagementView/DeviceVariableView/DataModelView/LiveDataView...
└── src/services/                  # signalRService/dataOrchestration...
```

### 1.2 现有实体关系图

```
Area (平级) 1 ──── N Device
                        │ ModelId (N:1, 必填)
                        ↓
                    DataModel ── ProtocolId (N:1, 必填) ──→ Protocol(Key/Name/DriverKey)
                        │ 1:N
                        ↓
                   ModelVariable (模板: Key/DataType/ScaleExpression/DeadBand/StoreMode...)
                        │ 1:N
                        ↓
                   DeviceVariable (实例: DeviceId + ModelVariableId + Address/AddressConfigJson + Override*)
                        （DeviceVariable 同时挂 Device 1:N）

运行时: RuntimeManager.InitializeAsync
  → db.Devices.Include(Model).ThenInclude(Protocol)
                  .Include(DeviceVariables).ThenInclude(ModelVariable)
  → BuildAndRegisterDeviceAsync(device)
  → DeviceRuntime(Device.JsonConfig + Protocol.DriverKey → ProtocolDriverFactory → IProtocolDriver)

实时值: DeviceWorker → IRealtimeSnapshotService.Update(内存快照)
  → RealtimeSnapshotService (1s 周期批量 Upsert MySQL VariableRealtime)
  → SignalR /hubs/scada 推送前端

历史值: DeviceWorker → InfluxStore.WriteAsync (measurement=variable_history, tags=device_key+variable_key)

报警:   AlarmRuleEngine(DeviceId+VariableKey 查规则) → AlarmRecorder → MySQL AlarmRecords
```

文件：[Server/ScadaServer.Domain/Entities/ModelVariable.cs](../../Server/ScadaServer.Domain/Entities/ModelVariable.cs)

### 2.6 `DeviceVariables`（设备变量 ≈ 目标 DataPointMapping）

关键字段：`Id`、`DeviceId`(FK)、`ModelVariableId`(FK)、`Address`(string?)、`BitOffset`(int?)、`AddressConfigJson`(longtext, **权威机读地址**，经 AddressConfigSerializer 生成 Address 展示串)、`IsEnabled`、`PollingIntervalMs`(int?)、`ScaleExpressionOverride`、`DeadBandOverride`、`IsReadOnlyOverride`、`ExtensionData`。唯一索引 `ix_devicevariable_device_model` (DeviceId, ModelVariableId)。Override 语义：实例值为空回退模板值。

文件：[Server/ScadaServer.Domain/Entities/DeviceVariable.cs](../../Server/ScadaServer.Domain/Entities/DeviceVariable.cs)

### 2.7 运行数据层（已就绪，无需重构）

| 目标表 | 现有实现 | 状态 |
|---|---|---|
| DeviceDataValue | `VariableRealtimes` 表（DeviceId/DeviceKey/VariableKey/Value/RawValue/Quality/Timestamp），由 [RealtimeSnapshotService](../../Server/ScadaServer.WebApi/HostedServices/RealtimeSnapshotService.cs) 1s 批量 Upsert | ✅ 就绪 |
| DataHistory | InfluxDB `variable_history`，tags=device_key+variable_key，fields=value/raw_value/quality/device_id/variable_name（[InfluxStore](../../Server/ScadaServer.Infrastructure/Influx/InfluxStore.cs)） | ✅ 就绪 |
| AlarmRecord | `AlarmRecords`（DeviceId/DeviceKey/VariableKey/RuleId/Level/TriggeredAt/RecoveredAt/Acked...，含 3 个索引） | ✅ 就绪 |

### 2.8 连接配置现状（阶段 3 的核心输入）

当前一台设备的"连接"由三处共同决定：
1. `Device.JsonConfig`：IP/端口/rack/slot/OPC UA 端点等协议私有参数（longtext JSON）；
2. `Device.ModelId → DataModel.ProtocolId → Protocol`：用哪个协议/驱动；
3. `Device.PollingInterval` + `DeviceVariable.PollingIntervalMs`：采集周期。

即：**"设备型号（DataModel）"与"怎么连（协议+连接参数）"目前是绑定关系——设备选了模型就定了协议，连接参数全在设备自己的 JsonConfig 里。** 目标设计要把它拆为 Controller（物理控制器资产）+ DeviceConnection（连接参数）两个独立实体。

## 五、差距总表（按改动量排序）

1. **DeviceConnection 抽取（含 Controller 前置）**：2 张新表 + 回填 + 运行时双读改造 + 前端表单 → 阶段 2+3，工作量最大、风险最高。
2. **DeviceDataModel 多对多**：1 张新表 + 变量解析语义调整 + 前端绑定 UI → 阶段 5。
3. **Area 树形化**：加列 + 树 API + 前端树 → 阶段 1，纯加法、低风险。
4. **定义层字段补全（DataModel/ModelVariable）**：加列 + API + 表单 → 阶段 4，低风险。
5. **DeviceDataValue / DataHistory / AlarmRecord**：已就绪，仅可选增强（阶段 6）。
