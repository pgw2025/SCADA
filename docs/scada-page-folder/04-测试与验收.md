# 04 测试与验收

> 覆盖功能、回归、权限/审计、迁移与编译构建。执行完 P1–P6 后按本清单逐项打勾。

## 1. 文件夹 CRUD 功能

- [ ] 桌面端/移动端各能「新建文件夹」（根级），名称合法、落库后 serverId 回填、刷新不丢。
- [ ] 能新建子文件夹（嵌套 ≥ 2 层），树形正确展开/折叠。
- [ ] 重命名文件夹即时生效，600ms 防抖 PUT，刷新后名称一致。
- [ ] 同名文件夹（同 ProjectId+平台+父级）新建时前端拦截 + 后端 400。
- [ ] 移动文件夹到另一父级后，树结构正确，`ParentFolderId` 更新。

## 2. 删除语义验证

- [ ] **reparent（默认）**：删除含子夹+画面的文件夹后，其直接子夹与直接画面全部上提一级，无任何丢失；孙目录内部结构不变。
- [ ] reparent 删除根级文件夹后，内容回退该端根级（`FolderId/ParentFolderId=null`）。
- [ ] reparent 后目标父级 `SortOrder` 已连续重排，无重复/空洞。
- [ ] **cascade**：删除含子夹+画面的文件夹后，整个子树（文件夹+画面+组件）在同一事务删除，后端无残留记录。
- [ ] cascade 会把工程页面删到 0 时被拦截（前端 + 后端双层）。
- [ ] 删除后 `selectedPageId` 不指向已删页面（自动切到首个存活页）。

## 3. 拖拽排序

- [ ] 画面拖入文件夹、拖出到根级、在文件夹间移动，`FolderId` 正确。
- [ ] 文件夹段内拖动、画面段内拖动，顺序按拖拽结果保存。
- [ ] 快速连续拖拽不产生重复 SortOrder、不丢顺序。
- [ ] 刷新后顺序与拖拽结果完全一致。
- [ ] 跨端拖拽被拦截并提示（不落库）。

## 4. 画面既有功能回归

- [ ] 叶子画面选中、重命名、复制、导出、设首页、删除 5 项动作全部正常。
- [ ] 首页唯一性（同端至多一个）不受文件夹影响。
- [ ] 复制画面到文件夹内：副本归属正确（跟随源或留空，需与实现确认）。
- [ ] 组件绑定、实时数据、图层/背景编辑不受影响。
- [ ] Popup 弹窗画面三件套（新建/平铺/操作）保持原样，不参与文件夹。

## 5. 兼容与迁移

- [ ] 打开存量工程：画面全部落各端根级，`SortOrder` 递增且显示顺序与改造前一致。
- [ ] 存量弹窗画面 platform=Popup 不出现文件夹、正常显示。
- [ ] 迁移脚本在空库/有数据库均能执行；回填 SQL 不报错。

## 6. 导入导出

- [ ] 导出工程/画面迁移文件不含 folderId（结构未变）。
- [ ] 导入工程：全部画面落根级（`FolderId=null`），首页去重/重名后缀逻辑不变。
- [ ] 导入单画面到指定工程：落根级，不与现有文件夹冲突。
- [ ] 剪贴板复制/粘贴画面：不携带文件夹归属或正确赋新（需与实现确认），不产生孤立 folderId。

## 7. 权限与审计

- [ ] 文件夹所有端点 `RequireAdmin`，Operator/Viewer 访问返回 403。
- [ ] 新建/重命名/删除/排序均写审计日志（Category/relatedId 正确）。
- [ ] 非 Admin 打开工程只能看到画面树，不能操作文件夹。

## 8. 编译与构建

- [ ] `dotnet build`（Server）0 error。
- [ ] `npm run build`（Client）通过、无 TS 报错。
- [ ] EF 迁移 `script`（dry-run）生成且可执行。

## 9. 性能与稳定性

- [ ] 页面/文件夹数量较大（如 50 夹 + 200 画面）时树渲染无卡顿（buildFolderTree 复杂度合理）。
- [ ] 拖拽/删除/排序无请求风暴（防抖/批量生效）。
- [ ] 删除/移动/排序失败（网络抖动）可重试，不产生半删状态（事务保证）。

---

> 上述第 4/7 节中标注「与实现确认」的两项（复制画面归属、剪贴板是否携带 folderId），在 P5/P6 实现时需最终定稿：建议均「不携带文件夹归属、落根级」，保持与导入行为一致、实现最简。
