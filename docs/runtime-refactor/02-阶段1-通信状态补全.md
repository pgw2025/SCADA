## 设计总览

### 新增字段与生命周期决策（对照 00 总览原则 2）

| 字段                                     | 存储位置                     | 生命周期                 | 理由                                                                                    |
| -------------------------------------- | ------------------------ | -------------------- | ------------------------------------------------------------------------------------- |
| `LastError` (string?)                  | DeviceRuntime 实例         | 连接周期级（runtime 重建即清空） | 新连接周期开始后旧错误无意义；D3 选 b 时成功不清空，由下次失败覆盖                                                  |
| `ConnectionStateChangedAt` (DateTime?) | DeviceRuntime 实例         | 连接周期级                | 「本次连接周期内最近一次状态翻转时刻」；重建后为 null 直到首次变化                                                  |
| `ReconnectCount` (int)                 | **RuntimeManager 进程级字典** | 进程级（跨重连/重载累计）        | **P1 修正**：重连流程整体重建 runtime（RuntimeManager.cs:270→281→405），实例字段计数必然丢失；进程级才是「网络稳定性」观测指标 |
| `LastReconnectAt` (DateTime?)          | RuntimeManager 进程级字典     | 进程级                  | 最近一次发起重连的时刻，与 Count 配对输出                                                              |

### 打点位置总图

```
DeviceWorker.WorkerAsync
 ├─ 变量读失败 catch（L245–254）───────► runtime.LastError = 截断(ex.Message)

DeviceRuntime.ConnectionState setter（L57–67）

RuntimeManager.ReconnectDeviceAsync（L261–282）
 └─ TryRemove 门闸成功后 ─────────────► _reconnectStats[deviceId] 计数 +1 / 时间戳
```

## 步骤 1.1 DeviceRuntime 新增实例字段

**文件**：`Server/ScadaServer.Runtime/Devices/DeviceRuntime.cs`

**任务**：在既有统计字段区（L92–110 附近，`LastCommunicationTime` 一组之后）新增：

```csharp
/// <summary>
/// 最近一次采集/连接失败的原因（截断至 500 字符）。
/// 生命周期：连接周期级——runtime 重建（重连/重载）即清空；
/// 采集成功后不清空（D3-b：保留最近错误利于排障），由下次失败覆盖。
/// </summary>
public string? LastError { get; set; }

/// <summary>
/// 本次连接周期内最近一次连接状态翻转时刻（UTC）。
/// 由 ConnectionState setter 在值变化分支推进；runtime 重建后为 null，直至首次状态变化。
/// 注意：与进程级 ReconnectCount（RuntimeManager 维护）生命周期不同，见方案 P1。
/// </summary>
public DateTime? ConnectionStateChangedAt { get; set; }
```

**要点**：

- 保持既有平铺风格（setter 公开、由 Worker/Manager 手动维护），不引入 ConnectionRuntime 子对象（原方案已判定完整分区档不做，本方案沿用）；

- `LastError` 用 `string?`，无长度校验依赖（截断在打点处做）。

**验收**：`dotnet build` 通过；无其他引用改动。

## 步骤 1.2 ConnectionState setter 推进时间戳

**文件**：`Server/ScadaServer.Runtime/Devices/DeviceRuntime.cs`（L57–67）

**任务**：在 setter 的值变化分支内（`_connectionState = value;` 之后、事件 Invoke 之前或之后均可，建议放在赋值后紧邻位置）增加一行：

```csharp
set
{
    if (_connectionState == value) return;
    _connectionState = value;
    ConnectionStateChangedAt = DateTime.UtcNow;   // ← 新增：仅值变化时推进
```

**要点**：

- 该赋值发生在 Worker 线程与注册线程等多调用方，与既有 `_connectionState` 写同线程上下文，无新增竞态。

**验收**：阶段 0 基线场景 b（断线重连）日志时序比对一致——状态推送的次数与顺序不变。

## 步骤 1.3 RuntimeManager 进程级重连统计（P1 修正核心）

**文件**：`Server/ScadaServer.Runtime/RuntimeManager.cs`

**任务 1.3a**：新增进程级统计容器（与 `_lastPushedStatus` L65 相邻声明）：

```csharp
/// <summary>
/// 设备自动重连的进程级统计：key = 设备ID。
/// 生命周期为进程级：跨 runtime 重建（重连/重载会整体替换 DeviceRuntime 对象）累计——
/// 挂在 DeviceRuntime 实例上的计数会在每次重连时随旧对象销毁而丢失（方案 P1）。
/// 语义：进程启动以来自动重连发起次数（含初始连接失败后的占位重连）。
/// </summary>
private readonly ConcurrentDictionary<int, DeviceReconnectStats> _reconnectStats = new();

/// <summary>单设备重连统计（进程级聚合）。</summary>
private sealed class DeviceReconnectStats
{
    public int Count { get; set; }
    public DateTime? LastReconnectAt { get; set; }
}
```

**任务 1.3b**：在 `ReconnectDeviceAsync`（L261–282）的 TryRemove 门闸成功后（L270–273 与 `_lastPushedStatus.TryRemove` 相邻处）打点：

```csharp
if (!DeviceRuntimes.TryRemove(deviceId, out var runtime))
{
    return;
}

// 重连计数：仅统计实际发起的重连（门闸通过 = 本次重连成立）。
var stats = _reconnectStats.GetOrAdd(deviceId, _ => new DeviceReconnectStats());
stats.Count++;
stats.LastReconnectAt = DateTime.UtcNow;
```

**要点（与原方案的关键差异）**：

- 原方案建议的「BuildAndRegisterDeviceAsync 连接失败路径（L439–450）也应 +1」**不再采用**：该路径注册的占位对象在下次重连时销毁，且会导致「一次失败链」被重复计数（初始失败 → 占位注册 → 重连失败 → 又占位注册……每轮占位 +1 与 ReconnectDeviceAsync +1 双重计数）。修正后口径唯一：**ReconnectDeviceAsync 门闸通过 = 1 次重连**。初始连接失败不计入 ReconnectCount（它由 ConnectionStateChangedAt + LastError + DeviceStatus=Fault 共同表达，语义不重叠）；

- `RemoveDeviceAsync`（设备禁用/删除，L285–311）**不清零**统计：禁用再启用视作同一设备的连续观测历史。若产品语义需要「重置统计」，留给将来的管理端点，本轮不做；

- 该字典仅 RuntimeManager 与快照组装（阶段 3）读取，不暴露到 DeviceRuntime。

**验收**：断线→自动重连循环中，重复 3 次失败重连后 `_reconnectStats` 计数为 3（可通过日志或阶段 3 快照验证；阶段 1 先以调试日志验证）。

```csharp
    _runtime.LastError = TruncateError(ex.Message);   // ← 新增

```

1. **整轮异常 catch**（L310–317）：

```csharp
catch (Exception ex)
{
    _runtime.ConnectionState = DeviceConnectionState.Error;
    _runtime.LastError = TruncateError(ex.Message);   // ← 新增
    ...
}
```

1. **新增私有辅助方法**（放 DeviceWorker 尾部工具方法区，TryToNumber 附近）：

```csharp
/// <summary>失败原因截断（上限 500 字符），防止异常消息超长撑爆快照/日志。</summary>
private static string? TruncateError(string? message)
{
    if (string.IsNullOrWhiteSpace(message)) return message;
    return message.Length <= 500 ? message : message[..500];
}
```

**要点**：

- **轮次级全部失败分支**（L281–308 的 else，即 `anySuccess == false` 但无异常抛出的路径——驱动返回 null 被当作无效读）：该路径无异常对象可记，补充取「本轮 N 个到期变量全部读取失败」类聚合描述写入 LastError，与 L290–293 的既有 LogWarning 文案对齐。这是原方案遗漏的第三条失败路径（原方案只列了 L244–253 / L309–316 两处）；

- 成功分支（L274–280）**不**清空 LastError（D3-b）；

- 赋值为纯内存 string 写，无抛出路径，不影响采集循环。

**验收**：模拟 S7 断链（错误 IP 或停仿真）→ 快照/调试观察 LastError 非空且内容为驱动异常消息；恢复连接后 LastError 保留（D3-b）直到下次失败覆盖。
