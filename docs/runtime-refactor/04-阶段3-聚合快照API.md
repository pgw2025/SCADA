# 阶段 3：聚合快照 API（R3）

> 前置文档：`00-总览与方案核实报告.md`（P4/P5/P6 处理 + D4/D5/D6/D10 决策落地）
> 目标：提供 `GET /api/devices/{id}/runtime` 聚合快照端点 + RunState 置位端点，前端首帧一次拉取双状态与统计。
> 预置条件：阶段 1/2 已完成（快照依赖其新增字段与进程级统计）。
> 预计投入：1–2 天

## 设计总览

### 数据流

```
GET /api/devices/{id}/runtime
   │
   ▼
RuntimeController（WebApi，仅认证）
   │
   ▼
IRuntimeStatusProvider.TryGetRuntimeSnapshot（Application 接口，D5: 未注册返回 false → 404）
   │
   ▼
RuntimeStatusProviderAdapter（WebApi 适配层，转发 —— 沿用现状分层，Application 不反向依赖 Runtime）
   │
   ▼
RuntimeManager.BuildRuntimeSnapshot（组装）
   ├─ DeviceRuntimes.TryGetValue(id) → runtime 实例字段
   │    ConnectionState / RunState / HasAlarm / LastError / ConnectionStateChangedAt
   │    LastCommunicationTime / ConsecutiveFailureCount / AverageResponseTime
   │    SuccessCount / FailureCount / PollRoundCount / VariableCount
   ├─ _reconnectStats.TryGetValue(id) → ReconnectCount / LastReconnectAt（进程级，P1）
   └─ MapConnectionStateToStatus(runtime) → DeviceStatus（向后兼容 5 态）
```

### 线程安全声明（P6，写入代码注释与本文档）

快照组装**无锁读取**多个内存字段：.NET 保证单字段（枚举/int/double/引用/DateTime?）读写原子性，但**字段间一致性不保证**（可能读到 LastError 新值 + ConsecutiveFailureCount 旧值，误差窗口为一次采集轮次）。对可观测快照**可接受且是有意为之**——对 DeviceRuntime.Lock 加锁读取会与采集循环互相阻塞，明确禁止。后续维护者不得以「一致性」为由给快照加锁。

## 步骤 3.1 新增快照 DTO（Application 层）

**文件**：`Server/ScadaServer.Application/DTOs/DeviceRuntimeSnapshotDto.cs`（新建）

```csharp
using ScadaServer.Domain.Enums;

namespace ScadaServer.Application.DTOs;

/// <summary>
/// 设备运行时聚合快照：一次返回连接态 + 运行态 + 报警 + 通信统计。
/// 供前端进入设备详情页时初始化首帧；实时变化仍走 SignalR（变量值）与快照轮询（RunState/统计）。
/// <para>线程安全说明：字段间一致性不保证（无锁读取，误差窗口 ≤ 一个采集轮次），见方案 P6。</para>
/// </summary>
public class DeviceRuntimeSnapshotDto
{
    // ---- 身份 ----
    public int DeviceId { get; init; }
    public string DeviceKey { get; init; } = string.Empty;
    public string DeviceName { get; init; } = string.Empty;
    public bool IsEnabled { get; init; }

    // ---- 连接态维度（既有语义，向后兼容） ----
    /// <summary>对外设备状态（5 态，与 GET /api/devices 的 RuntimeStatus 同源同值）。</summary>
    public DeviceStatus Status { get; init; }
    public DeviceConnectionState ConnectionState { get; init; }
    /// <summary>本次连接周期内最近一次连接状态翻转时刻（UTC，可空）。</summary>
    public DateTime? ConnectionStateChangedAt { get; init; }

    // ---- 运行态维度（阶段 2 新增，与连接态正交） ----
    /// <summary>机器运行状态。注意与 Status/ConnectionState 的 Fault 语义区分（方案 P4）：
    /// RunState.Fault = 机器自身故障；Status.Fault = PLC 通信故障。</summary>
    public DeviceRunState RunState { get; init; }
    public DateTime? RunStateChangedAt { get; init; }
    /// <summary>是否存在未恢复报警（不论是否已确认 Ack）。</summary>
    public bool HasAlarm { get; init; }

    // ---- 通信统计 ----
    /// <summary>最近一次采集/连接失败原因（连接周期级，成功后保留至下次覆盖，D3-b）。</summary>
    public string? LastError { get; init; }
    public DateTime? LastCommunicationTime { get; init; }
    public int ConsecutiveFailureCount { get; init; }
    /// <summary>进程启动以来自动重连发起次数（进程级累计，方案 P1/D9-a）。</summary>
    public int ReconnectCount { get; init; }
    public DateTime? LastReconnectAt { get; init; }
    public double AverageResponseTimeMs { get; init; }
    public long SuccessCount { get; init; }
    public long FailureCount { get; init; }
    public long PollRoundCount { get; init; }

    // ---- 规模信息 ----
    /// <summary>设备启用变量数（不含禁用）。</summary>
    public int EnabledVariableCount { get; init; }
    /// <summary>设备变量总数。</summary>
    public int VariableCount { get; init; }

    // ---- 值概要（D4-1：本轮不含变量值；字段预留给 includeValues 扩展） ----
    // public IReadOnlyList<RuntimeVariableSnapshotDto>? Values { get; init; }
}

/// <summary>变量级快照（预留，D4-2 启用时补充，含 Key/Value/Quality/UpdateTime + 上限截断）。</summary>
public class RuntimeVariableSnapshotDto
{
    public string VariableKey { get; init; } = string.Empty;
    public object? Value { get; init; }
    public VariableQuality Quality { get; init; }
    public DateTime? UpdateTime { get; init; }
}
```

**要点**：
- DTO 放 Application 层（沿用 `IRuntimeStatusProvider` 的分层约定：接口与 DTO 在 Application，实现在 WebApi 适配，避免 Application → Runtime 反向依赖）；
- `Status` 与 `ConnectionState` 同时输出：前者供既有前端兼容（deviceStatus.ts 归一化），后者供新消费方精确显示；
- 值概要（Values）本轮不实现（D4-1），DTO 注释保留扩展位。

## 步骤 3.3 RuntimeManager 快照组装

**文件**：`Server/ScadaServer.Runtime/RuntimeManager.cs`

**任务**：实现 `IRuntimeManager` 上的组装方法（IRuntimeManager 接口同步增加签名，`Runtime/Interface/IRuntimeManager.cs`）：

```csharp
/// <inheritdoc/>
public bool TryGetRuntimeSnapshot(int deviceId, out DeviceRuntimeSnapshotDto? snapshot)
{
    if (!DeviceRuntimes.TryGetValue(deviceId, out var runtime))
    {
        snapshot = null;
        return false;
    }

    _reconnectStats.TryGetValue(deviceId, out var stats);

    snapshot = new DeviceRuntimeSnapshotDto
    {
        DeviceId = runtime.Device.Id,
        DeviceKey = runtime.Device.Key,
        DeviceName = runtime.Device.Name,
        IsEnabled = runtime.Device.IsEnabled,

        Status = MapConnectionStateToStatus(runtime),          // 复用既有映射，保证与列表接口同源同值
        ConnectionState = runtime.ConnectionState,
        ConnectionStateChangedAt = runtime.ConnectionStateChangedAt,

        RunState = runtime.RunState,
        RunStateChangedAt = runtime.StateChangedAt,
        HasAlarm = runtime.HasAlarm,

        LastError = runtime.LastError,
        LastCommunicationTime = runtime.LastCommunicationTime,
        ConsecutiveFailureCount = runtime.ConsecutiveFailureCount,
        ReconnectCount = stats?.Count ?? 0,                    // 进程级（P1/D9-a）
        LastReconnectAt = stats?.LastReconnectAt,
        AverageResponseTimeMs = runtime.AverageResponseTime,
        SuccessCount = runtime.SuccessCount,
        FailureCount = runtime.FailureCount,
        PollRoundCount = runtime.PollRoundCount,

        VariableCount = runtime.Variables.Count,
        EnabledVariableCount = runtime.Variables.Values.Count(v => v.IsEnabled)
    };
    return true;
}
```

**要点**：
- **单方法内完成组装，不建独立 SnapshotBuilder 类**：组装逻辑仅十余行、无复用方，独立类属过度设计（00 总览原则 1 的精神）；若 D4-2 将来启用 includeValues 再抽离；
- `EnabledVariableCount` 遍历在快照请求线程执行，变量数量级（单设备几十~几百）遍历成本微秒级，可接受；
- 注释中写明 P6 线程安全声明（无锁、容忍字段间微小不一致）。

```csharp
/// <summary>获取设备运行时聚合快照（连接态/运行态/报警/统计）。</summary>
[HttpGet("/api/devices/{id:int}/runtime")]
[Authorize]                        // 只读，登录即可（与管理端点一致）
public IActionResult GetRuntimeSnapshot(int id)
{
    if (_runtimeStatusProvider.TryGetRuntimeSnapshot(id, out var snapshot))
        return Ok(snapshot);

    // D5-a：未注册（禁用/初始化失败/重连窗口）→ 404。
    // 调用方判断设备存在性应使用 GET /api/devices。
    return NotFound(new { message = $"设备 {id} 不在运行中（可能已禁用或正在重连）。" });
}
```

**端点 2：RunState 置位（D2-A，写路径）**

```
PUT /api/devices/{id}/runtime/runstate        body: { "runState": "Maintenance" }
```

```csharp
/// <summary>置位设备运行状态（机器状态，人工置位）。持久化并即时更新运行时内存。</summary>
[HttpPut("/api/devices/{id:int}/runtime/runstate")]
[Authorize(Roles = "Admin")]         // 写操作：管理员（与设备写值端点同等级）
[AuditLog]                           // 操作审计（与设备写操作惯例一致）
public async Task<IActionResult> SetRunState(int id, [FromBody] SetRunStateRequest request)
{
    // 1) 枚举合法性：非法字符串 → 400
    if (!Enum.TryParse<DeviceRunState>(request.RunState, ignoreCase: true, out var runState)
        || !Enum.IsDefined(runState))
        return BadRequest(new { message = $"无效的运行状态：{request.RunState}" });

    // 2) 设备存在性：查 DB（设备可能不在运行时中——禁用设备也允许置位，重启后生效）
    //    ExecuteUpdate 返回影响行数 = 0 → 404
    var now = DateTime.UtcNow;
    var affected = await db.Devices
        .Where(d => d.Id == id)
        .ExecuteUpdateAsync(s => s
            .SetProperty(d => d.RunState, runState)
            .SetProperty(d => d.RunStateChangedAt, now));
    if (affected == 0)
        return NotFound(new { message = $"设备 {id} 不存在。" });

    // 3) 运行时内存即时生效（设备在册时）
    if (_runtimeManager.DeviceRuntimes.TryGetValue(id, out var runtime))
        runtime.SetRunState(runState);

    // 4) 不推送 SignalR（D10-a）：RunState 变化由前端轮询快照感知
    return Ok(new { deviceId = id, runState = runState.ToString(), changedAt = now });
}
```

> 实施细节：
> - `SetRunStateRequest` 仅一个 `RunState` string 字段（前端传枚举名字符串，与 SignalR/REST 既有「字符串枚举」序列化约定一致，见 deviceStatus.ts L9）；
> - DbContext 经控制器构造注入（WebApi 控制器本身 Scoped，无需 scope factory）；
> - **禁用设备置位**是刻意支持的能力：维护场景常发生在停机设备上，置位后待设备启用时 RestoreRunState 自动生效；
> - AuditLog 过滤器沿用项目既有 `[AuditLog]` 机制（若 RunState 置位需要记录操作人，与设备写值审计同源）。

**要点**：
- 路由风格 `/api/devices/{id}/runtime` 保持与既有 REST 资源路径一致（设备子资源）；
- 不提供 DELETE/批量端点（YAGNI，需要时再加）。

## 步骤 3.7 API 冒烟

登录后依次验证（curl / Swagger / 前端临时脚本均可）：

1. **正常设备**：`GET /api/devices/{id}/runtime` → 200，字段齐全：Status=Online、ConnectionState=Connected、RunState=置位值、HasAlarm、统计数值合理；
2. **一致性抽查**：同设备 `GET /api/devices` 的 `RuntimeStatus` 与快照 `Status` **同值**（证明同源映射未分叉）；
3. **断线设备**：错误 IP 的 S7 设备 → 快照 Status=Fault、ConnectionState=Error、LastError 非空、ConsecutiveFailureCount>0、ReconnectCount 随重连循环递增（P1 验证闭环）；
4. **未注册设备**：不存在的 id / 已禁用 id → 404（D5-a）；
5. **置位**：`PUT .../runstate` body `{"runState":"Maintenance"}` → 200 → 再 GET 快照 RunState=Maintenance；非 Admin → 403；非法枚举 → 400；
6. **响应体积**：单设备快照 JSON < 2KB（无 values，D4-1 生效）。
