# 01-落地方案

> 行号均为写稿时（2026-09-12）代码核对值，实施时以符号搜索为准。

## 1. 背景与目标

弹窗画面（`ScadaPages` 表中 `Platform='Popup'` 的记录）在设计页左侧面板目前为平铺列表。桌面端/移动端画面已具备完整的文件夹能力（`docs/scada-page-folder/`），本方案将该能力扩展到弹窗分组：支持建夹、嵌套、拖拽排序、重命名、reparent/cascade 删除，交互与另外两端完全一致。

**目标边界**：文件夹是纯设计态组织手段，不改变弹窗的运行态行为、不做新表、不做数据迁移。

## 2. 现状：弹窗与文件夹互斥的拦截点

当前代码从存储到 UI 共有多处显式拒绝 Popup 参与文件夹，是本次要放行的全部"障碍"：

### 2.1 后端（3 处核心拦截）

| # | 位置 | 现状行为 |
|---|---|---|
| B1 | `Server/ScadaServer.Application/Services/ScadaPageFolderAppService.cs` L305-306 `NormalizePlatform` | 非 `Mobile` 一律归一化为 `Desktop`。传 `'Popup'` 会被静默吞成 `Desktop` |
| B2 | 同文件 L308-314 `ValidatePlatform` | 只允许 Desktop/Mobile，Popup 抛 `ArgumentException("Popup 端不支持画面文件夹…")` |
| B3 | `Server/ScadaServer.Application/Services/ScadaPageAppService.cs` L209-213 `ResolveFolderIdAsync` | `platform == "Popup"` 时直接 throw `"Popup 弹窗画面不能放入文件夹"`；该方法被 `SavePageAsync`（L72）与 `UpdateAsync`（L106）调用，是弹窗 `FolderId` 落库的必经之路 |

### 2.2 前端（类型联合 + 映射）

| # | 位置 | 现状行为 |
|---|---|---|
| F1 | `Client/src/api/scadaApi.ts` L308 `fromFolderDto` | `platform: (d.platform === 'Mobile' ? 'Mobile' : 'Desktop')` —— **放行后端后，Popup 文件夹经此函数会被映射成 Desktop** |
| F2 | `Client/src/types.ts` L1004 `ScadaPageFolder.platform` | 类型仅 `'Desktop' \| 'Mobile'`；L987 `ScadaPage.folderId` 注释声明"Popup 画面恒不设" |
| F3 | `Client/src/store/scadaStore.ts` L246 `buildFolderTree` | 参数类型仅 `'Desktop' \| 'Mobile'`（L65 `popupPages` computed 平铺过滤 `platform === 'Popup'`） |
| F4 | `Client/src/services/scadaService.ts` L281 `persistFolderReorder` | platform 参数类型仅 `'Desktop' \| 'Mobile'` |
| F5 | `Client/src/components/ScadaPageTree.vue` L126 | `platform` prop 类型仅 `'Desktop' \| 'Mobile'`；且恒渲染「设为首页」按钮（L93） |
| F6 | `Client/src/components/ScadaTopologyView.vue` L1282/L1378/L1402/L1236/L1113 | `applyDrop` / `handleCreateSubfolder` / `handleCreateRootFolder` / `reindexAndPersistSegment` / `setHomePage` 内的 platform 类型均为 `'Desktop' \| 'Mobile'` |
| F7 | `Client/src/components/ScadaTopologyView.vue` L1758-1808 | 弹窗分组为手写 `v-for="page in popupPages"` 平铺列表，未接 `ScadaPageTree` |

### 2.3 存储层（复核结论：无需任何改动）

- `ScadaPageFolders.Platform` 为 varchar(16)、默认 `'Desktop'`，**无 CHECK 约束**，直接容纳 `'Popup'`。
- 现有索引仅两个**普通**索引：`ix_scadapagefolders_parent`、`ix_scadapagefolders_project_platform`。同层级同名防重完全依赖应用层 `EnsureNameUniqueAsync`（`ProjectId + Platform + ParentFolderId + Name` 四元组，EF 将 `== null` 翻译为 `IS NULL`），对 Popup 语义正确——**不需要迁移补唯一索引**（注：MySQL 下 `NULL != NULL`，根级同名靠数据库索引本就防不住，应用层校验是唯一防线）。
- `ScadaProjectAppService.GetTreeAsync` 已把全部文件夹放入 `FullDto.Folders`（且已在页面循环外只加一次，无重复问题），Popup 文件夹放行后自动入树。
- 现有弹窗 `FolderId` 全 NULL，放行后自然落弹窗根级，**无需存量数据回填**。

## 3. 总体方案

**复用现有 `ScadaPageFolder` 体系，把 `'Popup'` 变成 platform 的第三个合法值；前端弹窗分组改用 `ScadaPageTree` 组件。**

- 不新建实体/表/AppService/Controller/DTO/迁移。
- 嵌套、拖拽、排序、删除、防重、循环引用检测等逻辑全部继承现有实现（`ReorderAsync`、`DeleteReparentAsync`、`DeleteCascadeAsync`、`IsSelfOrDescendantAsync` 等均按 platform 参数化，放行即用）。
- 弹窗与桌面/移动端的差异只有一点：**无「设为首页」**。通过 `ScadaPageTree` 按平台隐藏 Home 按钮实现。

## 4. 改动清单

### P0 —— 不做必出 bug

#### 4.1 后端放行（2 文件 3 处）

**① `ScadaPageFolderAppService.NormalizePlatform`（L305）改三分支**

```csharp
// 改前：非 Mobile 一律 Desktop，'Popup' 会被静默吞掉，导致后续 ReorderAsync 校验 400
private static string NormalizePlatform(string? platform)
    => string.Equals(platform?.Trim(), "Mobile", StringComparison.OrdinalIgnoreCase) ? "Mobile" : "Desktop";
```

改为：`Popup` → `"Popup"`、`Mobile` → `"Mobile"`、其余回退 `"Desktop"`。

**② `ScadaPageFolderAppService.ValidatePlatform`（L308）放行 Popup**

把 `"Popup"` 纳入合法值集合；同步修改 L313 报错文案（如"仅 Desktop/Mobile/Popup 可建文件夹"，理论上放行后不会再触发，文案仅兜底）。

**③ `ScadaPageAppService.ResolveFolderIdAsync`（L209）删 Popup 拦截**

删除 L212-213 的 `if (platform == "Popup") throw …`。删除后 Popup 页面走与 Desktop/Mobile 完全相同的校验链（父文件夹存在、同工程、同端），L207 的注释同步更新（去掉"Popup 端恒为 NULL"）。

> ①② 改完后，`CreateAsync` / `UpdateAsync` / `ReorderAsync` 整条链路自动适用 Popup；③ 改完后，弹窗新增/修改时 `folderId` 可落库，`persistPageMove`（夹间移动）后端校验通过。

#### 4.2 前端类型与映射（P0 核心：F1）

**④ `scadaApi.ts` `fromFolderDto`（L308）改三分支** —— 初版方案漏掉的唯一真 bug 点：

```ts
// 改前：Popup 文件夹会被映射成 Desktop，刷新后出现在桌面端树
platform: (d.platform === 'Mobile' ? 'Mobile' : 'Desktop'),
// 改后（同文件 L291 fromPageDto 已有正确写法，照抄）：
platform: d.platform === 'Mobile' || d.platform === 'Popup' ? (d.platform as 'Mobile' | 'Popup') : 'Desktop',
```

**⑤ `'Desktop' | 'Mobile'` 类型联合扩展（加 `| 'Popup'`）**，共 6 处：

## 6. 与既有功能的继承关系（零改动项，复核通过）

- **跨端拖拽拦截**：`applyDrop('Popup')` 命中 `item.platform !== platform` → toast；`ScadaPageTree` 内部 `canDropHere` 同理——弹窗不能拖到桌面/移动端，反之亦然。
- **循环引用检测**：后端 `IsSelfOrDescendantAsync`、前端 `isFolderDescendant` 均 platform 无关。
- **serverId 双轨与就绪时序**：`ensureFolderSaved` / `ensureParentReady` / `buildFolderIdMap` / `persistPageMove` / `toFolderDto`（`srv-<id>` 正则兜底）全部 platform 无关或参数化。
- **同名防重**：`EnsureNameUniqueAsync` 四元组含 Platform，Popup 与桌面端同名文件夹互不冲突。
- **reparent/cascade 删除**：`DeleteReparentAsync` / `DeleteCascadeAsync` 按 folder 自身 platform 处理；cascade 守卫（L203）按工程全量页面计数，"删到最后一个弹窗"被允许（与画面"至少留一页"语义一致，工程级而非端级）。
- **删除后前端编排**：`handleDeleteFolder`（L1422-1445）取 `folder.platform`，先 reparent 落库再 reorder 的时序逻辑原样适用。
