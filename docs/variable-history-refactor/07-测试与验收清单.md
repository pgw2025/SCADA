## 2. 全局回归用例（功能）

### 2.1 写入链路
- [ ] 轮询设备（Modbus 等）正常采集 → Influx 未配置时写 MySQL、配置后写 Influx（stats 确认）
- [ ] MQTT 订阅变量变化 → 同上双后端验证
- [ ] StoreMode：None 不记录；Change 死区内不记录；Cycle 按周期记录（三种模式各一条变量验证）
- [ ] 质量降级（断开设备）→ 不写历史、实时快照仍更新（现状保持）
- [ ] NaN/Infinity 采样点分流 MySQL（stats `invalidValuePoints` 递增），同批正常点仍落 Influx
- [ ] 服务正常停止 → 排空路径无丢数（对比停止前后 stats 入队/落库计数）

### 2.2 查询链路
- [ ] 单变量查询：时间范围/limit/聚合（5 种 fn）在 Influx 与 MySQL 两个后端下行为一致（对拍同一时段数据）
- [ ] 批量查询：8 变量上限、多变量互不混入
- [ ] 跨设备同名变量：带 deviceKey 查询只返回目标设备（新索引下行为不变）
- [ ] 导出：50000 行 CSV 结构正确（BOM、表头、转义、NaN 空值）；非管理员被拒
- [ ] 迁移中断状态下查询页提示条出现/消失

### 2.3 运维链路
- [ ] 迁移：全量 → 完成；中断（kill/停 Influx/取消）→ Interrupted → 续传 → Completed，最终 Influx 与 MySQL 总数对账一致
- [ ] 清理：clear_history 计划任务三种路径（仅 Influx / 仅 MySQL / 双清）+ 保留期自动清理 + 迁移门禁
- [ ] 备份：Influx 按月分片导出 + MySQL 业务表 JSON；恢复演练（备份文件结构抽查）一次

### 2.4 前端
- [ ] 历史查询页：查询/空态/错误态三分；分页跳转；统计条口径
- [ ] 运行画面：趋势回填 + 实时衔接；库管理页：生效后端徽标、迁移进度条/取消
- [ ] 键盘快捷键等既有功能不受影响（本次未触碰，冒烟即可）

## 3. 性能基准（发布门禁）

| 项 | 方法 | 预期 |
|---|---|---|
| 写入吞吐 | 10 变量 × 1Hz × 30 分钟，观察 stats 与队列深度 | 队列深度稳定低位、0 丢弃 |
| 查询延迟 | 30 天范围 + 1 分钟聚合（Influx / MySQL 各测） | P95 < 2s（依硬件记录基线） |
| 导出内存 | 单变量 50000 行导出，记录进程峰值 | 峰值 < 300 MB（超出则触发流式 backlog） |
| 迁移吞吐 | 百万级测试库全量迁移 | 记录速率基线，验证 ETA 估算合理性 |
| 清理影响 | 保留期清理运行时同步写入 | 无写入失败/超长锁等待 |

## 4. 发布顺序与回滚预案

**发布顺序**：
1. 后端（含 EF 迁移——索引迁移放低峰执行）；
2. 前端（阶段 3/4/5 的 UI 依赖后端新端点，先后后前）；
3. 发布后冒烟：status/stats/migrate/status 三个新端点 + 一次查询。

**数据库迁移注意**：
- `DatabaseConfig` 新增 3 个可空字段 + `VariableHistories` 2 个新索引；Up 前备份 `DatabaseConfigs` 与确认索引执行方式（InnoDB INPLACE）；
- 所有新字段默认 NULL，Down 可逆。

**回滚**：
- 行为类（阶段 1/2/3/5 大部分）：回滚代码即恢复旧行为，无数据残留（补偿队列内存态）；
- 数据类（阶段 4 断点字段）：回滚后迁移回到"从 0 全量"旧语义，字段留存无害；
- 索引：Down 删除，或保留（无害）。

## 6. 建议的观察期

发布后 1~2 周观察：
- `history/stats` 的丢弃计数应保持 0 或极低（非 0 需分析容量）；
- MySQL 清理首批执行日志确认删除量与预期一致；
- Influx 未配置部署（纯 MySQL 模式）的实例无异常日志。
