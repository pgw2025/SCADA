# 06-阶段5-趋势回填与体验优化

> 解决问题：**P2-8**（趋势图无历史回填）、**P3-10~14**（查询失败静默、-30d 默认值、质量缺口、CSV 转义、备份分片）
> 前置依赖：阶段 3（趋势回填建议在 limit 参数化后实施，弱依赖）
> 粗估工作量：4~5 人日

---

## 1. 目标

1. 运行时趋势图打开/切换画面时从后端拉取历史数据回填，刷新后曲线不再"从零开始"。
2. 查询失败与"无数据"在前端可区分。
3. Influx 查询隐式 -30d 行为显式化。
4. CSV 导出转义完整；备份 Influx 导出分片化并在缺失时告警。
5. 质量降级点写入策略：形成明确决策（默认保持现状）。

## 2. 步骤明细

### 步骤 5.1 趋势图历史回填（核心）

**任务**：`TrendChartWidget` 初始化时从后端拉取窗口内历史数据填充 `trendHistory` 缓冲。

**涉及文件**：
- `Client/src/components/widgets/TrendChartWidget.vue`
- `Client/src/utils/trendHistory.ts`（可能需要暴露"批量预填充"方法或调大缓冲上限）
- 复用 `Client/src/api/historyApi.ts` 的 `fetchHistoryBatch`（POST /api/scada/history/batch，支持 8 变量）

**设计**：
- **触发时机**：控件挂载（`onMounted`）且运行时模式、且绑定了变量时；绑定变量集合变化时重新回填。
- **窗口与聚合**：
  - 回填窗口 `W`：**已核实当前控件属性无时间范围/窗口配置项**（`TrendChartWidget` 的 series 配置仅含变量绑定相关字段），故统一默认 **最近 60 分钟**；
  - 可选增强（列 backlog）：控件属性面板增加 `timeWindow`（分钟）配置，回填窗口跟随；
  - 聚合窗口 `aggregateWindowMs = W / 120`（缓冲区 `MAX_POINTS = 120`，已核实常量位置 `trendHistory.ts` L7，回填后与实时点自然衔接）；
  - `aggregateFn = "mean"`（趋势回看场景均值最稳）。
- **竞态控制**：`AbortController`；变量集合变化或组件卸载时 abort 旧请求；回填数据按 series 逐个 push 进缓冲（保持时间序，早于当前缓冲首点的插入头部）。
- **降级策略**：回填失败（网络/后端不可用）→ `console.warn` + 保持现状（从零开始），**不得**阻塞画面加载或弹错误框（运行画面优先稳态）。
- **性能约束**：同画面多个趋势控件 → 每控件一次 batch 请求（≤8 变量），不做全局合并（画面控件数通常个位数，可接受；若实测有问题再合并，backlog）。
- **trendHistory 适配**：现有缓冲上限若硬编码 120，回填点数按 120 设计（W/120 聚合已保证），无需扩容（已核实 `MAX_POINTS = 120` 常量在 `trendHistory.ts` L7，无需改动）。

**验收**：刷新运行画面 → 趋势图立刻有过去 1 小时曲线 → 实时点无缝追加；快速切换画面无错乱（竞态测试）。

### 步骤 5.2 查询失败提示

**涉及文件**：`Client/src/components/HistoricalQueryView.vue`（`executeHistoryQuery` 的 catch）

**设计**：
- catch 中区分：网络层失败（TypeError/AbortError）、HTTP 非 2xx（读 `response` 错误信息）；
- 失败 → `ElMessage.error("历史查询失败：{原因}")` + 图表区显示**错误态**（红字 + 重试按钮），与现有"未查询到任何时序"空态视觉区分；
- 成功但 0 行 → 保持现有空态文案。
- 同时保留现有操作日志写入。

### 步骤 5.3 Influx 默认 -30d 显式化

**涉及文件**：
- `Server/ScadaServer.Infrastructure/Influx/InfluxStore.cs`（`BuildQuery` L777-780：`start` 为空 → `"-30d"`）
- `Server/ScadaServer.WebApi/Controllers/HistoryController.cs`：XML 注释补充契约

**设计**：`QueryLatestAsync` 收到 `start == null` 时，在方法入口显式计算 `start = (end ?? DateTime.UtcNow).AddDays(-30)` 再传入 `BuildQuery`（行为不变，隐式变显式，可测试、可文档化）；`BuildQuery` 的 `-30d` 分支保留作兜底。
- Controller 注释与前端 API 文档（`historyApi.ts` JSDoc）标注："未传 start 时默认查询最近 30 天"。
- 前端"所有数据"现有 `2000-01-01` 显式起点**保持不变**（它是刻意的全量语义）。

### 步骤 5.4 质量降级点写入策略（决策项，默认不实施）

**现状**：`VariableValueProcessor` 质量降级（Bad/CommunicationError）不写历史 → 中断期曲线缺口，`Quality` 字段几乎恒为 Good。

**决策记录**：**默认保持现状**。理由：
- Influx field 不支持 NaN，写入 Bad 点只能带上次值，曲线会呈现"假平线"，比缺口更易误导；
- 写入需同时改动采集判定、Influx field、前端趋势断线逻辑三处，收益/成本比低；
- 缺口 + 前端"中位间隔 ×2"断线推断已可表达"中断"。

**可选增强方案**（仅当用户明确要求时实施，列 backlog）：中断期间写 `Quality=Bad`、`Value=上次值` 的点，趋势图对 Bad 点绘制虚线；`QueryLatestAsync` 支持按 quality 过滤。

### 步骤 5.5 CSV 导出转义完善

**涉及文件**：`Server/ScadaServer.Application/Services/HistoryAppService.cs`（`ExportCsvAsync` L103-115、`EscapeCsv` L171-176）

**设计**：
- 所有字符串列（时间以外的 DeviceKey/VariableKey/VariableName/Quality）统一走强化的 `EscapeCsv`：
  ```
  EscapeCsv(v) = '"' + v.Replace("\"", "\"\"").Replace("\r\n", "\n").Replace("\r", "\n").Replace("\n", "\\n") + '"'
  ```
  （换行归一为 `\n` 字面两字符，保证单行结构；若下游 Excel 需要真实换行，可改为保留真实换行在引号内——CSV 规范允许，但当前消费方以脚本/Excel 为主，归一更安全，**采用归一**并在文件头注释说明）。
- `Value` 列：`double.IsNaN(v) || double.IsInfinity(v)` → 输出空串（避免 Excel 解析错误）。
- 时间列已是 `O` 格式 + 引号包裹，保持。

### 步骤 5.6 备份 Influx 分片导出与缺失告警

**涉及文件**：
- `Server/ScadaServer.Infrastructure/Influx/InfluxStore.cs`：`ExportAllAsync` 改造（或新增 `ExportRangeAsync(start, end, path)` 供组合）
- `Server/ScadaServer.Runtime/Tasks/BackupTaskExecutor.cs`：调用侧适配

**设计**：
- **分片策略**：按自然月分片（`range(start: 月初, stop: 次月初)`）。起点确定：
  1. 先查数据最早时间：`from(bucket) |> range(start: 0) |> first()`（轻量）；
  2. 无数据 → 写空文件（现状行为）；
  3. 从最早数据所在月循环到当前月，每片 `QueryRawAsync` → **`File.AppendAllTextAsync` 追加**（每片一次性拉取但单片量已受限；若单月仍过大可降级为按天，backlog 参数化）。
- **失败语义**：单片失败重试 1 次，仍失败 → 该次备份标记 `influxExported=false` 并附失败月份区间；不中断其他片。
- **缺失告警**：`InfluxExported=false` 时备份结果状态置 `PartialFailure`（或现有等价状态）+ 消息注明"InfluxDB 时序数据未包含在本备份中"；同时确认 MySQL 历史表是否应纳入备份清单（当前在排除清单）——**决策**：不纳入（表过大且 Influx 是主存储），告警文案引导用户检查 Influx 备份配置。
- 导出行数统计沿用换行计数（注释已说明非精确值），分片后按片累计。

## 4. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 回填请求拖慢画面首屏 | 回填异步、失败静默；聚合窗口保证点数 ≤120；必要时为回填加 loading 态但不阻塞渲染 |
| 回填与实时点重叠/乱序 | 按 series 插入头部 + 时间序断言；竞态 abort |
| 分片备份循环长 | 按月粒度 + 单片失败不扩散；备份任务本为计划低峰执行 |
| 回滚 | 前端改动为主；后端 CSV/备份为局部行为变更，回滚代码即恢复 |
