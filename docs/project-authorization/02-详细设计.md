# 02 · 详细设计

> 路径约定：`Server/…` 指 `d:\CSharp\SCADA\Server`，`Client/…` 指 `d:\CSharp\SCADA\Client`。

## 1. 数据模型

### 1.1 ER 关系

```
ScadaProjects (工程)                SystemUsers (用户)
      │ 1                                   │ 1
      │                                     │
      └──────── N : N ───────────────────────┘
                     │
        ScadaProjectAuthorizations (授权中间表)
        ├── ProjectId  int   FK → ScadaProjects.Id  (Cascade)
        ├── UserId     int   FK → SystemUsers.Id    (Cascade)
        ├── GrantedAt  datetime (UTC)
        └── 主键 = (ProjectId, UserId) 复合
```

### 1.2 实体定义

新增 `Server/ScadaServer.Domain/Entities/ScadaProjectAuthorization.cs`：

```csharp
/// <summary>组态工程授权实体：记录「某工程授权给某用户」的多对多关系。</summary>
[Table("ScadaProjectAuthorizations")]
public class ScadaProjectAuthorization
{
    /// <summary>工程 Id（复合主键之一，FK → ScadaProjects）。</summary>
    public int ProjectId { get; set; }

    /// <summary>被授权用户 Id（复合主键之一，FK → SystemUsers）。</summary>
    public int UserId { get; set; }

    /// <summary>授权时间（UTC）。</summary>
    public DateTime GrantedAt { get; set; }
}
```

设计要点：

- **复合主键**（无自增 Id）：天然防止重复授权，`(ProjectId, UserId)` 重复插入直接违反主键约束；
- **双 FK 均 Cascade**：删除工程（现有 `DeleteAsync` 走事务级联清理页面/组件）或删除用户时，授权记录由数据库自动清理，无孤儿数据；
- **不设导航属性**：工程与用户实体不感知授权（保持 `ScadaProject`/`SystemUser` 零侵入），查询一律经仓储按需联查；
- **不设 GrantedBy（授权人）**：授权人信息由操作审计日志（`SystemLogs`，Category=Operation）记录，避免字段冗余。

### 1.3 EF 配置（ScadaDbContext）

```csharp
// DbSet（OnModelCreating 中同步显式声明表名）
public DbSet<ScadaProjectAuthorization> ScadaProjectAuthorizations => Set<ScadaProjectAuthorization>();

// OnModelCreating 配置（遵循现有 DbVersion/索引命名规范 ix_ 前缀）：
modelBuilder.Entity<ScadaProjectAuthorization>(b =>
{
    b.ToTable("ScadaProjectAuthorizations");
    b.HasKey(x => new { x.ProjectId, x.UserId });                    // 复合主键
    b.HasOne<ScadaProject>()                                        // 工程侧 FK
        .WithMany()
        .HasForeignKey(x => x.ProjectId)
        .OnDelete(DeleteBehavior.Cascade);
    b.HasOne<SystemUser>()                                          // 用户侧 FK
        .WithMany()
        .HasForeignKey(x => x.UserId)
        .OnDelete(DeleteBehavior.Cascade);
    b.HasIndex(x => x.UserId)                                       // 反查「用户被授权了哪些工程」
        .HasDatabaseName("ix_scadaprojectauthorizations_userid");
});
```

> 索引说明：`(ProjectId, UserId)` 即主键，天然支持「查工程的授权用户」（前缀匹配）；`UserId` 单列索引支撑列表过滤的主查询 `WHERE UserId = @uid`。

## 2. 仓储层设计

### 2.1 接口（追加到 `IEntityRepositories.cs`）

```csharp
/// <summary>
/// 组态工程授权仓储：管理 ScadaProjectAuthorizations 中间表。
/// 复合主键实体，不继承 IRepository&lt;TEntity, TKey&gt;（无单列主键）。
/// </summary>
public interface IScadaProjectAuthorizationRepository
{
    /// <summary>查询用户被授权的全部工程 Id 集合（主数据源：UserId 单列索引）。</summary>
    Task<List<int>> GetProjectIdsByUserIdAsync(int userId);

    /// <summary>判断用户是否被授权访问指定工程。</summary>
    Task<bool> IsAuthorizedAsync(int projectId, int userId);

    /// <summary>查询工程当前授权记录（含授权时间，不含用户名，用户名由 AppService 联查补全）。</summary>
    Task<List<ScadaProjectAuthorization>> GetByProjectIdAsync(int projectId);

    /// <summary>全量替换工程的授权用户集合（调用方负责包在事务中）：先删后插，Admin 角色用户由调用方先行剔除。</summary>
    Task ReplaceForProjectAsync(int projectId, IEnumerable<int> userIds);
}
```

### 2.2 实现（`ScadaServer.Infrastructure/Repositories/` 新文件）

`ScadaProjectAuthorizationRepository` 直接注入 `ScadaDbContext`（**不继承 RepositoryBase**）：

- `GetProjectIdsByUserIdAsync`：`WHERE UserId == userId` → `Select(ProjectId)`；
- `IsAuthorizedAsync`：`AnyAsync(x => x.ProjectId == projectId && x.UserId == userId)`；
- `GetByProjectIdAsync`：`WHERE ProjectId == projectId`；
- `ReplaceForProjectAsync`：`RemoveRange(查旧)` + `AddRange(新列表，GrantedAt=UtcNow)`；**不自带 SaveChanges**，由 `_uow.ExecuteInTransactionAsync` 统一提交（与现有 `DeleteAsync` 事务模式一致）。

DI 注册（`Database.Extensions.cs`，与其他仓储同处）：`AddScoped<IScadaProjectAuthorizationRepository, ScadaProjectAuthorizationRepository>()`。

## 3. 当前用户服务（ICurrentUser）

### 3.1 接口（`ScadaServer.Application/Interfaces/ICurrentUser.cs` 新文件）

```csharp
/// <summary>当前请求用户抽象：从 JWT claims 解析。后台任务/测试环境下无 HttpContext，返回默认值。</summary>
public interface ICurrentUser
{
    /// <summary>用户 Id（claim "id"），未登录/解析失败为 0。</summary>
    int UserId { get; }

    /// <summary>用户名（claim "username"，回退 ClaimTypes.Name），可能为 null。</summary>
    string? Username { get; }

    /// <summary>是否 Admin 角色（claim "role" == SystemRoles.Admin）。</summary>
    bool IsAdmin { get; }
}
```

### 3.2 实现（`ScadaServer.WebApi/Services/CurrentUser.cs` 新文件）

- 构造注入 `IHttpContextAccessor`（WebApi 已注册该服务，审计服务在用）；
- 解析顺序：`UserId` ← `claim "id"`（`int.TryParse` 失败置 0）；`IsAdmin` ← `claim "role"` 或 `ClaimTypes.Role` 等于 `SystemRoles.Admin`；`Username` ← `claim "username"` 回退 `ClaimTypes.Name`；
- **无 HttpContext / 未登录**：`UserId=0`、`IsAdmin=false`、`Username=null`（防御式，见 01 文档 P3-2）。

> 分层依据（D8）：Application 层不引用 ASP.NET Core 类型（项目既有惯例，参见 `HmiImageAppService` 的工厂注入注释）。接口在 Application，实现与注册在 WebApi 的 `Application.Extensions.cs`：`services.AddScoped<ICurrentUser, CurrentUser>()`。

## 4. 应用服务层设计（ScadaProjectAppService）

### 4.1 新增依赖注入

构造函数追加：`IScadaProjectAuthorizationRepository _authRepository`、`ICurrentUser _currentUser`、`ISystemUserRepository _userRepository`（联查用户名、保存时校验与剔除 Admin）。

### 4.2 私有授权判定（核心谓词）

```csharp
/// <summary>当前用户是否可访问指定工程：Admin 恒放行；否则查授权表。</summary>
private Task<bool> CanAccessAsync(int projectId)
    => _currentUser.IsAdmin
        ? Task.FromResult(true)
        : _authRepository.IsAuthorizedAsync(projectId, _currentUser.UserId);
```

### 4.3 既有方法改造

| 方法 | 改造 |
|---|---|
| `GetListAsync()` | `IsAdmin` → 维持现状返回全部；非 Admin → `GetProjectIdsByUserIdAsync(UserId)`，**空集合短路返回 `[]`**，否则 `GetListAsync(p => ids.Contains(p.Id))`（P3-3） |
| `GetByIdAsync(id)` | 查到实体后追加 `if (!await CanAccessAsync(id)) return null;` → Controller 落 404（D3） |
| `GetTreeAsync(id)` | 同上：工程存在但未授权 → 返回 `null`（404 语义）。`ExportAsync` 内部复用 `GetTreeAsync`，自动被覆盖 |
| `GetByIdAsync` 的调用方 | `GetFullTree`/`GetById` Controller 无需改代码（null → 404 已是现状分支） |

### 4.4 新增授权读写方法

```csharp
/// <summary>获取工程已授权用户列表（联查用户名）。工程不存在返回 null。</summary>
Task<List<ScadaProjectAuthorizedUserDto>?> GetAuthorizedUsersAsync(int projectId);

/// <summary>全量覆盖工程授权。返回 false=工程不存在；userIds 含不存在用户抛 ArgumentException。</summary>
Task<bool> SaveAuthorizationsAsync(int projectId, List<int> userIds);
```

`GetAuthorizedUsersAsync` 逻辑：
1. 工程不存在 → `null`（Controller → 404）；
2. `GetByProjectIdAsync` 取授权记录；
3. 批量联查 `SystemUsers`（`GetListAsync(u => userIds.Contains(u.Id))`）补全 `Username/Role/Status`；
4. 已删除用户的授权记录由 FK Cascade 保证不残留，无需防御。

`SaveAuthorizationsAsync` 逻辑（`_uow.ExecuteInTransactionAsync` 包裹）：
1. 工程不存在 → 返回 `false`（Controller → 404）；
2. 过滤入参：去重 + **剔除 Admin 角色用户**（D2，双保险之一）；
3. userIds 中存在不存在的用户 → 抛 `ArgumentException`（Controller → 400，与 Import 错误处理风格一致）；
4. `_authRepository.ReplaceForProjectAsync(projectId, 最终集合)` → 事务提交。

## 5. API 契约

### 5.1 新增端点（`ScadaProjectController`）

| 方法 | 路由 | 授权 | 请求 | 成功响应 | 错误 |
|---|---|---|---|---|---|
| GET | `/api/ScadaProject/{projectId}/authorizations` | `RequireAdmin` | — | `200 [{ userId, username, role, status, grantedAt }]` | `404` 工程不存在 |
| PUT | `/api/ScadaProject/{projectId}/authorizations` | `RequireAdmin` | `{ "userIds": [1,2,3] }` | `204` | `404` 工程不存在；`400` 含无效用户 |

两处端点均写操作审计（复用 `AuditAsync`，模块=「组态工程」）：

- PUT 描述需含**变更明细**：新增授权谁、取消谁（前端提交前快照对比，或后端 diff 后描述）——执行计划采用**后端 diff**（保存前查旧集合，生成 `授权 +alice -bob` 式描述），前端无需传额外信息。

### 5.2 端点权限矩阵（本方案最终态）

| 端点 | Admin | Operator/Viewer（已授权） | Operator/Viewer（未授权） | 改动 |
|---|---|---|---|---|
| `GET /api/ScadaProject` | 200 全部 | 200 仅授权 | 200 空列表 | 服务层过滤 |
| `GET /api/ScadaProject/{id}` | 200 | 200 | **404** | 服务层校验 |
| `GET /api/ScadaProject/{id}/full` | 200 | 200 | **404** | 服务层校验 |
| `GET /api/ScadaProject/{id}/export` | 200 | **401/403** | **401/403** | +`RequireAdmin` |
| `GET/POST/PUT/DELETE 工程写操作` | 200 | 401/403 | 401/403 | 现状已 `RequireAdmin` |
| `GET /api/ScadaProject/{id}/authorizations` | 200 | 401/403 | 401/403 | 新增 |
| `PUT /api/ScadaProject/{id}/authorizations` | 204 | 401/403 | 401/403 | 新增 |
| `GET /api/ScadaPage`、`GET /api/ScadaPage/{id}` | 200 | **401/403** | 401/403 | +`RequireAdmin`（P1-1） |
| `GET /api/ScadaPage/{id}/export` | 200 | **401/403** | 401/403 | +`RequireAdmin`（P1-1） |
| `GET /api/HmiComponent`、`GET /api/HmiComponent/{id}` | 200 | **401/403** | 401/403 | +`RequireAdmin`（P1-1） |
| `POST /api/ScadaPage/import`、`POST /api/ScadaProject/import` | 200 | 401/403 | 401/403 | 现状已 `RequireAdmin` |

> 401/403 的区分由 JWT 中间件与授权策略自动产生（无 token → 401；有 token 但角色不符 → 403），无需代码干预。

## 6. 前端设计

### 6.1 API 封装（`Client/src/api/scadaApi.ts` 追加）

```ts
/** 与后端 ScadaProjectAuthorizedUserDto 对齐（camelCase 线格式） */
export interface ProjectAuthorizedUserDto {
  userId: number; username: string; role: string; status: string; grantedAt: string;
}

export const loadProjectAuthorizations = async (projectId: number): Promise<ProjectAuthorizedUserDto[]> =>
  (await http.get(`${API()}/ScadaProject/${projectId}/authorizations`)).data || [];

export const saveProjectAuthorizations = async (projectId: number, userIds: number[]): Promise<void> =>
  void (await http.put(`${API()}/ScadaProject/${projectId}/authorizations`, { userIds }));
```

### 6.2 授权弹窗（`ProjectPickerView.vue`）

**入口**：工程卡片头左上角，与现有导出按钮同排（`@click.stop` 防止触发卡片进入），仅 `isAdmin` 可见，图标建议 `UserCheck`（lucide-vue-next，项目已用该库），title=「管理授权」。

**弹窗布局**（复用 `UserManagementView.vue` 的 modal 写法：Vue + Tailwind 固定遮罩层，无第三方组件库依赖）：

```
┌─ 管理工程授权 ──────────────────────── ✕ ┐
│ 工程：{name}                                │
│ 说明：未列出的用户无法看到该工程；           │
│       管理员默认可见全部工程，无需授权。      │
│ ┌─────────────────────────────────────┐   │
│ │ ☑ 张三 (操作员)  Active             │   │
│ │ ☐ 李四 (观察员)  Active             │   │
│ │ ☐ 王五 (操作员)  Inactive           │   │
│ │ …（fetchSystemUsers 结果，剔除 Admin）│   │
│ └─────────────────────────────────────┘   │
│                       [取 消]  [保存授权]   │
└───────────────────────────────────────────┘
```

**交互流程**：
1. 点击授权按钮 → 打开弹窗，并行 `fetchSystemUsers()` + `loadProjectAuthorizations(projectId)`；
2. 用户列表按 `role !== ROLE_ADMIN` 过滤（Admin 默认可见全部，见 D2）；
3. 已授权 userId 集合设为勾选态；停用（Inactive）用户可正常显示与勾选（其登录被后端拦截，授权自然无效，无需特殊处理，显示 status 徽标即可）；
4. 保存 → `saveProjectAuthorizations(projectId, 勾选 userIds)` → 成功提示（内联消息条，与导入导出结果同一容器）→ 关闭弹窗；**无需刷新卡片列表**（Admin 视角列表不变）；
5. 失败（400/404）→ 内联错误消息条展示 `err.response.data.message`。

### 6.3 状态与缓存治理（`scadaStore.ts` + `authApi.ts`）

**新增 `resetScadaStore()`**：

```ts
/** 清空组态工程缓存并复位初始化标志：登出/切换账号时调用，
 *  防止下一账号复用上一账号（可能含未授权工程）的 SPA 内存缓存。 */
export const resetScadaStore = () => {
  scadaProjects.value = [];
  projectSummaries.value = [];
  selectedProjectId.value = '';
  selectedPageId.value = '';
  _scadaInitialized = false;
  _summariesInitialized = false;
};
```

**接线点**（`authApi.ts`）：
- `performLogout()`：清 token 前后调用 `resetScadaStore()`；
- `performLogin()` 成功分支：同样调用（双保险，覆盖「未登出直接换账号登录」路径）。

**`selectProject` 强制回源（D7）**：

```ts
// 原：const existing = findProject(rawId); if (existing) { …直接返回缓存 }
// 改：非 Admin 跳过缓存命中分支，始终走 loadProjectFull 回源，
//     由后端授权校验兜底（未授权/被撤销 → 404 → catch → null → 播放器空态）。
//     Admin 保留缓存命中（编辑器频繁切换工程的性能优化）。
const skipCache = loginUser.value?.role !== ROLE_ADMIN;
const existing = skipCache ? undefined : findProject(rawId);
```

> 场景覆盖：管理员撤销授权后，用户已打开的工程标签页内刷新/跳转（`selectProject` 走缓存）会被回源 404 拦截；用户主列表标签页刷新后列表自然消失。

## 7. 授权生效时效说明（写入运维常识）

| 变更 | 生效时机 | 机制 |
|---|---|---|
| 新增授权 | 用户下一次拉取列表/打开工程 | 授权记录实时查库，立即可见 |
| 撤销授权 | 列表：用户刷新列表页即消失；已打开标签页：下一次 `selectProject` 回源（跳转/刷新）被 404 拦截 | D7 强制回源 |
| 用户角色变更（如 Operator → Admin） | JWT 内 role claim 最长 8h 后随 token 刷新生效 | 既有机制，不属本方案范围（P3-5） |

## 8. 范围外（明确不做）

1. **HmiImage 文件流收紧**：`[AllowAnonymous]` + GUID 文件名不可枚举，风险可控；
2. **SignalR 数据面权限**：hub 仅验证登录；如需按工程隔离实时值订阅，需 hub 级授权设计，另行立项；
3. **页面级/组件级授权粒度**：中间表结构未来可加 `PageId?` 列扩展，本期不做；
4. **授权委托/有效期**：`GrantedAt` 仅记录不消费；如需「授权到期自动失效」可后续消费该字段。
