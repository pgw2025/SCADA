## 1. 授权功能验证矩阵

### 1.1 列表可见性

| # | 场景 | 操作 | 预期 | 结果 |
|---|---|---|---|---|
| L1 | Admin 列表 | admin 登录 → 组态运行 | 显示全部工程（无论有无授权记录） | ☐ |
| L2 | 未授权用户列表 | op1 登录（无任何授权）→ 组态运行 | 空列表 + 文案「暂无可访问的工程，请联系管理员授权」 | ☐ |

## 5. 测试数据清理与准备脚本（MySQL）

```sql
-- 查看授权关系（排障用）
SELECT pa.ProjectId, p.Name, pa.UserId, u.Username, pa.GrantedAt
FROM ScadaProjectAuthorizations pa
JOIN ScadaProjects p ON p.Id = pa.ProjectId
JOIN SystemUsers u ON u.Id = pa.UserId
ORDER BY pa.ProjectId, pa.UserId;

-- 快速给 op1 授权全部工程（L3 前置，按实际用户名替换）
INSERT INTO ScadaProjectAuthorizations (ProjectId, UserId, GrantedAt)
SELECT p.Id, u.Id, UTC_TIMESTAMP() FROM ScadaProjects p, SystemUsers u
WHERE u.Username = 'op1'
ON DUPLICATE KEY UPDATE GrantedAt = UTC_TIMESTAMP();
```

## 6. 风险与缓解

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| K1 | 迁移在存量库执行失败（外键约束冲突：授权表引用了已不存在的工程/用户 Id——理论上不会发生，因 FK 是新建的） | 低 | 迁移仅 CREATE TABLE，无回填数据，无既有表变更；失败回滚无副作用 |
| K2 | 既有集成测试/脚本匿名调用被收紧端点 | 中 | 步骤 20 逐项排查补 Admin token；Swagger 调试亦需选 bearer |
| K3 | `ICurrentUser` 在无 HttpContext 场景（后台任务）被意外解析 | 低 | 实现返回默认值（UserId=0/IsAdmin=false），最坏结果是空列表而非越权 |
| K4 | 高频列表查询带来的授权联查开销 | 低 | `UserId` 单列索引 + 每请求仅一次授权查询；工程量级（通常 <100）下可忽略 |
| K5 | 撤销授权的即时性依赖用户端回源/刷新 | 中 | D7 已覆盖播放器回源；纯静态停留画面（不再发起任何请求）无法强制下线——属页面级会话语义，如需强踢另行立项 |
| K6 | JWT role claim 8h 有效期内角色变更不生效 | 低 | 既有机制，授权记录本身实时查库不受影响；运维常识记录于 [02-详细设计 §7](02-详细设计.md#7-授权生效时效说明写入运维常识) |
