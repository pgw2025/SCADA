## 3. 回归风险与边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| QueueCapacity/MaxPerMinutePerChannel 仍重启生效 | 构造 Channel/RateBucket 时固定 | 文档已声明；如确需即时生效属后续增量（需重建管道，违背本方案最小改动原则） |
| 全量 `_states` 使未启用渠道空转 | 4 个消费循环常驻读空 Channel | 开销可忽略；`RateBucket` 仅投递时消耗 |
| 保存触发 `reloadOnChange` 的抖动 | FileSystemWatcher 非原子写可能多次触发 | 本方案**不订阅** `OnChange`，仅靠 `CurrentValue` 惰性读，无抖动副作用 |
| sender 单例的 `IOptionsMonitor` 线程安全 | 多线程并发读 `CurrentValue` | `IOptionsMonitor` 本身线程安全；`Opt`/`Push`/`Templates` 均为无副作用惰性读 |

## 4. 回滚方案

- 本次改动为纯「读取数据源切换」（`IOptions` → `IOptionsMonitor` + 动态访问器），**无数据迁移、无接口变更、无前端变更**。
- 回滚方式：`git revert` 本次提交即可恢复原「重启生效」行为；或直接切回变更前 commit。
- 由于不涉及数据库/文件格式，无需数据回滚。
