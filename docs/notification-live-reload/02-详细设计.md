# 02 · 详细设计（逐文件 before/after）

> 约定：所有 sender 把「启动快照字段」替换为「`IOptionsMonitor` + 动态访问器属性」，命名统一为 `Opt`（decorator/service 用 `Policy`/`Templates`/`Push`）。`using Microsoft.Extensions.Options;` 已存在，`IOptionsMonitor<T>` 与 `IOptions<T>` 同一命名空间，**无需新增 using**。

## 文件 5 · `WebApi/HostedServices/ExternalNotificationService.cs`

### 现状（关键片段）
```csharp
private readonly List<SenderState> _states;
private readonly ExternalPushPolicy _policy;
...
public ExternalNotificationService(
    IEnumerable<IExternalMessageSender> senders,
    IOptions<NotificationOptions> options,
    INotificationLogRecorder logRecorder,
    ILogger<ExternalNotificationService> logger)
{
    _policy = options.Value.Push;
    ...
    _mainChannel = Channel.CreateBounded<ExternalMessage>(new BoundedChannelOptions(Math.Max(64, _policy.QueueCapacity)) { ... });
    _states = senders
        .Where(s => s.Enabled)
        .Select(s => new SenderState { ..., Bucket = new RateBucket(TimeSpan.FromMinutes(1), _policy.MaxPerMinutePerChannel) })
        .ToList();
}

public bool HasEnabledChannels => _states.Count > 0;
public bool IsChannelEnabled(string senderName) =>
    _states.Any(s => string.Equals(s.Sender.Name, senderName, StringComparison.OrdinalIgnoreCase));
```

`Enqueue`（第 95 行）：`if (_states.Count == 0) return false;`
`StartAsync`（第 112 行）：`if (_states.Count == 0) { log "均未启用"; return; }`
`FanoutAsync`（第 196 行）：`foreach (var state in _states)`（无 Enabled 判断）
`SendWithRetryAsync`：`_policy.MaxAttempts`、`_policy.RetryBaseDelayMs`

### 目标
1. 注入改 `IOptionsMonitor<NotificationOptions>`。
2. `_states` 去掉 `.Where(s => s.Enabled)`，全量保留全部 sender。
3. 新增 `Push` 动态访问器（运行期参数）；构造期参数（QueueCapacity/MaxPerMinutePerChannel）用构造时局部变量取值。
4. `HasEnabledChannels`/`IsChannelEnabled` 改为动态读 sender.Enabled。
5. `Enqueue`/`StartAsync` 短路判断改用动态标志。
6. `FanoutAsync` 投递前动态跳过未启用渠道。
7. `SendWithRetryAsync` 的 `MaxAttempts`/`RetryBaseDelayMs` 改从 `Push` 动态读。

### 改动后

**字段与构造**：
```csharp
private readonly List<SenderState> _states;
private readonly IOptionsMonitor<NotificationOptions> _monitor;
private readonly INotificationLogRecorder _logRecorder;
private readonly ILogger<ExternalNotificationService> _logger;
...
public ExternalNotificationService(
    IEnumerable<IExternalMessageSender> senders,
    IOptionsMonitor<NotificationOptions> options,
    INotificationLogRecorder logRecorder,
    ILogger<ExternalNotificationService> logger)
{
    _monitor = options;
    _logRecorder = logRecorder;
    _logger = logger;

    // 构造期参数（Channel 容量 / 限流桶窗口）在启动时取一次快照，不改运行时语义
    var push = options.CurrentValue.Push;

    _mainChannel = Channel.CreateBounded<ExternalMessage>(new BoundedChannelOptions(Math.Max(64, push.QueueCapacity))
    {
        FullMode = BoundedChannelFullMode.DropWrite,
        SingleReader = true
    });

    // 全量保留全部渠道：启用判定下放到 HasEnabledChannels / Fanout 动态判断
    _states = senders
        .Select(s => new SenderState
        {
            Sender = s,
            Channel = Channel.CreateBounded<ExternalMessage>(new BoundedChannelOptions(Math.Max(64, push.QueueCapacity))
            {
                FullMode = BoundedChannelFullMode.DropWrite,
                SingleReader = true
            }),
            Bucket = new RateBucket(TimeSpan.FromMinutes(1), push.MaxPerMinutePerChannel)
        })
        .ToList();
}

// 运行期参数（重试次数/退避）每次发送动态读取，保存后即时生效
private ExternalPushPolicy Push => _monitor.CurrentValue.Push;
```

**动态标志（原第 88/106 行）**：
```csharp
public bool HasEnabledChannels => _states.Any(s => s.Sender.Enabled);

public bool IsChannelEnabled(string senderName) =>
    _states.Any(s => s.Sender.Enabled &&
        string.Equals(s.Sender.Name, senderName, StringComparison.OrdinalIgnoreCase));
```

**Enqueue（原第 95 行）**：
```csharp
if (!HasEnabledChannels) return false;   // 原 _states.Count == 0
```

**StartAsync（原第 112–127 行）**：
```csharp
public Task StartAsync(CancellationToken cancellationToken)
{
    var enabled = _states.Where(s => s.Sender.Enabled).ToList();
    if (enabled.Count == 0)
    {
        _logger.LogInformation("钉钉/邮件/企业微信/Web Push 通知渠道均未启用，外部消息推送服务空闲。");
    }
    else
    {
        _logger.LogInformation("外部消息推送服务启动：{Count} 个渠道（{Channels}）。",
            enabled.Count, string.Join("、", enabled.Select(s => s.Sender.Name)));
    }

    // 注意：即使无启用渠道，扇出与消费循环仍启动（空转），以便运行期动态启用渠道免重建
    _fanoutTask = FanoutAsync(_cts.Token);
    foreach (var state in _states)
    {
        state.Loop = SenderLoopAsync(state, _cts.Token);
    }
    return Task.CompletedTask;
}
```

**FanoutAsync（原第 196 行）**：
```csharp
foreach (var state in _states)
{
    // 动态跳过未启用渠道（渠道禁用的竞态窗口由 IsChannelEnabled 前置校验兜底）
    if (!state.Sender.Enabled) continue;

    // 重试路径：只投递到目标渠道
    if (msg.TargetChannel is not null &&
        !string.Equals(state.Sender.Name, msg.TargetChannel, StringComparison.OrdinalIgnoreCase))
    {
        continue;
    }
    ...
}
```

**SendWithRetryAsync（原第 286/295 行）**：
```csharp
if (attempt >= Push.MaxAttempts) { ... }          // 原 _policy.MaxAttempts
...
var delay = Push.RetryBaseDelayMs;                 // 原 _policy.RetryBaseDelayMs（注意：delay 初值在第 270 行）
```

> 注意：`var delay = _policy.RetryBaseDelayMs;` 在 `SendWithRetryAsync` 开头（第 270 行）定义初值，也要一并改为 `Push.RetryBaseDelayMs`。

### 注意点（坑位）
1. **`_policy` 字段不再保留**（它原本只承载 `ExternalPushPolicy`）。若保留会与 `Push` 动态属性产生两套语义；务必删除。
2. **`StopAsync` 不变**——仍遍历全量 `_states` 完成 Channel 与等待 Loop，因为全量保留后无「被移出的僵尸循环」。
3. **`QueueCapacity` / `MaxPerMinutePerChannel` 仍重启生效**：它们参与 Channel/RateBucket 构造，构造后即固定。`MaxAttempts` / `RetryBaseDelayMs` 走 `Push` 动态，即时生效。
4. **`StartAsync` 现在即使「均未启用」也启动循环**——这是有意为之（空转代价可忽略），换取「运行期动态启用渠道免重建」。日志措辞已相应调整为「空闲」而非「直接 return」。
5. **`FanoutAsync` 动态跳过放最前**：先判断 `Enabled`，再判断 `TargetChannel`，双保险避免向已禁用渠道重试投递。
