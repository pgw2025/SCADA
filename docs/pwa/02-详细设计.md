## 2. Manifest 设计

由 `vite-plugin-pwa` 的 `manifest` 配置在构建期生成 `dist/manifest.webmanifest`，并自动注入 `<link rel="manifest">`。

| 字段 | 值 | 说明 |
|---|---|---|
| `name` | 晋鑫设备管理系统 | 完整名（安装对话框/启动画面用） |
| `short_name` | 晋鑫设备 | ≤6 汉字，桌面/主屏图标下标签 |
| `id` | `/` | 固定 id，避免后续配置变化被判定为"另一个应用"导致重复安装 |
| `start_url` | `/` | 登录态由路由守卫按角色分发（`/dashboard` 或 `/scada-view`），无需区分 |
| `scope` | `/` | 全站范围 |
| `display` | `standalone` | 独立窗口，无浏览器 UI |
| `orientation` | `any` | 组态大屏横竖屏均允许 |
| `theme_color` | `#0ea5e9` | 与 boot-loading spinner 主色一致 |
| `background_color` | `#f1f5f9` | 与启动画面背景一致，启动过渡无闪变 |
| `lang` / `dir` | `zh-CN` / `ltr` | |
| `icons` | 192 / 512 PNG + 512 maskable PNG | maskable 安全区：内容缩至图标 80% 内（≥40% 安全边距） |
| `shortcuts`（可选） | 组态运行 `/scada-view`、报警管理 `/alarm-management` | 长按图标快捷入口，实施时按价值取舍 |

`index.html` 另行补充：`<link rel="icon">`（favicon）、`<link rel="apple-touch-icon">`（180×180，iOS 添加主屏必需）、`<meta name="theme-color">`、`<meta name="apple-mobile-web-app-capable" content="yes">` 与 `apple-mobile-web-app-status-bar-style`。

## 3. Service Worker 设计

### 3.1 模式与构建接线

- `vite-plugin-pwa` 配置 `strategies: 'injectManifest'`，`srcDir: 'src'`，`filename: 'sw.ts'`。
- `src/sw.ts` 顶部 `declare const self: ServiceWorkerGlobalScope`，引用 `virtual:pwa-register` 类型；使用 Workbox 的 `precacheAndRoute(self.__WB_MANIFEST)` —— 构建期插件把**完整预缓存清单**（全部带哈希的构建产物）注入该变量。
- `registerType: 'prompt'`（D2）；`injectRegister: false`，由 `pwaRegister.ts` 手动注册（控制注册时机在应用挂载后）。
- `devOptions: { enabled: true, type: 'module' }`：开发期也产出 SW（`sw.js` 由 dev server 提供），保证开发环境可调试缓存与推送逻辑。
- 预缓存体积控制：`globPatterns: ['**/*.{js,css,html,svg,png,ico,woff2}']`，`maximumFileSizeToCacheInBytes: 3MB`（超出者跳过并构建告警，实施时按 dist 实际产物核对——注意现有 `widget-template` 手动 chunk 与各懒加载路由 chunk 均会被全量预缓存）。

### 3.2 预缓存（App Shell）

- 内容：`index.html`、全部 JS/CSS chunk、图标、字体。带内容哈希，**新构建发布即触发 SW 更新流程**（§3.5）。
- `cleanupOutdatedCaches: true`：新版激活后自动清理旧版本预缓存。

### 3.3 运行时缓存策略表

`injectManifest` 模式下 runtime 路由在 `sw.ts` 手写（`registerRoute`）：

| 匹配 | 策略 | 缓存名 | 参数 | 说明 |
|---|---|---|---|---|
| `request.mode === 'navigate'`（SPA 导航/刷新） | `NetworkFirst` | `html-runtime` | `networkTimeoutSeconds: 3` | 在线拿新 HTML；弱网/断网回退缓存，再回退 `index.html`（precache）。**history 路由深链刷新不断网也可用** |
| `/api/**` GET 且命中白名单 `isCacheableApi(path)` | `NetworkFirst` | `api-runtime` | `networkTimeoutSeconds: 3`；`ExpirationPlugin: maxEntries 200, maxAgeSeconds 86400` | 离线数据兜底的 API 侧缓存（D4） |
| `/api/**` 其余（Auth、用户管理、系统配置、写操作等） | **不缓存**（直接放行网络） | — | — | 安全边界（§4.1） |
| `/open/**` | **不缓存** | — | — | 开放 API 网关，语义上不属前端可缓存资源 |
| `/hubs/**` | **不缓存** | — | — | SignalR WebSocket 通道由 `withAutomaticReconnect` 自管 |
| 同源静态资源未入预缓存清单者 | `CacheFirst`（可选） | `static-runtime` | `ExpirationPlugin: 30d` | 兜底动态引用的图片等，实施时按需取舍 |

**`isCacheableApi` 白名单**（前缀匹配，实施时以 `Client/swagger.json` 实际路由逐项核对）：

```
允许：/api/Devices、/api/DataPointMappings（变量）、/api/AlarmRecords（报警记录）、
      /api/ScadaPage、/api/ScadaProject（组态工程与页面，按授权过滤——见 §4）、
      /api/Dashboard、/api/Areas、设备状态类只读 GET
排除：/api/Auth/**（缓存 /me 会让已吊销会话离线"复活"）、/api/Users/**、
      /api/NotificationConfig/**、/api/SystemLog/**（含敏感管理面）、
      一切非 GET（POST/PUT/DELETE 永不缓存）
```

### 3.4 SW 消息通道协议（页面 ↔ SW）

| 方向 | type | 载荷 | 行为 |
|---|---|---|---|
| 页面→SW | `SKIP_WAITING` | — | 等待中的新 SW 立即 `skipWaiting()`（用户在更新横幅点"立即刷新"时） |
| 页面→SW | `CLEAR_USER_DATA` | — | 删除 `api-runtime`、`html-runtime` 缓存（**precache 不删**，壳不破） |
| 页面→SW | `GET_VERSION` | — | 回传 SW 版本（调试/验收用） |
| SW→页面 | `NAVIGATE` | `{ url }` | 通知点击聚焦已有窗口时，由页面执行 `router.push(url)` |

### 3.5 版本更新流程（prompt 模式状态机）

```
发布新版本
  → 浏览器后台轮询发现 sw.js 变化（precache 清单哈希不同）
  → 新 SW 安装（install）进入 waiting（不自动激活，D2）
  → pwaRegister 的 onNeedRefresh 回调触发
  → ReloadPrompt 横幅：「新版本已就绪 [立即更新] [稍后]」
       用户点「立即更新」
         → postMessage(SKIP_WAITING) → 新 SW controllerchange
         → pwaRegister 自动 location.reload()
       用户点「稍后」
         → 横幅收起，下次刷新页面时 SW 仍在 waiting，横幅再次出现
```

无人值守大屏场景的增强（可选，实施时评估）：横幅出现超过 N 分钟未响应时升级为更醒目的常驻角标，但仍**不自动刷新**（保证不打断正在进行的操作）。

### 3.6 SW 生命周期纪律

- `sw.ts` 中 `skipWaiting` **只**由消息通道触发，不注册 `install` 事件自动 skipWaiting。
- 页面注册使用 `register SW 绝对同源相对路径`（`/sw.js`，`scope: '/'`）。
- SW 内所有事件回调使用 `event.waitUntil()` 包裹异步工作，防止 SW 提前休眠。
- `push`/`notificationclick`/`pushsubscriptionchange` 处理器见 §5。

## 4. 缓存与数据安全（跨账号防护）

### 4.1 三道防线

| 防线 | 机制 | 覆盖场景 |
|---|---|---|
| 一：白名单 | §3.3 `isCacheableApi` 只放行只读业务 GET；`/api/Auth`、用户/配置管理面、非 GET 全排除 | 缩小泄漏面：管理面数据从不落缓存 |
| 二：主动清理 | **登出（authApi.logout）/ 换号登录（登录成功且当前账号 ≠ 订阅/快照绑定的账号）/ 401 强登出（http.ts 拦截器）** 三路径统一执行：① `postMessage(CLEAR_USER_DATA)` 让 SW 删 `api-runtime`+`html-runtime`；② 页面清 IndexedDB 快照（`snapshotDB.clearAll()`） | 正常流转下换号前旧数据已清 |
| 三：命名空间兜底 | IndexedDB 快照按 userId 命名空间存储（`pwa-snapshot:u{userId}`）；加载快照前校验当前登录 userId | 防御"清理被绕过/失败"的极端情况（如 SW 消息丢失） |

> 与项目授权功能（doc/project-authorization）的关系：`/api/ScadaPage`、`/api/ScadaProject` 响应是**按授权过滤的账号视角数据**，属白名单内"允许缓存"但也属"换号必清"的重点对象——防线二/三即为此设计。

### 4.2 清理时机矩阵

| 触发点 | api-runtime 缓存 | html-runtime 缓存 | IndexedDB 快照 | 推送订阅 |
|---|---|---|---|---|
| 登出 | ✅ 清 | ✅ 清 | ✅ 清 | ❌ **保留**（D3） |
| 换号登录（A→B） | ✅ 清 | ✅ 清 | ✅ 清 + 命名空间切到 B | ➡️ **换绑到 B**（D3） |
| 401 强登出 | ✅ 清 | ✅ 清 | ✅ 清 | ❌ 保留（推送判定不依赖会话在线） |
| SW 更新激活 | 保留（含哈希的 precache 自动换代） | 保留 | 保留（与 SW 版本无关） | 保留 |

## 5. Web Push 设计

### 5.1 端到端数据流

```
[触发] 报警触发 / 设备故障 / 系统错误（既有管线调用点，无新增调用方）
  → ExternalNotificationDecorator（既有：过滤/去抖/模板渲染）
      新增：填充 Severity + Tokens（D8）
  → Enqueue(ExternalMessage)（既有有界队列）
  → ExternalNotificationService 扇出（既有：渠道隔离/限流/合并/退避）
  → WebPushSender.SendAsync(message)（新增渠道）
      ① 级别过滤：Severity < 配置阈值（默认 Error）→ 丢弃
      ② 查询有效订阅（含订阅者角色）
      ③ 逐订阅构造 payload（landingUrl 按角色，§5.4）
      ④ 并发推送（SemaphoreSlim 限并发，默认 8）
      ⑤ 410/404 → 删除该订阅并记日志（过期清理）
  → 浏览器推送服务（FCM/Mozilla 自动推送服务，URL 来自订阅 endpoint）
  → 设备 SW `push` 事件
      解 payload → showNotification（tag 折叠）
  → 用户点击 → SW `notificationclick`
      已有窗口 → focus + postMessage(NAVIGATE)
      无窗口 → openWindow(landingUrl)
```

### 5.2 订阅模型（前端）

- **权限请求**：仅由用户手势触发（D11）——设置中心「推送通知」开关/通知中心入口按钮。`Notification.requestPermission()` 被拒后，开关显示"浏览器已拒绝，请在浏览器设置中开启"引导文案。
- **订阅创建**：`navigator.serviceWorker.ready` → `registration.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: urlBase64ToUint8Array(vapidPublicKey) })` → 序列化 `PushSubscription.toJSON()`（endpoint/keys.p256dh/keys.auth/expirationTime）→ `POST /api/push/subscriptions`（JWT 关联当前用户）。
- **换绑**：后端以 `endpoint` 为唯一键 upsert——同一浏览器换账号登录后重新 POST，即把该订阅的 `UserId` 更新为当前账号（D3）。
- **登出**：不调退订 API，订阅保留。
- **自动续订**（D12）：SW 监听 `pushsubscriptionchange` → `unsubscribe()` 旧订阅 → `subscribe()` 新订阅 → `fetch` 调 `POST /api/push/subscriptions`（无 JWT 时带上一绑定的订阅凭证——设计取舍见下）。
  - **续订鉴权问题**：SW 续订发生在页面之外，可能无有效 JWT。方案：续订请求头携带一个**续订令牌**（订阅创建时后端签发的随机 opaque token，存于订阅记录并回传前端，前端存 IndexedDB 供 SW 使用）；后端凭续订令牌识别"哪个订阅在续订"，换绑时重签。若续订令牌亦失效则静默放弃，等待用户下次打开应用时走正常订阅流程。
- **退订**：设置页关闭开关 → `subscription.unsubscribe()` + `DELETE /api/push/subscriptions`。

### 5.3 订阅数据模型（后端，MySQL）

实体 `PushSubscription`（放现有实体目录，随既有 EF 迁移流程建表）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `Id` | int/long PK | |
| `Endpoint` | varchar(512) | 推送服务 URL，**唯一索引**（换绑 upsert 键） |
| `P256DH` | varchar(256) | 客户端公钥 |
| `Auth` | varchar(256) | 认证密钥 |
| `UserId` | int FK → Users | 当前绑定用户（换绑即更新） |
| `RenewalToken` | varchar(128) | SW 续订凭证（换绑时重签） |
| `ExpirationTime` | datetime NULL | 订阅自带过期时间 |
| `UserAgent` | varchar(256) | 设备/浏览器识别（多设备管理展示） |
| `CreatedAtUtc` / `LastPushAtUtc` | datetime | 创建/最近推送成功时间（运维观测） |
| `LastErrorCode` | varchar(64) NULL | 最近推送失败原因（410/404/超时…） |

索引：`Endpoint` 唯一；`UserId` 普通索引（按用户查订阅）。

### 5.4 推送 payload 契约（后端 → SW）

`WebPushSender` 对每个订阅构造 JSON（UTF-8，≤2KB 谨慎控制字段）：

```jsonc
{
  "title": "⚠️ 报警触发 [温度超限]",        // 模板渲染后的标题（复用既有 Title）
  "body": "1#炉·Temp PV=128.5℃ 阈值120 · 2026-09-05 14:32",  // 结构化摘要（非 Markdown）
  "tag": "alarm:{alarmRuleId}",           // 同规则折叠：新通知替换旧通知（renotify:true）
  "severity": "Error",                     // Error/Critical/System…
  "landingUrl": "/alarm-management",       // 按订阅者角色计算（Admin）
  "timestampUtc": "2026-09-05T06:32:11Z"   // UTC，显示时本地化
}
```

角色 → landingUrl 映射（后端逐订阅计算，D6）：

| 订阅者角色 | landingUrl |
|---|---|
| Admin | `/alarm-management` |
| Operator / Viewer | `/scada-view`（通知正文已含报警摘要，不依赖落地页详情） |
| 角色缺失/失效 | `/scada-view`（保守默认） |

SW `showNotification` options：`icon`（192 图标）、`badge`（可选小徽标）、`tag`、`renotify: true`、`data: { landingUrl }`、`requireInteraction`（仅 Critical 级可设，实施时评估）。

### 5.5 频率治理（复用 + 增量）

| 层 | 机制 | 来源 |
|---|---|---|
| 管线层 | 渠道限流（每分钟上限）、超限合并计数捎带、指数退避重试 | **既有** `ExternalNotificationService`，Web Push 作为渠道自动获得 |
| 事件层 | 变量更新不外发；设备状态仅 Offline(可配)/Fault 且按设备去抖 | **既有** `ExternalNotificationDecorator` |
| 渠道层（新增） | `WebPush:MinSeverity`（默认 `Error`，低于不推）；`WebPush:PushRecover`（报警恢复通知，默认 `false`）；`WebPush:MaxConcurrentSends`（默认 8） | `NotificationOptions` 新增 `WebPushOptions` 节 |
| 客户端层 | `tag` 折叠：同规则告警风暴在通知栏只保留最新一条 | payload `tag` + `renotify` |

### 5.6 API 契约（后端，JWT 鉴权）

| 方法/路由 | 请求 | 响应 | 说明 |
|---|---|---|---|
| `GET /api/push/vapid-public-key` | — | `{ publicKey }` | 公钥无需保密；应用启动/设置页拉取 |
| `POST /api/push/subscriptions` | `{ endpoint, p256dh, auth, expirationTime? }` | `{ bound: true, renewalToken }` | upsert：endpoint 存在→换绑当前用户+重签续订令牌；否则新建 |
| `GET /api/push/subscriptions/me` | — | `{ subscribed: true, userAgent, lastPushAtUtc }[]` | 设置页展示本账号全部设备订阅 |
| `DELETE /api/push/subscriptions` | `{ endpoint }` | 204 | 退订（本人订阅才可删） |
| `POST /api/push/subscriptions/renew` | 头 `X-Renewal-Token`，体同 POST | `{ bound: true }` | SW 自动续订专用（凭续订令牌鉴权，不要求 JWT） |

权限边界：订阅管理接口要求已登录（Admin/Operator/Viewer 均可——操作工正是推送的主要受众）；推送内容不越过角色可见性（正文摘要来自报警事件本身，非越权查询）。

### 5.7 后端服务设计

`WebPushSender : IExternalMessageSender`（`Server/ScadaServer.WebApi/Services/` 或与钉钉/邮件发送器同目录）：

- `Name = "WebPush"`；`Enabled = WebPushOptions.Enabled && VAPID 密钥完整`（缺密钥时 Disabled，管线自动不扇出该渠道——与现有渠道行为一致）。
- `SendAsync(ExternalMessage, ct)`：§5.1 的 ①–⑤。单订阅推送失败不抛异常（记 `LastErrorCode`，410/404 删除）；**全部失败也不向管线抛**（渠道级失败由管线退避，但订阅级失败属正常运维噪声）。
- 依赖注入：`AddSingleton<IExternalMessageSender, WebPushSender>()`（与既有两渠道并列一行）；内部经 `IServiceScopeFactory` 取 DbContext（订阅表查询），避免单例持有 DbContext。
- Web Push 协议库：`WebPush`（NuGet，web-push-csharp）——VAPID JWT 签名 + RFC 8291 `aes128gcm` 载荷加密。**阶段五第 1 步真机预验证后才全面实施**（D13）。

### 5.8 VAPID 密钥管理

- 配置节：`Notification:WebPush:Vapid:PublicKey / PrivateKey / Subject`（`mailto:` 或 `https:` 身份，推送服务商联系用）。
- 生成：一次性命令行工具或启动时缺失自动生成并**写回 override 文件 + 日志提示**（实施时二选一，推荐前者：密钥应纳入部署流程管理而非运行时生成）。
- 生产经 `appsettings.dboverride.json`（最后加载覆盖）或环境变量注入，**私钥不入库不入前端**。
- **运维红线（D14）**：私钥轮换 = 全部订阅失效（签名主体变更，推送服务拒发），需全员重新开启推送；单实例部署前提；多实例必须共享同一密钥。

## 6. 离线数据快照设计

### 6.1 数据模型（IndexedDB：`pwa-snapshot`）

按 userId 命名空间（防线三）：每用户一个 object store 集合，或库名带 userId（`pwa-snapshot-u3`）。推荐**单库多 store + 记录键带 `u{userId}:` 前缀**（避免库数量随用户增长）：

| store | 键 | 值 | 来源 |
|---|---|---|---|
| `meta` | `u{userId}:current` | `{ userId, savedAtUtc, swVersion }` | 写入器每次落盘更新（横幅"数据截至"取此） |
| `devices` | `u{userId}:{deviceId}` | 设备状态快照（status/lastSeen…） | `ReceiveDeviceStatus` + 设备列表加载 |
| `variables` | `u{userId}:{deviceId}:{variableKey}` | 最新值（value/quality/updateTimeUtc） | `ReceiveVariableUpdate`（节流批量） |
| `alarms` | 自增 | 最近 N 条（默认 100）报警事件 | `ReceiveAlarm` |

版本化：`indexedDB.open('pwa-snapshot', 1)`，`onupgradeneeded` 建 store；后续结构演进升版本号迁移。

### 6.2 写入器（snapshotWriter.ts，D9）

```
数据源（SignalR 回调 / store 更新）──┐（仅标脏，不落盘）    │
定时器（默认 10s）──触发──▶ flush()：脏 store 批量写入 IndexedDB ──▶ 更新 meta.savedAtUtc
visibilitychange(hidden) / pagehide ──强制 flush──▶（防止移动端切换后台被冻结丢数据）
写入失败 ──▶ 静默降级（console.warn + 停止本会话快照），不影响主流程
```

- 节流参数可配（常量集中定义，暂不做 UI 配置面）。
- 版本号防回写：flush 前校验 `meta` 中 swVersion/会话 epoch，避免旧页面实例（多标签页）覆盖新会话数据。

### 6.3 离线读取与恢复流程

```
应用启动（initializeAuth 后，进入已登录壳）
  ├─ navigator.onLine === true → 正常流程（API 拿新数据）
  └─ 离线 / API 全部失败
       → 按 userId 读快照 → 灌入对应 Pinia store 作为初值
       → OfflineBanner：「离线模式 · 数据截至 14:32:05」
       → SignalR withAutomaticReconnect 持续重试（既有能力，零改动）
       → 网络恢复（online 事件 / SignalR 重连成功）
            → 触发一轮全量刷新（重新拉取设备/变量/报警列表 API——复用各页面既有加载函数）
            → 快照写入器恢复正常节流落盘
            → 横幅消失
```

- **冷启动降级**：IndexedDB 被系统回收（移动端存储压力）或快照损坏 → 读失败视为"无快照"，进入正常的离线空态提示（"当前离线，暂无缓存数据"），应用不得崩溃（优化点 12）。
- 时间戳展示本地化（数据 UTC 存储，遵守全局时间约定）。

## 8. 关键时序

### 8.1 报警推送端到端

```
AlarmRuleEngine 判定报警触发
  → IScadaNotificationService.NotifyAlarm…（既有）
  → ExternalNotificationDecorator：模板渲染 + [新增] Severity/Tokens 填充
  → 队列 → 扇出 → WebPushSender
       → 过滤(≥Error) → 查订阅(含角色) → 逐订阅 payload(角色 landingUrl)
       → 并发推送 → 410 清理
  → 推送服务 → 设备 SW push 事件 → showNotification(tag 折叠)
  → [页面关闭也能收到——推送与登录会话解耦]
  → 用户点击 → 聚焦/新开 → landingUrl → 路由守卫按角色放行 ✓
```

### 8.2 版本发布（prompt 更新）

```
运维发布新版 dist → 用户浏览器后台检测 sw.js 变化 → 新 SW waiting
  → onNeedRefresh → ReloadPrompt 横幅
  → [立即更新] → SKIP_WAITING → controllerchange → reload（进入新版）
  → [稍后]     → waiting 保持，下次导航横幅再现（不自动重载，不打断盯屏）
```

### 8.3 离线启动 → 恢复

```
设备断网 → 用户打开 PWA
  → initializeAuth：/me 请求失败但本地有 token → 沿用本地快照（既有行为）→ 进入已登录壳
  → API 失败 + SW api-runtime 命中 → 页面用缓存数据渲染
  → SignalR/快照初值补充实时面 → 横幅「离线模式 · 数据截至 14:32」
  → 网络恢复 → online 事件 → 全量刷新 → 横幅消失 → 快照恢复正常节流
```
