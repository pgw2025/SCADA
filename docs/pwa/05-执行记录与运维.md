## 二、与计划文档的偏差记录（步骤 34 复核）

| # | 偏差 | 理由 |
|---|---|---|
| 1 | `WebPushSender` 落位 `ScadaServer.Infrastructure/Communication/`（计划写 WebApi/Services） | 执行计划头部约定「以钉钉/邮件发送器实际位置为准对齐」，两既有渠道均在 Infrastructure/Communication |
| 2 | `PushSubscriptions` 不建 SystemUsers 外键（计划 §5.3 写 UserId FK） | 同 AlarmRecord 设计取舍：用户删除不级联影响订阅表；孤儿订阅由 410/404 清理兜底。UserId 索引保留 |
| 3 | 续订令牌额外加**唯一索引** `ix_pushsubscriptions_renewaltoken`（计划仅列 Endpoint/UserId 索引） | renew 端点凭令牌定位订阅是高频路径，显式索引避免全表扫描 |
| 4 | 快照库无独立 `variables` store（§6.1 四 store → 实为 meta/devices/alarms 三 store） | 本项目变量实时值内嵌在 Device 对象（`variables`/`variableTimestamps`/`variableMeta`），设备全量落盘即携带变量最新值，独立 store 属重复存储且放大写入量 |
| 5 | 网络恢复刷新复用 `syncDevices({realtime:true})` + `refreshActiveAlarms()`，不做整页 reload | 更小侵入；SignalR 重连路径本就执行同一组刷新函数，行为一致 |
| 6 | `MinSeverity` 排名兼容两套命名：Info/Low=0、Warning/Medium=1、Error/High=2、Critical=3 | 项目报警级别为 Low/Medium/High/Critical，计划默认值 `Error` 按映射等价于「High 及以上才推」 |
| 7 | `ExternalNotificationService.WithSuppressedNote` 克隆补齐 `Severity/Tokens` | 限流合并捎带若丢弃新字段，Web Push 的级别过滤/payload 构造在合并消息上将失效（计划未提及，实施中发现） |
| 8 | 步骤 19「Web Push 库真机预验证」**未在本轮执行**（需真实浏览器订阅+HTTPS） | WebPush（web-push-csharp）1.0.12 已接入；真机验证矩阵（Chrome/Edge/Firefox/Android）列入下节部署验收 D 项，**验证不通过前不建议生产启用该渠道** |
| 9 | 图标资产直接生成（Pillow/脚本），未留设计源 SVG | 五件资产已验收（maskable 预留 80% 安全区）；后续可按需补源文件 |

## 三、部署清单（上线前逐项核对）

### A. 生产环境前置确认（阶段一步骤 1）

- [ ] nginx SPA `try_files $uri $uri/ /index.html;` 存在且覆盖全部 PWA 资源路径
- [ ] 部署 URL 为**根路径**（若子路径：manifest `start_url`/`scope`、SW 注册路径、图标引用需统一加前缀——当前实现按根路径落地）
- [ ] HTTPS 证书浏览器受信（真机访问无告警；自签/内网 CA 需真机验证推送连通）
- [ ] 后端**单实例**部署（VAPID 密钥本地持有前提；多实例必须共享同一密钥）
- [ ] `/api`、`/open`、`/hubs`（含 WebSocket upgrade）反代规则维持现状

### B. nginx PWA 配置（合入 server 块）

```nginx
# SW 与 manifest 必须绕过一切 HTTP 缓存，否则更新流程被缓存卡死（D2 prompt 更新的前提）
location = /sw.js {
  add_header Cache-Control "no-cache, no-store, must-revalidate";
}
location = /manifest.webmanifest {
  types { } default_type application/manifest+json;
  add_header Cache-Control "no-cache";
}
# SPA history 回退（若已配置则确认覆盖 PWA 资源路径）
location / {
  try_files $uri $uri/ /index.html;
}
```

### C. 后端发布

1. 应用 EF 迁移（`PushSubscriptions` 表 + 3 索引）：发布随 `dotnet ef database update` 或启动自动迁移流程
2. 生成 VAPID 密钥对（一次性，见下「四、VAPID 密钥管理」）
3. `appsettings.dboverride.json` / 环境变量注入：`Notification__WebPush__Enabled=true`、`Vapid__Subject/PublicKey/PrivateKey`
4. 启动日志核对：`外部消息推送服务启动：N 个渠道（…、WebPush）`；若 WebPush 未出现，检查 Enabled 与密钥完整性（缺密钥渠道自动禁用，属预期行为）

- [ ] 版本发布演练：部署版本 A → 浏览 → 部版本 B → 旧页面出现「新版本已就绪」横幅 → 立即更新进入 B → 旧 precache 清理

## 四、VAPID 密钥管理（D14 · 运维红线）

**生成**（一次性，任选其一）：

```bash
# 方式一：Node web-push CLI（推荐，任意有 Node 的机器执行）
npx web-push generate-vapid-keys

# 方式二：后端依赖自带能力（C# 交互式，调试用）
# WebPush.VapidHelper.GenerateVapidKeys()
```

**注入**：`PublicKey` 可明文入 appsettings；`PrivateKey` 生产必须走 `appsettings.dboverride.json` 或环境变量 `Notification__WebPush__Vapid__PrivateKey`，**不入库、不入前端、不入 git**。

**红线**：

1. **私钥轮换 = 全部订阅失效**（签名主体变更，推送服务拒发），需公告全员重新开启推送；
2. 多实例部署必须共享同一密钥对（否则推送随机失败）；
3. `Subject` 为 `mailto:` 或 `https:` 联系方式，推送服务商滥用申诉时使用，不可留空。

## 五、推送故障排查

| 现象 | 排查路径 |
|---|---|
| 设置页「推送服务未启用」 | 后端 `Notification:WebPush:Enabled` 是否 true；`vapid-public-key` 接口返回 |
| 订阅成功但收不到 | ① `PushSubscriptions` 表是否有该用户记录（`GET /api/push/subscriptions/me`）；② `LastErrorCode` 字段（410=订阅过期已清理/404=失效/HttpError=推送服务不可达）；③ 报警级别是否 ≥ MinSeverity（默认 Error ⇒ Low/Medium 不推）；④ 恢复类通知默认不推（`PushRecover=false`） |
| 换号后收不到 | 预期行为之一：换号登录会换绑订阅到新账号，旧账号不再接收（D3）；若新账号也不收，检查登录后 `rebindIfNeeded` 是否执行（浏览器控制台 `[PWA]` 日志） |
| 手机端浏览器订阅静默失效 | 浏览器数月不用会过期；SW `pushsubscriptionchange` 自动续订（D12）。若续订令牌也失效（401），需用户打开应用重新开启 |
| 私钥不匹配（换过密钥） | 全部订阅推送失败，报 403/404；按红线 1 处理：全员重新开启 |
| 渠道被限流 | 管线 `MaxPerMinutePerChannel=15`（每渠道每分钟）；超限合并捎带「另有 N 条未单独推送」 |

**监控建议**（可后续接系统日志分析）：推送成功率（`LastPushAtUtc` 非空且 `LastErrorCode` 为空的占比）、订阅数趋势、`LastErrorCode` 分布、SW 更新率。

## 六、用户使用说明要点

- **安装**：桌面 Chrome/Edge 地址栏安装图标或设置中心「安装到桌面」；Android Chrome 菜单「添加到主屏幕」；**iOS 必须先「添加到主屏幕」**（Safari 未安装态无推送能力，iOS 16.4+ 支持 PWA 推送）。
- **开启推送**：设置中心 → 推送通知 → 开启（浏览器弹权限询问需允许）。被拒后需到浏览器站点设置中手动恢复，页面不会重复弹窗。
- **离线模式**：断网时顶部黄条「离线模式 · 数据截至 HH:mm:ss」——此时间为最后一次快照落盘时刻，**非实时值**；恢复联网后数据自动刷新、横幅消失。离线状态下的写操作（配置修改/报警确认）不可用。
- **更新**：新版本发布后右下角出现「新版本已就绪」，点「立即更新」刷新进入新版；点「稍后」不影响当前操作，下次刷新时再次提示（系统**绝不会**自动重载页面，避免打断盯屏）。
