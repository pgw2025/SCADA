# 运行态弹窗（openPopup）方案设计 — 方案 A（v1.1 修订版）

> 适用范围：组态运行界面（`ScadaPlayerView`）点击图元弹出面板窗口。
> 决策结论：在既有事件系统上新增 `openPopup` 动作类型 + 全局 `PopupHost` 容器，复用现成的
> `vfd-motor-panel` 面板、权限逻辑与实时数据链路。全程仅前端改动，后端零改动。
>
> 版本：v1.1（已并入代码级评审修订，评审详情见 [02-评审修订记录.md](./02-评审修订记录.md)）
> 实施细节见 [03-实施计划.md](./03-实施计划.md)（5 阶段 16 步）。

---

## 1. 现状盘点（决定方案走向的四个事实）

| # | 事实 | 出处 |
| --- | --- | --- |
| 1 | 变频操作面板已存在：启/停/复位/设频/电流监控完整，且**内置操作员/管理员权限判断**（`hasWritePermission = ADMIN || OPERATOR`） | `VfdMotorPanelWidget.vue` |
| 2 | 电机图标（`motor`）是**纯展示 SVG，无任何点击逻辑**；所有点击由 `CanvasPanel` 分发到运行时宿主的事件系统 | `MotorWidget.vue` / `CanvasPanel.vue` |
| 3 | 已具备可复用基础，仅缺“弹窗”能力：权限（`canControlWrite` 集中计算 + 后端 `[Authorize(Roles)]` 兜底）、模态化示范（`SetValueDialog`）、事件系统（已有 `writeVar / navigate / runScript / setProp` 四类动作），事件配置经 `props.events` 随 `PropsJson` 落库 | `ScadaPlayerView.vue` / `hmiEventService.ts` / `EventPanel.vue` |
| 4 | 隐藏组件仍被渲染（`v-show`，非 `v-if`）且**不参与订阅过滤**：`boundDeviceIds` 遍历 `currentPage.components` 时不过滤 `visible`，因此页内隐藏面板的 `bindDeviceId` **天然已在订阅集合内** | `CanvasPanel.vue`（`v-show="isComponentVisible(...)"`）/ `ScadaPlayerView.vue` |

**核心结论**：本功能不是“做一个变频面板”，而是 **“给运行界面加一个弹出一个面板窗口”的通用能力**。
拆解为四件事：触发（电机点击）→ 内容（复用面板）→ 容器（弹窗宿主）→ 权限（Operator/Admin 操作）。

## 2. 方案选型对比

| 方案 | 思路 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| **A（采用）** | 事件系统新增 `openPopup` 动作 + 全局 `PopupHost` 模态容器，弹窗复用 `vfd-motor-panel` | 改动最小；面板/实时值/设备绑定/权限全复用；天然泛化（任意图元弹任意组件）；后端零改动 | 需补一个弹窗原语 + 一个事件配置字段 | ✅ 采用 |
| B | 每个可弹图元组件自包含内嵌弹窗 | 每个组件自闭环 | 不通用，“图标→面板”焊死，无法配置 | 不采用 |
| C | 运行时“面板页/子画面”窗口（类 WinCC/iFix） | 最像传统组态软件，所见即所得 | 基础设施成本最高，对本诉求过度设计 | 留作后续演进 |

## 3. 完整调用链与改动落点

```
电机图标点击
 └─ CanvasPanel.handleDragStart            → emit('componentEvent', motor, 'click')
     └─ ScadaPlayerView.handleComponentEvent
         └─ dispatchComponentEvent(motor,'click', eventCtx)     // eventCtx 由 ScadaPlayerView 注入
             └─ 新增 action.kind === 'openPopup'
                 └─ 调用 ctx.openPopup(sourceComponentId)          // 新增分发能力（可选成员）
                     └─ ScadaPlayerView 设置 activePopupId
                         └─ PopupHost 渲染模态（复用 HMIWidget）
```

**改动落点（全部前端，共 5 处）**：

| # | 文件 | 改动 | 新增/修改 |
| --- | --- | --- | --- |
| 1 | `Client/src/types.ts` | `HmiEventActionKind` 增加 `'openPopup'`；`HmiEventAction.params` 增加 `sourceComponentId` / `requireWritePermission` 字段 | 修改 |
| 2 | `Client/src/services/hmiEventService.ts` | `HmiEventDispatchContext` 增加**可选** `openPopup` 回调；`runAction` 增加 `openPopup` 分支（含权限拦截与宿主能力判空降级） | 修改 |
| 3 | `Client/src/components/EventPanel.vue` | `ACTION_KIND_META`、`addAction()` 参数初始化、动作参数模板、候选下拉、底部提示文案 | 修改 |
| 4 | `Client/src/components/PopupHost.vue`（新增）+ `Client/src/utils/componentDeviceRefs.ts`（新增） | 全局模态容器 + 组件设备引用收集纯函数 | 新增 |
| 5 | `Client/src/components/ScadaPlayerView.vue` | 弹窗状态与开/关函数、`eventCtx` 增加 `openPopup`、挂载 `PopupHost`、弹窗设备订阅差集并入/退订、切页自动关闭 | 修改 |
| 6 | `Client/src/components/ScadaTopologyView.vue`（编辑器预览宿主） | `previewEventCtx` 提供 `openPopup` 实现（预览态弹窗，与运行态同体验） | 修改 |

> 落点 6 为评审新增（P2）：`ScadaTopologyView` 也构造 `HmiEventDispatchContext`，若 `openPopup`
> 设为接口必填将导致预览宿主编译失败；本方案将其定为**可选成员**，预览宿主自行实现。
>
> 事件配置继续经 `props.events` 随 `PropsJson` 透传落库，持久化机制沿用既有，**后端零改动**。

## 4. 参数 schema（关键设计决策）

弹窗里那块面板如何引用，是比“加一个动作”更重要的取舍。

### 做法 X：按“组件类型 + 设备”新建面板
`{ panelType: 'vfd-motor-panel', deviceId, … }`，弹窗用 `HMIWidget` 现成渲染全新组件。

- ❌ 面板有 11 个点位变量 key（startVar / stopVar / resetVar / spFreqVar …），在事件面板里逐个配置既反人类，又与画布上的配置重复。

### 做法 Z：按“页内组件 id”引用（采用）
`openPopup { sourceComponentId: string; requireWritePermission?: boolean }`

1. 设计时往画面放一块 `vfd-motor-panel`（变量绑定、风格一次配好），建议置于**隐藏图层**（见 §8）；
2. 给任意电机图标配 `click → openPopup{ sourceComponentId: 该面板 id }`；
3. 弹窗用 `useWidgetBase` 那套 props 契约把该组件渲染为模态，设备绑定、实时值、权限**自动继承**。

- ✅ 面板配置只有一份、所见即所得；任意图元“点谁弹谁”、天然通用；
- ✅ 兑现事件系统注释里“点击按钮弹出报警面板”的预判；
- 预览时面板仍随画布；运行时才脱离画布浮为模态。

**候选组件范围**：事件面板下拉列出**当前页全部组件（排除触发组件自身）**，命名沿用
`setPropTargetOptions` 先例（`${c.name || c.type} (${c.id.slice(-6)})`）。不限定 `vfd-motor-panel`
一种——弹窗内容未来可以是 `multi-var-dashboard` 看板、`trend-chart` 趋势等任意组件。

## 5. PopupHost 组件设计

- **渲染**：复用 `HMIWidget.vue`（`builtinRenderers` 已将 `vfd-motor-panel` 映射到面板组件），
  传入**浅拷贝**的 `HMIComponent` descriptor，拷贝时强制：
  - `visible: true`（不继承源组件的隐藏状态，与项目“快照强制 visible”约束先例一致）；
  - `locked: false`（不继承组件级锁定）；
  - 剥离 `layerId`（不继承图层归属，与弹窗组件快照约束先例一致）；
  - `props` 浅拷贝一份，避免模态内交互污染画布源对象（`vfd-motor-panel` 本地仿真状态写的是自身 ref，不受影响）。
- **渲染契约**：`HMIWidget` 必传 `value`——`vfd-motor-panel` 不消费该 prop（自读 `devices` store），传 `0` 即可；
  `control-locked` 传 `!canControlWrite`，使带绑定变量的控件在非授权时显示既有锁标。
  ⚠️ 泛化边界：`trend-chart` 等依赖 `history`/`componentValues` 通道的组件在弹窗中无数据，
  首版不在候选下拉中做特殊适配（文档明示，后续按需扩展）。
- **布局 / z-index**：对齐项目既有弹窗约定（`SetValueDialog`）：`fixed inset-0 z-[100]`、
  `bg-black/50 backdrop-blur-sm`、flex 居中；**不使用 teleport**（父级无 transform 场景下 fixed 相对视口可靠，
  与 `SetValueDialog` 同款实现，减少一层心智负担）。PopupHost 必须是 `CanvasPanel` 的**同级兄弟节点**，
  绝不能套进画布缩放容器（否则随 `adaptMode` 缩放、文字失真）。
- **尺寸**：内容容器桌面 `w-[min(92vw,640px)]`、移动端 `w-[92vw]`；高度按面板组件原始宽高比或
  `min(80vh, 520px)` 封顶，内部 `overflow-auto`。
- **状态**：`ScadaPlayerView` 持 `activePopupId = ref<string | null>`；`openPopup(id)` 设值、`closePopup()` 清空。
  **单层弹窗**（一次只弹一个），重复点击同一面板**幂等**（已开则保持，不重复叠加）；多弹窗栈留作扩展点。
- **关闭**：右上角关闭按钮 + ESC + 点遮罩，统一走 `closePopup`；命令型面板无“未保存确认”。
- **标题栏**：显示源组件名/标签（如 `1# 变频主循环泵`），多电机页面可区分“这是几号泵”（评审可选优化项，低成本采纳）。

## 6. 实时值数据流（评审修正版）

### 6.1 已天然覆盖的部分
- 面板组件 `vfd-motor-panel` **不依赖** `props.value / componentValues`，自身从 `devices` store
  `readVar(...)` 实时读，值链路无问题。
- 做法 Z 下源面板位于**当前页** components 数组内；`CanvasPanel` 用 `v-show` 渲染隐藏组件，
  `boundDeviceIds` 遍历时**不过滤 visible**，因此源面板的 `bindDeviceId` **本来就已订阅**，
  无需额外补订。

### 6.2 既有缺口：变量级 deviceId 未入订阅（评审发现 P1）
`boundDeviceIds` 只收集四类设备引用：`bindDeviceId`、`rounded-btn` 的 `opDeviceId`、
`multi-var-dashboard` 的 `dashboardItems`、`trend-chart` 的 `trendSeries`——
**没有 `vfd-motor-panel` 分支**。而该面板有 11 个变量级独立设备引用
（`startDeviceId / stopDeviceId / resetDeviceId / readyDeviceId / runningDeviceId / faultDeviceId /
signalDeviceId / spFreqDeviceId / pvFreqDeviceId / currentDeviceId / opDeviceId`）。
只要用户为面板配置了跨设备变量绑定，**画布上的面板与弹窗内的面板数值都会 stale**——这是既有问题，
由本方案一并收口。

### 6.3 解决设计：通用设备引用收集器
新增纯函数 `collectComponentDeviceRefs(component): Set<number>`：
- 收集 `bindDeviceId`；
- 遍历 `props` 中所有**以 `DeviceId` 结尾且值为合法数字**的字段（自动覆盖上述 11 个变量级字段，
  未来组件新增 `xxxDeviceId` 字段自动生效，无需逐组件维护白名单）。

消费点两处：
1. **弹窗生命周期**（核心）：`watch(activePopupComponent)` 差集订阅——打开时对「收集集合 − 当前页已订阅集合」
   逐个 `subscribeDeviceTelemetry`；关闭/切页时对不再被引用的设备 `unsubscribeDeviceTelemetry`；
2. **`boundDeviceIds` 收口**（顺带修复既有缺口）：computed 内对每个组件调用收集器并入集合。

## 7. 权限设计

需求原文是“**只有操作员和管理员可以操作**”——针对“操作”，而非“看”。故默认：

| 层 | 语义 | 实现 |
| --- | --- | --- |
| 开窗 | **不拦**：全员可点开、只读查看 | `openPopup` 默认不设权限 |
| 操作 | **拦**：非 Operator/Admin 按钮置灰、点了仅提示 | 面板内部 `hasWritePermission`（已具备） |
| 兜底 | 写接口硬权限 | 后端 `[Authorize(Roles)]` |

**扩展到“非操作员连窗都打不开”**：`openPopup` 动作的可选 `requireWritePermission: boolean` 标志
（默认 false），在 `dispatchComponentEvent` 用现成 `ctx.canControlWrite` 前置拦截，两套语义一句话切换。
**推荐按“可看不可动”实现，标志位同步实现（成本低），默认关闭。**

> 调用链位置自洽性：事件分发位于 `CanvasPanel.handleDragStart` 中 `canControlWrite === false` 早退
> **之前**（交互事件优先分支），因此非授权角色点击可正常开窗只读查看，与“可看不可动”语义吻合。

## 8. 边界处理（评审补充 E1–E3）

| # | 边界场景 | 处理 |
| --- | --- | --- |
| E1 | **弹窗开着时切页**：nav-menu 跳转后 `sourceComponentId` 失效 | `watch(currentPage.id) → closePopup()`；订阅退订由 `activePopupComponent` 置 null 的 watch 自动完成 |
| E2 | **悬空引用**：EventPanel 配好后用户删掉面板组件 | 候选下拉只列当前页现存组件（沿用 `setPropTargetOptions` 先例，删除即从列表消失）；运行时 `openPopup` 找不到目标组件 → toast「弹窗目标组件不存在」+ 不开窗 |
| E3 | **PopupHost 渲染契约** | `HMIWidget` 必传 `value`（面板不消费，传 0）；浅拷贝强制 `visible:true / locked:false`、剥离 `layerId`；依赖 `history` 通道的组件（trend-chart）首版不适配，下拉不限制但文档明示 |
| E4 | **隐藏面板的渲染成本** | `v-show` 下隐藏组件仍在 DOM 运行（仿真定时器/订阅照常）。对弹窗是**利好**（面板热启、状态不丢），但一页塞多个隐藏面板有成本——**设计约定：面板放“隐藏图层”（图层级 visible）而非依赖组件级 visible**，两者渲染等价（同一 `isComponentVisible` 判定），图层方式更符合组态管理习惯 |
| E5 | **重复点击幂等** | `openPopup` 对同一 `sourceComponentId` 重复调用保持已开状态（防触摸屏连点叠加） |
| E6 | **预览宿主能力** | `ctx.openPopup` 为可选成员：预览宿主（`ScadaTopologyView`）实现同款弹窗获得一致体验；未实现的宿主 `runAction` 判空降级 `onBlocked('当前宿主不支持弹窗动作')`，不崩溃 |

## 9. 约束核对照（与项目既有硬性约定对齐）

| 关注点 | 结论 |
| --- | --- |
| 后端改动 | 无。`props.events` 已有的 `PropsJson` 透传落库机制，`openPopup` 参数随事件配置持久化 |
| 权限一致性 | 复用 `canControlWrite` + 面板 `hasWritePermission`，与既有写链路同一真相源 |
| 数据订阅 | 弹窗生命周期差集订阅/退订（§6.3）；顺带收口 `boundDeviceIds` 变量级设备既有缺口 |
| 快照约束先例 | 弹窗渲染的组件浅拷贝强制 `visible:true`、剥离 `layerId`，与弹窗组件快照既有约束一致 |
| 键盘快捷键约束 | 本功能不涉及 Ctrl+C/X/V/Z；`Ctrl+C/V` 剪贴板约束不受影响（弹窗仅运行态，运行态本就禁用快捷键） |
| 操作日志 | 开/关弹窗走 `addLog('组态运行', …)`，与既有交互日志同源 |
| z-index / 遮罩 | 对齐 `SetValueDialog` 既有约定：`fixed inset-0 z-[100]` |

## 11. 验收清单（最终版）

**功能**
- [ ] `openPopup` 动作可在事件面板配置，下拉引用页内组件，保存/重载后配置不丢失
- [ ] 点击触发组件弹出模态面板，标题显示源组件名
- [ ] 重复点击同一面板幂等（不叠加）
- [ ] ESC / 遮罩 / 右上角关闭三种方式均可退出

**数据**
- [ ] 弹窗实时值随设备刷新（含面板绑定设备不在当前页其余组件中的场景）
- [ ] 面板配置了跨设备变量级绑定（如 `spFreqDeviceId` 指向另一台设备）时弹窗数值实时
- [ ] 画布上的 `vfd-motor-panel` 跨设备绑定数值同样实时（既有缺口收口验证）
- [ ] 关闭弹窗后不再被引用的设备退订，无残留订阅

**权限**
- [ ] 非 Operator/Admin：可开窗查看，面板操作按钮置灰、点击仅提示
- [ ] 配置 `requireWritePermission=true` 时，非授权角色开窗被拦截并提示
- [ ] Operator/Admin：面板启/停/设频等写操作正常下发

**边界**
- [ ] 弹窗开着时 nav-menu 切页 → 弹窗自动关闭且退订
- [ ] 删除被引用面板后，触发点击给出「目标组件不存在」提示且不崩溃
- [ ] 编辑器预览态（isActiveMode）点击同样可弹窗（预览宿主）

**回归**
- [ ] 既有四类事件动作（writeVar/navigate/runScript/setProp）行为不回归
- [ ] `var-display` 设值弹窗（SetValueDialog）不受影响
- [ ] 桌面/移动双端弹窗布局正常，文字不被画布缩放失真
- [ ] `npm run build` 通过；`dotnet build` 通过（后端零改动，防御性确认）
