# 评审修订记录（v1.0 → v1.1）

> 评审对象：`01-方案设计.md` v1.0（2026-09-11）
> 评审方法：对照实际代码逐条核验方案假设——画布隐藏组件渲染/命中处理、既有弹窗定位约定、
> 预览宿主事件上下文、事件面板结构、渲染器注册表。
> 评审结论：**方案方向正确、可实施**；发现 3 处与代码事实不符需修正（P1–P3）、
> 6 处边界遗漏需补充（E1–E6）、2 项低成本可选优化；修订后形成 v1.1。

## 一、需要修正的问题（方案与代码事实不符）

### P1：§6 数据流分析不准确（最重要）

**v1.0 原判断**：被弹面板绑定设备不在当前页时不会被订阅，要求 PopupHost 把 `bindDeviceId` 并入订阅。

**代码核验事实**：
- `CanvasPanel.vue`（组件渲染循环）：`v-show="isComponentVisible(component)"`——隐藏组件**仍在 DOM、仍在 components 数组**；
- `ScadaPlayerView.vue`（`boundDeviceIds` computed）：遍历 `currentPage.components` 时**不过滤 `visible`**。

**结论**：做法 Z（页内隐藏面板）下，源面板的 `bindDeviceId` **本来就已订阅**，v1.0 要求的补订阅对该字段是多余的。

**真正的缺口（既有问题）**：`boundDeviceIds` 只收集 4 类设备引用（`bindDeviceId`、rounded-btn 的 `opDeviceId`、`dashboardItems`、`trendSeries`），**没有 `vfd-motor-panel` 分支**。该面板有 11 个变量级独立设备引用（`startDeviceId/stopDeviceId/resetDeviceId/readyDeviceId/runningDeviceId/faultDeviceId/signalDeviceId/spFreqDeviceId/pvFreqDeviceId/currentDeviceId/opDeviceId`），用户配置跨设备绑定后，**画布上的面板与弹窗内的面板数值都会 stale**——这是与弹窗无关的既有缺陷。

**v1.1 修订**：
1. 新增通用纯函数 `collectComponentDeviceRefs(component)`：收集 `bindDeviceId` + 遍历 `props` 中所有以 `DeviceId` 结尾的合法数字字段（自动覆盖 11 个变量级字段，未来组件新增字段自动生效）；
2. 弹窗生命周期用该收集器做**差集订阅/退订**；
3. `boundDeviceIds` computed 一并接入收集器，**顺带收口既有缺口**（落点见 03-实施计划 阶段 3）。

### P2：漏了改动落点——编辑器预览宿主 `ScadaTopologyView`

**代码核验事实**：`ScadaTopologyView.vue` 也构造 `HmiEventDispatchContext`（`previewEventCtx`，约 L854），
预览态（isActiveMode）交互事件同样经 `dispatchComponentEvent` 分发。若 `openPopup` 作为**必填**字段
加入接口，预览宿主**TS 编译失败**。

**v1.1 修订**：
1. `HmiEventDispatchContext.openPopup` 定为**可选成员**（`openPopup?: (sourceComponentId: string) => void`）；
2. `runAction` 的 `openPopup` 分支对 `ctx.openPopup` **判空降级**：`onBlocked('当前宿主不支持弹窗动作')`；
3. 预览宿主实现同款弹窗（`PopupHost` 复用），编辑器预览获得与运行态一致的体验（边界 E6）；
4. 改动落点表从 4 行扩为 6 行（含新增 util）。

---

### P3：z-index 与遮罩实现应直接对齐项目既有约定

**v1.0 原设计**：“z-60+”、“teleport 或 fixed 二选一”。

**代码核验事实**：项目已有弹窗标准答案——`SetValueDialog.vue`（约 L138）：
`fixed inset-0 z-[100] flex items-center justify-center bg-black/50 backdrop-blur-sm`，
直接挂在 ScadaPlayerView 根节点内，无 teleport，线上工作正常。

**v1.1 修订**：对齐 `fixed inset-0 z-[100]`，**不引入 teleport**（父级无 transform 场景下 fixed 相对视口可靠；
与既有弹窗同款实现，减少一层心智负担）。PopupHost 挂载位置定为 `CanvasPanel` 同级兄弟节点。

## 二、需要补充的边界（v1.0 遗漏 → v1.1 §8）

| # | 边界 | v1.1 处理 |
| --- | --- | --- |
| E1 | 弹窗开着时切页（nav-menu 跳转后 `sourceComponentId` 失效） | `watch(currentPage.id) → closePopup()`；退订由 `activePopupComponent` 置 null 的 watch 自动完成；验收清单补条目 |
| E2 | 悬空引用（配好事件后删除面板组件） | 候选下拉只列当前页现存组件（沿用 `setPropTargetOptions` 先例）；运行时找不到目标 → toast「弹窗目标组件不存在」+ 不开窗 |
| E3 | PopupHost 渲染契约细节 | `HMIWidget` 必传 `value`（vfd-motor-panel 不消费，传 0）；浅拷贝强制 `visible:true / locked:false`、剥离 `layerId`（对齐项目“弹窗组件快照”既有约束先例）；依赖 `history` 通道的组件（trend-chart）首版不适配并文档明示 |
| E4 | 隐藏面板渲染成本 | v-show 下隐藏组件仍持续运行（对弹窗是利好：热启、状态不丢），但多面板有成本 → 设计约定「面板放隐藏图层」而非组件级 visible（两者渲染判定等价，图层方式更符合组态习惯） |
| E5 | 重复点击幂等 | 同一 `sourceComponentId` 重复 `openPopup` 保持已开状态，防触摸屏连点叠加 |
| E6 | 宿主能力差异 | `ctx.openPopup` 可选 + 判空降级（与 P2 联动） |

## 三、评审确认无问题的部分

- 调用链设计：事件分发位于 `canControlWrite` 检查**之前**（CanvasPanel 交互事件优先分支），非授权角色可开窗只读——与“可看不可动”自洽；
- 做法 Z vs X 取舍（11 个点位变量在事件面板重复配置确实不可接受）；
- 权限三层（开窗不拦 / 面板内 `hasWritePermission` 置灰 / 后端 `[Authorize(Roles)]` 兜底）；
- 后端零改动判断（`props.events` 随 `PropsJson` 落库，前端透传机制已存在）；
- 单层弹窗先行、`requireWritePermission` 留扩展位；
- 渲染复用路径（`HMIWidget` → `builtinRenderers['vfd-motor-panel']`，注册已确认存在）；
- 事件面板 `pageComponents` prop 已由 `ScadaTopologyView` 传入（约 L1790），候选下拉无需新增数据通道。
