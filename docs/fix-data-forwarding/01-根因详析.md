# 01 根因详析

> 本文档对根因 A / B / C / D 做代码级走查，给出触发链路、证据与日志关键词，为 [02-修复方案设计.md](./02-修复方案设计.md) 提供依据。

## 转发链路回顾（公共上下文）

```
源变量变化（轮询/订阅/用户写）
  → VariableValueProcessor 锁内更新 + 回声抑制 + IsChanged
  → 仅当 (IsChanged && Value != null) 发布 VariableChangeEvent
  → VariableBindingEngine.OnVariableChanged（跳过 BindingWrite 来源）查索引 (源设备,源变量) → 目标列表
  → 入队 _writeChannel（Bounded 10_000，DropOldest，SingleReader）
  → DispatchLoopAsync 单消费者串行 → WriteTargetAsync
  → RuntimeManager.WriteVariableAsync（7 道校验 + 驱动写 + 5s 超时兜底）
  → 成功：内存值更新 + NotifyVariableUpdate + Publish(UserWrite) + 快照更新 + 审计
  → 失败：FailAsync 返回 (false, message)，调用方仅记 Warning，无重试
```

## 根因 A：目标写入失败且无重试

### 触发链路

1. `WriteTargetAsync`（`ScadaServer.Runtime/Bindings/VariableBindingEngine.cs:231-268`）调用 `rm.WriteVariableAsync(target.DeviceId, target.VariableKey, value, "变量绑定")`。
2. `WriteVariableAsync`（`RuntimeManager.cs:842-961`）顺序执行 7 道校验/写入：
   - `DeviceRuntimes.TryGetValue` 失败 → "设备不在运行中"（重连窗口 / 已移除）
   - 变量不存在 → "设备下不存在变量"
   - `vr.IsEnabled == false` → "变量已禁用"
   - `vr.IsReadOnly` → "变量为只读，禁止写入"
   - `runtime.Driver == null` → "设备驱动未就绪"（会话重建中）
   - `ConnectionState != Connected` → "设备未连接，无法写入"
   - 值越限（非 bool 且 `value < Min || value > Max`）→ "写入值低于下限/超过上限"
   - 驱动 `WriteAsync(...).WaitAsync(5s)` 超时 → "写入超时，底层写入仍在进行"
   - 驱动抛异常 → "写入失败: {Msg}"
3. `WriteTargetAsync` 对失败仅 `Interlocked.Increment(ref _writeFail)` + `LogWarning`，**无重试、无补偿、无告警**。

### 证据

- 失败路径在 `VariableBindingEngine.cs:258-266`（失败计数 + Warning / Error 日志），随后返回，队列继续处理下一条。
- 无任何"失败 → 重试 / 失败 → 入补偿队列"逻辑。
- 设备重连窗口（`ReconnectDeviceAsync` 路径 B 中 `DeviceRuntimes.TryRemove` → `_reconnecting` → 重新注册）内，目标设备短暂不在册，所有转发写入返回"设备不在运行中"。

### 与"有时候"现象的对应

- **偶发网络抖动 / 写超时 / 目标短暂离线** → 该次转发失败即丢，现象为"偶尔一条/一段不转发"。
- **源值越出目标变量 Min/Max** → 越限时失败、限内时成功，现象为"值大/小到一定程度就不转发"（高度吻合"有时候"）。

### 日志关键词

`变量绑定写入失败：{DeviceId}/{Key}：{Msg}`、`变量绑定写入异常：{DeviceId}/{Key}`、`写入超时`。

## 根因 B：规则在设备未就绪时创建 → 被跳过且永不重试

### 触发链路

1. `LoadAsync`（`VariableBindingEngine.cs:64-132`）从 `IDataConversionRepository.GetListAsync()` 取全部规则，逐条校验：
   - 源设备不在 `rm.DeviceRuntimes` → `LogWarning("变量绑定跳过：源设备 {DeviceId} 未运行")`，`continue`（:80-84）
   - 目标设备不在册 → 同样跳过（:85-89）
   - 源变量不存在 / 目标变量不存在 / 目标只读 → 跳过（:90-105）
2. `LoadAsync` 仅在以下时机被调用：
   - 服务启动：`RuntimeManager.InitializeAsync`（`RuntimeManager.cs:253`）
   - 规则增删改：`DataConversionController.cs:36/45/54`
3. **跳过后的规则没有任何重试加载机制**——设备随后上线/重连成功也不会重新触发 `LoadAsync`。

### 证据

- 控制器 `Create/Update/Delete` 均调用 `_bindingEngine.LoadAsync()`，但该重载是全量重建，**不包含"设备未就绪 → 稍后重试"的语义**。
- `RuntimeManager.RegisterDeviceAsync / ReconnectDeviceAsync / ReloadDeviceAsync` 均未触发绑定重载。
- `DeviceScheduler` 周期 tick（50ms）只处理设备派发/重连，与绑定引擎无交互。

### 与"有时候"现象的对应

- **新建/启停规则恰逢设备启动加载中或断线重连窗口** → 规则被静默跳过 → 之后"从未转发过"（不是偶发，是持续，直到再次增删改规则或重启服务）。

### 日志关键词

`变量绑定跳过：源设备 {DeviceId} 未运行`、`变量绑定跳过：目标设备 {DeviceId} 未运行`。

## 根因 C：目标变量只读/不存在/禁用 → 恒定不转发

### 触发链路

1. **保存期无校验**：`DataConversionAppService.Create/Update`（`DataConversionAppService.cs:53-83`）只做实体字段赋值 + 仓储持久化，**不校验**源/目标设备存在性、变量存在性、目标可写性。
2. **加载期静默跳过**：`LoadAsync` 对非法规则仅 `LogWarning` 跳过（见根因 B 的 4 类校验），不持久化、不反馈到前端。
3. **运行期重复失败**：即使规则被加载（例如目标变量配置被后续改为只读），`WriteVariableAsync` 每次写入都会失败并记 Warning。

### 证据

- `VariableRuntime.IsReadOnly`（`VariableRuntime.cs:84`）由 `EffectiveAccessMode == "Read"` 判定；`WriteVariableAsync` 第 4 道校验拦截。
- 前端 `DataConversionView.vue` 的目标变量下拉直接使用 `Object.keys(dev.variables)`（:96-100），**未过滤只读变量**，用户可无感选择只读变量建规则。
- `LoadAsync` 的跳过信息只进日志，`DataConversionController.GetAll` 返回的 DTO 无任何"加载状态/跳过原因"字段（`DataConversionDto` 仅 Id/Name/Source*/Target*/Active）。

### 与"有时候"现象的对应

- 若规则配置的目标变量只读/Key 拼写不一致 → **恒定不转发**（用户感知为"这条规则从来没生效过"，属于"有时候不转发"的"从不"子集）。

### 日志关键词

`变量绑定跳过：目标变量 {Key} 为只读`、`目标变量 {Key} 在设备 {DeviceId} 不存在`、`变量 [{Key}] 为只读，禁止写入`。

## 根因 D：回声抑制窗口误吞真实变化（多跳链特有）

### 触发链路

1. 绑定写入成功后，`WriteTargetAsync`（`VariableBindingEngine.cs:246-255`）记录：
   - `tv.LastBindingWriteValue = value`
   - `tv.LastBindingWriteTime = DateTime.UtcNow`
2. 目标变量采集回读时，`VariableValueProcessor.ApplyPolledAsync`（`VariableValueProcessor.cs:96-101`）与 `ApplySubscribedAsync`（:164-169）计算：

   ```
   echoWindowMs = max(vr.PollingIntervalMs, 1000) * 2
   isEcho = LastBindingWriteValue != null
            && (now - LastBindingWriteTime) <= echoWindowMs
            && ValueEquals(newValue, LastBindingWriteValue)
   IsChanged = !Equals(Value, PreviousValue) && !isEcho
   ```

3. `isEcho == true` → `IsChanged = false` → **不发布事件** → 下游（若目标变量又是另一条绑定的源）不再转发。
4. 配套问题：`WriteVariableAsync` 发布事件时 **Source 硬编码 `UserWrite`**（`RuntimeManager.cs:929-938`），而 `OnVariableChanged` 的 `evt.Source == BindingWrite` 分支（`VariableBindingEngine.cs:182`）**永远不会命中** → 绑定写入的回声会作为 UserWrite 事件再次进入引擎。

### 失效场景（多跳链 A→B→C）

| 时序 | 事件 | B 的 IsChanged | 结果 |
|---|---|---|---|
| t0 | 绑定写 B=X（内存 B.Value=X，LastBindingWriteValue=X） | — | 发布 UserWrite(B) → 引擎查 B → 无 B 出边？有：B→C → 写 C=X |
| t1 | 轮询回读 B：设备尚未生效，读到旧值 Y≠X | `Equals(Y,X)=false`，isEcho=false → **true** | 发布 Polling(B,Y) → 引擎 → 写 C=Y（陈旧值） |
| t2 | 设备生效，回读 B=X | `Equals(X,Y)`，isEcho=(X==X 且窗口内)=**true** → **false** | **事件被抑制** → C 收不到 X |

**结果：C 最终卡在陈旧值 Y；若 t1 的 Y 回读与 t2 的 X 回读间隔 > 一个轮询周期（写入生效延迟大），C 值错误持续。**

### 窗口内"真实变化到同值"被吞

绑定写 B=X 后窗口内（最长 `2×轮询间隔`，轮询 60s 时达 120s），B 被设备/外部真实改为 X（与绑定值恰好相同）→ 被误判为回声 → 漏转发。

### 与"有时候"现象的对应

- 仅多跳链（A→B→C…）场景出现；单跳链（目标无出边）无影响。
- 现象：下游值卡陈旧 / 偶发漏一跳。

### 日志关键词

无直接日志（静默抑制）；可通过绑定引擎 `GetStats()`（`VariableBindingEngine.cs:176-177`）观察 Success/Fail 变化辅助判断。

## 附加说明

- 根因 E（Source 硬编码 `UserWrite`）**经复审重新定性为「非缺陷」**：多跳传播恰恰依赖"绑定写入 → 发布 UserWrite 事件 → 再次进入引擎 → 立即写下游"这条链，`BindingWrite` 分支虽为死代码，但激活它会切断多跳。修复方案**放弃 Source 语义修正**（见 [02-修复方案设计.md](./02-修复方案设计.md) 根因 D 修订与 [04-方案评审与修订建议.md](./04-方案评审与修订建议.md) P0-1）。
- 根因 F（队列 DropOldest 丢最旧）、G（转发循环异常退出后永久停摆）不在本次范围，但 A 的重试/补写机制天然缓解 F；G 建议在阶段 2 顺手补一条循环异常自愈（见 03 文档阶段 2 可选任务）。
