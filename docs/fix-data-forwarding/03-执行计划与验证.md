# 03 执行计划与验证

> 分阶段落地，每阶段含改动范围、验收标准、回归清单。全部改动经 **单元测试 + 集成验证 + 回归** 三重把关。

## 阶段总览

| 阶段 | 内容 | 依赖 | 建议时长 |
|---|---|---|---|
| 阶段 1 | 根因 C：保存期校验 + 前端过滤 + 状态可见 | 无 | 1 天 |
| 阶段 2 | 根因 A：失败分类 + 重试 + 补写 + 越限策略 + 告警 | 阶段 1（FailureKind 与校验共用类型） | 1.5 天 |
| 阶段 3 | 根因 B：设备就绪重载 + pending 重试 | 阶段 1（SkipReasons 复用） | 1 天 |
| 阶段 4 | 根因 D：绑定写入后静默窗口（不做 Source 修正） | 阶段 2（失败分类/补写辅助验证） | 1 天 |

---

## 阶段 1：根因 C（保存期强校验 + 前端过滤 + 加载状态可见）

### 执行步骤

1. `DataConversionAppService` 注入设备/变量查询能力，`CreateAsync`/`UpdateAsync` 增加 5 项静态校验（设备存在且启用、变量存在且启用、目标可写——可写判定复用运行时 `EffectiveAccessMode`:Override 优先），失败抛业务异常（中文明确文案）。
2. 全局异常过滤器确认将业务异常转为 400（沿用项目现有约定，若无则补一个过滤器分支）。
3. 前端 `targetVariables` 过滤只读变量；`types.ts` / `dataConversionApi.ts` 同步 DTO。
4. 引擎 `LoadAsync` 收集跳过原因到 `SkipReasons` 快照；`DataConversionController.GetAll` 返回 `BindingStatus`/`SkipReason`；前端规则卡片展示"未生效（原因）"徽标。

### 验收标准

- [ ] 新建规则选择只读目标变量 → 后端返回 400，错误信息含"只读"，数据库无新记录。
- [ ] 前端目标变量下拉不含只读变量。
- [ ] 存量非法规则在列表页显示"未生效（原因：目标变量只读 / 变量不存在）"。
- [ ] 合法规则保存/更新行为与改造前一致（无回归）。

### 回归清单

- 规则增删改查全部用例（前端 DataConversionView 新建/编辑/删除/启停）。
- 设备/变量不存在时 `GetListAsync` 正常返回（不抛异常）。

---

## 阶段 2：根因 A（失败分类 + 有限重试 + 离线补写 + 越限策略 + 失败告警）

### 执行步骤

1. `VariableWriteFailureKind` 枚举 + `WriteVariableAsync` 失败路径携带 FailureKind（保持现有签名兼容）。
2. `WriteTargetAsync` 重试分类与指数退避（500ms/1s/2s 共 3 次）；可重试失败全部耗尽后入 `_pendingWrites`（每目标仅最新值）。消费前对同目标做"只保留最新值"合并，避免重试占用单消费者导致同目标条目积压。
3. 补写触发：订阅 `RuntimeManager.StatusChanged`（目标设备转 Online）+ 1s 定时扫描兜底；补写成功移除、失败保留并退避。
4. 越限策略：`DataConversion.OutOfRangePolicy`（默认 Clamp），`WriteVariableAsync` 按策略夹取或拒绝；Clamp 作用于工程值 `value`（夹取后走 `ToRaw`），夹取值统一回写 `vr.Value`/事件/审计；DTO/前端规则弹窗同步。
5. 连续失败告警（≥10 次 → `NotifySystemAlarmAsync`）+ `GetStats` 扩展（Pending/Dropped）。
6. （可选，顺手）`DispatchLoopAsync` 循环异常自愈：捕获异常后延时重建循环（修复根因 G 的"永久停摆"隐患）。

### 验收标准

- [ ] 模拟目标设备断开：源变化期间转发失败进入补写队列；设备恢复 Online 后**最新值**被补写，目标最终值正确（非陈旧值）。
- [ ] 模拟驱动写入超时（测试驱动注入延迟 > 5s）：重试 3 次后进入补写通道，无重复风暴。
- [ ] 源值越出目标 Min/Max：默认 Clamp 写入目标（目标值=Min/Max）；规则级 Reject 时记录失败且不写。
- [ ] 不可重试失败（只读/变量不存在）不进入重试与补写，日志一次 Warning。
- [ ] 连续失败 ≥10 次触发系统报警（可在通知中心看到）。
- [ ] 队列满载时不再静默：Dropped 计数在 stats 端点可见。

### 回归清单

- 单跳转发时序：源变化 → 目标写入，值与改造前一致（Clamp 规则下越限值除外，按预期行为变化）。
- 手动写入（HTTP 用户写）路径不受 FailureKind 重构影响。
- 设备重连流程（路径 A 会话级 / 路径 B 占位重建）正常。

## 阶段 3：根因 B（设备就绪触发重载 + pending 规则重试）

### 执行步骤

1. `LoadAsync` 将"设备未运行"类跳过规则放入 `_pending`（含原因与时间），"变量缺失/只读"类不进入（属阶段 1 拦截范围）。
2. `RuntimeManager.RegisterDeviceAsync` / `ReconnectDeviceAsync` 成功后触发 `_bindingEngine.LoadAsync()`（引擎内置 100ms 去抖 + 最小重载间隔 1s；环报警 `NotifyCycleAlarm` 增加进程内去重，仅环集合变化时推送）。
3. 新增 `RetryPendingAsync()`：对 pending 中设备已就绪的规则执行单条校验并入索引；`DeviceScheduler` tick 或定时器兜底调用。
4. 前端规则卡片对 pending 规则显示"等待设备就绪…"，就绪后自动刷新状态。

### 验收标准

- [ ] 场景：设备离线时新建规则 → 规则显示"等待设备就绪"；设备重连成功后规则自动变为生效，源值变化开始转发（无需重启/手动改规则）。
- [ ] 场景：服务启动时设备因连接失败注册为占位（NeedsReconnect）→ 重连成功自动补加载。
- [ ] 设备批量注册（10+ 台启动）只触发少量重载（去抖生效），启动耗时无显著劣化。
- [ ] 确定性非法规则（变量不存在）不进入 pending、不无限重试，状态显示"未生效（原因）"。

### 回归清单

- 服务冷启动全链路：InitializeAsync → LoadAsync → StartAsync 顺序与日志正常。
- 规则增删改触发的重载与设备触发重载并发时无异常（volatile 原子替换 + 在途队列不受影响）。
- 环检测（自环/多节点环）在重载后仍生效。

## 阶段 4：根因 D（绑定写入后静默窗口）

### 执行步骤

1. 明确**不做 Source 语义修正**（评审 P0-1），保留 `WriteVariableAsync` 现行为（恒以 `UserWrite` 发布事件），不做任何 Source 参数改动。
2. `VariableValueProcessor` 两处回声判定（`ApplyPolledAsync` / `ApplySubscribedAsync`）改为**仅窗口判断**：窗口内目标变量任何回读一律 `IsChanged=false`（不再比对 `LastBindingWriteValue`）。
3. 窗口上限：`echoWindowMs = min(max(PollingIntervalMs, 1000) * 2, 5000)` 或引入可配置上限。
4. `VariableRuntime` 时间戳字段语义调整（`LastBindingWriteValue` 降级为观测字段），确认无其他调用方依赖其值匹配语义。

### 验收标准

- [ ] 多跳链 A→B→C + 写入生效延迟：绑定写 B=X → 回读旧值 Y（窗口内，不污染 C）→ 回读新值 X（窗口内，不重复）→ 窗口过后 B 真实变化正常转发；C 全程不被覆盖为陈旧值。
- [ ] 单跳转发行为与改造前一致（静默仅影响回读重复发布，目标写入值不变）。
- [ ] 环检测、防回环仍生效；无自回声死循环（观察引擎 Success/Fail 计数稳定）。
- [ ] 窗口内 B 被外部真实源改到新值 Z：窗口内被短暂静默、窗口后正常转发（已知取舍，验证符合预期）。

### 回归清单

- 单跳 / 多跳 / 多源一目标 / 一源多目标 四类绑定拓扑全量验证。
- 轮询型与订阅型（OPC UA）目标设备的静默窗口行为。
- 前后端联调：规则列表状态徽标、越限策略选项、只读过滤。
- 性能：高频源变化（100ms 级）下队列/补写/重试无风暴，CPU/内存平稳。

- [ ] `dotnet build` 全解决方案无警告新增（Server）。
- [ ] `Client` `npm run build` 通过（类型同步）。
- [ ] 单元测试：`ScadaServer.Runtime.Tests`（绑定引擎 LoadAsync 跳过/pending/重载、WriteTargetAsync 重试分类与队列合并、回声静默窗口、Clamp/Reject）全绿。
- [ ] 集成测试：模拟离线恢复补写、写超时重试、多跳一致性。

- [ ] 存量数据兼容：现有合法规则零改动继续转发；存量非法规则在列表页可见原因（可编辑修正或删除）。

## 风险登记与缓解

| 风险 | 阶段 | 缓解 |
|---|---|---|
| 重试/补写改变转发时序与耗时 | 2 | 保留"最新值"语义、跳过同目标积压条目、指标监控 |
| 静默窗口内真实变化被短暂抑制 | 4 | 窗口上限 5s + 文档明示，后续可升级"首次命中提前结束静默" |
| 重载去抖不充分导致启动变慢 | 3 | 100ms 去抖 + 最小重载间隔 1s + 启动日志观测 |
| Clamp 改变数据语义（写值≠源值） | 2 | 默认 Clamp 但规则级可切换 Reject，前端明示 |
| Source 语义改动引发多跳断链 | 4 | 已明确不做 Source 修正（评审 P0-1），阶段 4 回归覆盖多跳一致性 |
