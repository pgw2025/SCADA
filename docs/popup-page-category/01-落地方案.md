# 弹窗画面 (Popup) 画面分类 落地方案

> 适用范围：为组态系统新增第三个画面分类 `Popup`（桌面 / 手机 / 弹窗），支持像编辑普通画面一样
> 新建并组态弹窗画面，运行态由事件动作以**模态窗口**整体调用显示。
> 状态：**方案 v1.1（已并入代码级评审修订，待确认，未实施）**。本方案基于对现有代码的只读核验撰写，
> 关键代码断言（`scadaApi.ts` 归一化丢失、`NormalizePlatform` 白名单、事件作用域缺口、模态层级冲突）
> 均已核实。评审详情见 [02-评审修订记录.md](./02-评审修订记录.md)；实施细节见 [03-实施计划.md](./03-实施计划.md)。

## 0. 结论速览

| 决策点 | 结论 |
| --- | --- |
| 是否需数据库迁移 | **零迁移**。`ScadaPage.Platform` 是纯 string 列（`nvarchar(16)` 默认 `'Desktop'`），无枚举转换/CHECK 约束/新列 |

## 1. 功能定位与目标

### 1.1 是什么、解决什么问题

"弹窗画面"是继"桌面 / 手机"之后新增的第三个画面分类（`platform = 'Popup'`）。它允许组态设计者像编辑普通主画面一样**新建并组态一张独立的完整画面**（可放任意组件、图层、背景、自适应适配、变量绑定），在运行态由事件动作以**模态窗口**形式整体调用显示。

解决的核心痛点：
- **设备多、组态自由需求**：现有一版"运行态弹窗"（`openPopup` 弹单个**页内组件**）能力有限——只能把隐藏在画布里的**一个组件**以模态弹出。当需要"点一台电机弹出一个含多组件、带完整布局的整屏控制/监视面板"（多表计 + 趋势 + 多按钮）时，单组件弹窗明显不够。
- **布局自由**：弹窗画面是独立画布，尺寸、背景、图层、适配由设计者完全掌控，无需再为"藏进画布的隐藏组件"做画布占位或图层管理。

### 1.2 对比现有"页内组件弹窗"方案

| 维度 | 现有 openPopup（弹组件） | 本方案（Popup 画面） |
| --- | --- | --- |
| 弹窗内容 | 当前主画面上的**单个组件**（HMIWidget） | **一整张画面**（嵌套 CanvasPanel 渲染多组件+图层+背景） |
| 布局能力 | 受限（单组件快照，尺寸固定弹窗壳） | 自由（独立画布尺寸/背景/图层/适配） |
| 数据源 | 复用主画面组件 PropsJson 绑定 | 复用弹窗页面各组件 PropsJson 绑定（独立于主画面） |
| 设备订阅 | 对源组件聚合补订 | 对**弹窗页面全部组件**聚合补订 |
| 适用场景 | 单面板（变频操作面板、设值） | 整屏操作/监视页、多设备汇总、趋势页面 |

### 1.3 未来如何共存

- **保留**：现有 `openPopup` 指向 `sourceComponentId`（弹组件）的行为与已保存配置**完全不变**，向后兼容。
- **扩展**：事件动作 `openPopup` 增加一种目标形态——指向 `panelPageId`（弹画面）。两者靠动作参数中的目标类型字段区分。
- **建议命名**：动作仍叫 `openPopup`（不新增 `kind`），UI 文案区分"弹组件 / 弹画面"；事件 schema 不变 `kind`，仅扩 `params`，保证旧配置零迁移。

## 2. 数据模型设计

### 2.1 `platform` 三值枚举影响面

`platform` 从二值扩展为 `'Desktop' | 'Mobile' | 'Popup'`。语义：
- `Desktop` / `Mobile`：运行主画面，分别由播放器按端检测作为默认落地页。
- `Popup`：**非运行主画面**，绝不出现在播放器 `runtimePages`；仅能被主画面（或其它层级）的事件动作以模态调用。

### 2.2 后端改动清单

| 文件 | 改动 | 说明 |
| --- | --- | --- |
| `Server/ScadaServer.Application/Services/ScadaPageAppService.cs` | `NormalizePlatform` 改为三值白名单 | 见下 |
| `Server/ScadaServer.Application/DTOs/ScadaPageDto.cs` | 仅更新 `Platform` 字段注释（`Desktop / Mobile / Popup`） | 属性仍是 `string` 无需改类型/长度（`Length(20)` 够） |
| `Server/ScadaServer.Domain/Entities/ScadaPage.cs` | 仅更新 `Platform` 属性注释 | 无 schema 变更 |
| `Server/ScadaServer.Infrastructure/Persistence/ScadaDbContext.cs` | **不改** | Column 已 `HasMaxLength(16)`、索引 `(ProjectId,Platform)` 仍有效 |
| 迁移文件 | **不需新增** | 见 §2.3 零迁移结论 |

`NormalizePlatform` 目标逻辑（保持回退良序，当前实现仅认 Mobile，见 L142）：

```csharp
private static string NormalizePlatform(string? platform)
    => platform?.Trim() switch
    {
        "Mobile" => "Mobile",
        "Popup" => "Popup",
        _ => "Desktop",
    };
```

### 2.3 是否零迁移 —— 结论与理由

**结论：零迁移（无需新增 EF Migration、无需改库）。**

理由：
1. `ScadaPage.Platform` 在实体、`DbContext` 配置、`ScadaDbContextModelSnapshot` 中**均为纯 `string` 列**（`HasMaxLength(16)`、`HasDefaultValue("Desktop")`），从不使用 EF 的 `.HasConversion` 枚举转换，也没有数据库 CHECK 约束或枚举列类型。
2. 因此"新增第三个合法字符串值"只在**应用层白名单**生效，数据库层面 `nvarchar(16)` 本就存得下 `'Popup'`（5 字符）。
3. 现有 `'Desktop'` / `'Mobile'` 存量行不受影响；`(ProjectId, Platform)` 索引无需变更。
4. 唯一隐性风险在**前端**：`scadaApi.ts fromPageDto` 把非 `'Mobile'` 一律归为 `'Desktop'`，会丢 Popup，必须同步改为三值透传（见 §3.1）。—— **该断言已核实，`scadaApi.ts` L246 确实写死该逻辑**。

### 2.4 前端 `ScadaPage` 类型扩展

`Client/src/types.ts` 中：

```ts
export interface ScadaPage {
  ...
  /** 画面归属端：Desktop（桌面端）/ Mobile（移动端）/ Popup（弹窗画面）。缺省回退 Desktop。 */
  platform?: 'Desktop' | 'Mobile' | 'Popup';
  ...
}
```

同时 `scadaStore.ts` 的 `currentPlatform` 需扩展为 `'Desktop' | 'Mobile' | 'Popup'`（见 §3.1）。

### 2.5 popup 画面是否 isHome、是否参数化 —— 建议

- **isHome**：**Popup 不设首页**。理由：Popup 不是运行主画面，播放器 `runtimePages` 不会落入 Popup，`isHome` 无意义。前端在"弹窗画面"分组不渲染"设为首页"操作；后端 `UnsetOtherHomePagesAsync` 本就按 `(ProjectId, Platform)` 维护唯一首页，Popup 即便被置位也无副作用，首版在前端层面避免即可。
- **deviceId 参数化**：**首版不做参数化，一设备一画面**。理由：
  - 弹窗画面上每个组件本来就可绑定自己的 `bindDeviceId`，设计者为不同设备"复制画面后改绑定"即达到一设备一画面的效果，无需代码支持。
  - 若首版硬做参数化，需要设计"打开时用调用侧 deviceId 覆盖画面里 N 个组件的绑定"的传播规则，语义复杂、易错。
  - **建议**：在 `HmiEventAction.params` 预留 `popupDeviceIds?: number[]` 字段与 `PopupPageHost` 的 `deviceOverride` 透传参数，但首版**不消费**（透传保持绑定不变）。参数化作为阶段 6 扩展项。

## 3. 前端改动清单（按阶段组织）

### 阶段 A：分类过滤与类型基础（数据层）

| 涉及文件 | 改动 |
| --- | --- |
| `Client/src/types.ts` | `ScadaPage.platform` 联合类型加 `'Popup'`；`HmiEventAction.params` 增加 `popupTargetType?: 'component' \| 'page'`、`panelPageId?: string`、`popupDeviceIds?: number[]`（预留） |
| `Client/src/store/scadaStore.ts` | ①新增 `popupPages` computed（过滤 `platform === 'Popup'`）；②`currentPlatform` 类型扩为 `'Desktop'\|'Mobile'\|'Popup'`；③`watch(selectedPageId)` 的 cast 同步三值 |
| `Client/src/api/scadaApi.ts` | `fromPageDto` 改为透传三值（**关键修复，L246**）：`platform: d.platform === 'Mobile' || d.platform === 'Popup' ? d.platform : 'Desktop'` |

**关键点**：播放器的默认端探测 `detectMobile`、`runtimePlatform`、`runtimePages`、`currentPage` **一律不受影响**——它们只用 `desktopPages` / `mobilePages`，Popup 天然被排除出运行主画面（这正是期望：Popup 只被动调用，不主动落地）。

### 阶段 B：事件动作服务扩展（hmiEventService）

`Client/src/services/hmiEventService.ts`：
- `HmiEventDispatchContext` 增加可选 `openPagePopup?: (pageId: string) => void`。
- `runAction` 的 `openPopup` 分支改为按目标类型分发：
  - 保留现 `canControlWrite` + `requireWritePermission` 前置拦截（两种模式共用）。
  - 若 `p.popupTargetType === 'page'` 且存在 `panelPageId`：调用 `ctx.openPagePopup?.(panelPageId)`（宿主未实现则 `onBlocked` 降级提示）。
  - 否则走原"弹组件"分支（读 `sourceComponentId` → `ctx.openPopup`），逻辑不变。

```ts
case 'openPopup': {
  if (p.requireWritePermission && !ctx.canControlWrite) { ctx.onBlocked?.('当前角色无弹窗操作权限'); return; }
  if (p.popupTargetType === 'page' && p.panelPageId) {
    if (!ctx.openPagePopup) { ctx.onBlocked?.('当前宿主不支持弹窗动作'); return; }
    ctx.openPagePopup(p.panelPageId); return;
  }
  // ★ 原"弹组件"逻辑原样保留
  const sourceId = p.sourceComponentId;
  if (!sourceId) return;
  if (!ctx.openPopup) { ctx.onBlocked?.('当前宿主不支持弹窗动作'); return; }
  ctx.openPopup(sourceId); return;
}
```

### 阶段 C：事件参数 UI（EventPanel.vue）

`Client/src/components/EventPanel.vue`：
- `addAction` 中 openPopup 默认参数补 `popupTargetType: 'component'`（保证旧动作不误伤）。
- openPopup 参数区改为**两级**：
  1. 目标形态下拉：`component`（页面内组件）/ `page`（弹窗画面）。
  2. `component` 模式 → 现有 `popupSourceOptions` 下拉（不变）。
  3. `page` 模式 → 新增 `popupPageOptions`（从 store `popupPages` 取，`{ id, name }`，排除当前页）下拉到 `params.panelPageId`。
- `requireWritePermission` 复选框两模式共用，放置不变。
- 帮助文案补充说明两种模式行为差异。

### 阶段 D：ModalShell 抽取 + 新增 PopupPageHost.vue（弹窗画面宿主）

**O1 修订**：先抽取 `Client/src/components/ModalShell.vue` 作为**共用模态壳**（标题栏 + X/ESC/遮罩关闭，
`fixed inset-0 z-[100]` 既有约定），供现有 `PopupHost.vue`（组件弹窗）与新 `PopupPageHost.vue` 复用——
避免两份关闭逻辑日后漂移。改造 `PopupHost` 复用 ModalShell 时**顺带补齐其既有缺陷**：
当前 HMIWidget 未接 `@request-set-value`，组件弹窗内 var-display 的设值请求被静默丢弃。

新建 `Client/src/components/PopupPageHost.vue`，职责是**在 ModalShell 里嵌套渲染一张弹窗画面**。

Props：
```ts
{
  page: ScadaPage;              // 被调用的弹窗画面
  canControlWrite?: boolean;    // 角色写权限（传给 CanvasPanel 与显示锁标）
  componentValues?: Record<string, number | boolean>;  // 弹窗页面实时值（宿主构建，严格复合键）
  componentQualities?: Record<string, any>;            // 质量标记（必做，见 §5-E2）
}
```
Emits（透传给内部 CanvasPanel 事件；**P1 修订**：由宿主按"弹窗作用域"处理，而非主画面处理器）：
```ts
'triggerToggleValue' | 'navigateToPage' | 'triggerRunScript' | 'componentEvent' | 'requestSetValue' | 'close'
```
实现要点：
- 外层壳 = `ModalShell`（标题取 `page.name`）；关闭交互（X / ESC / 遮罩）由 ModalShell 统一提供。
- 内容区嵌套一个 `CanvasPanel`：
  - `:components="page.components"` `:selectedId="null"` `:selectedIds="[]"` `:isActiveMode="true"`
  - `:component-values="componentValues"` `:component-qualities="componentQualities"`
  - `:canvas-width="page.width"` `:canvas-height="page.height"` `:can-control-write`
  - `:readonly="true"` `:background="page.background"` `:adapt-mode="page.adaptMode"` `:layers="page.layers"` `:current-page-id="page.id"`
  - 事件 `@triggerToggleValue / @navigateToPage / @triggerRunScript / @component-event / @request-set-value` 逐项上抛（**不接主画面处理器**，见阶段 E 作用域路由）。
- 内部写操作权限：`CanvasPanel` + 各控件内置 `hasWritePermission` 已自动继承 `canControlWrite`（权限见 §4）。

### 阶段 E：运行播放器（ScadaPlayerView.vue）—— 含 P1 事件作用域与 P2 模态治理

**P1 修订：弹窗作用域事件上下文（本方案最关键的架构补充）**

现状证据：`CanvasPanel` 上抛事件只带组件对象不带页面归属（L227-230）；播放器 `eventCtx`（L358）的
`applyRuntimePatch` / `openPopup` 均在 `currentPage.components`（主画面）解析目标（L366-377）；
`useHmiDataEvents`（L385-389）也只监听主画面组件。若直接复用主 ctx，弹窗画面内组件的 `setProp` 会
静默失效、`openPopup` 误报不存在、valueChange/alarm 数据事件不触发。

设计：
1. **`popupEventCtx`（第二上下文）**：与主 `eventCtx` 同构，差异仅在页面作用域成员——
   `applyRuntimePatch` / `openPopup`（组件模式）/ `openPagePopup` 的目标解析改为
   `popupPageToShow.value?.components`。设备级/全局级成员（`writeVariable` / `runScript` /
   `navigateToPage` / `onBlocked`）与主 ctx 共用同一实现。
2. **交互事件归属路由**：`handleComponentEvent` 增加归属判断——组件存在于 `currentPage.components`
   → 主 `eventCtx`；存在于 `popupPageToShow.components` → `popupEventCtx`（`dispatchComponentEvent`
   签名干净，直接传对应 ctx）。
3. **数据事件第二实例**：`useHmiDataEvents` 为可多实例 composable（内部 watch 随宿主卸载自动清理），
   为弹窗画面再挂一个实例：`components: () => popupPageToShow.value?.components ?? []` +
   `popupPageComponentValues` + `popupEventCtx`。弹窗未开时数组为空，watch 零开销。
4. **禁止嵌套**：`popupEventCtx.openPagePopup` 已开时幂等保持当前弹窗（首版单层栈）。

**P2 修订：三类模态互斥与层级治理**

1. **互斥规则**：`openPopup`（组件）/ `openPagePopup`（画面）/ 设值弹窗三者互斥——任一打开时先关闭
   其余两个（`handleRequestSetValue` 打开时同样清理弹窗态）；
2. **模板层级**：CanvasPanel → PopupPageHost → PopupHost → SetValueDialog（SetValueDialog 恒最上，
   或将其 z-index 提至 `z-[110]`，实施时二选一），修复"弹窗内设值对话框被遮蔽"。

其余集成点：
- 新增 `activePopupPage = ref<string | null>(null)` 与 `popupPageToShow` computed（从 `currentProject.pages` 中查 `platform === 'Popup'` 且 `id === activePopupPage`）。
- 实现 `openPagePopup(pageId)`：
  - 幂等：同 id 重复打开保持已开，不叠加；
  - 悬空引用：目标不存在/不是 Popup 页 → toast「弹窗画面不存在（可能已被删除）」并 log。
- **切页自动关闭**：扩展现有 `watch(() => currentPage.value?.id, ...)`，同时关闭 `activePopupPage`（与既有 `closePopup()` 合并为统一关闭）。
- **弹窗画面实时值**：构建 `popupPageComponentValues` 与 `popupPageComponentQualities`（对弹窗页面组件按 `bindDeviceId+bindVariableKey` 严格复合键取值，同现有 `componentValues` L151-177 逻辑，严禁裸 key），传入 `PopupPageHost`。
- **弹窗画面设备订阅差集**（复用 `collectComponentDeviceRefs` 思路）：
  - 新增 `watch(popupPageToShow)`，打开时对**弹窗页面全部组件**聚合 `collectComponentDeviceRefs`，对主订阅 `boundDeviceIds` 未覆盖的设备 `subscribeDeviceTelemetry`；关闭时退订"不再被任何层引用"的设备（逻辑与现有 `watch(activePopupComponent)` 一致，只是聚合对象从单组件换成整页组件数组）。
  - `onUnmounted` 兜底退订弹窗页设备，防订阅残留。
- 模板挂载：在 `PopupHost` 之后同级加 `<PopupPageHost v-if="popupPageToShow" :page="..." ... @close="activePopupPage = null" />`。

### 阶段 F：编辑器预览（ScadaTopologyView.vue）—— 含 P1/P2/P3 对称处理

- `switchPlatform` 仅用于 Desktop/Mobile 视口模拟，**不把 Popup 当作切换端**；select 弹窗页面时 `currentPlatform` 设为 `'Popup'` 渲染弹窗尺寸视口（复用现有 `watch(selectedPageId)` 同步，store L66-69 cast 同步三值）。
- 全屏快速切页 `optgroup` 增加"弹窗画面"分组（可选）。
- 预览态的 page-popup 宿主：与播放器**同模式**实现 `openPagePopup`、切页关闭、设备订阅差集、
  **P1 弹窗作用域 `previewPopupEventCtx` + 事件归属路由 + 数据事件第二实例**、**P2 模态互斥**；
  模板把 PopupPageHost 挂到预览容器同级。
- Popup 分组页面不渲染"设为首页"操作；复制/删除/更名等与现有 Desktop 页行为一致（`handleDuplicatePage` / `handleDeletePage` 已按 platform 通用，Popup 沿用）。

## 4. 权限设计

与现有 `openPopup` 完全对齐，弹画面作为其平行分支，无新增权限面：

## 5. 边界处理

| 边界 | 处理 | 责任方 |
| --- | --- | --- |
| 切页关闭弹窗 | 扩展现有 `watch(currentPage.id)`，弹组件与弹画面一并关闭；退订由订阅 watch 自动完成 | 播放器 / 预览 |
| **模态互斥与层级（P2）** | SetValueDialog / PopupHost / PopupPageHost 三者互斥（任一打开先关其余）；模板层级 CanvasPanel → PopupPageHost → PopupHost → SetValueDialog（或设值弹窗 z-[110]），防遮蔽与双层叠加 | 播放器 / 预览 |
| **弹窗内事件作用域（P1）** | 弹窗画面组件的 setProp/openPopup/数据事件经 `popupEventCtx` + 归属路由 + `useHmiDataEvents` 第二实例解析（详见阶段 E） | 播放器 / 预览 |
| 弹窗内再开弹窗 | **首版单层栈禁止嵌套**：`openPagePopup` 已开时若再触发，幂等保持当前不动（或 toast 提示）；嵌套多栈留给扩展（PopupPageHost 内事件上下文递归挂载 + 栈管理） | 播放器 / 预览 |
| 弹窗内的 navigate | 若弹窗页面组件配了 navigate，目标应解析在"弹窗页所属端"的同端画面；首版建议弹窗内 navigate 回主画面当前端→关闭弹窗并跳转，行为需在阶段 F 明确 | 播放器 / 预览 |
| 删除被引用弹窗画面 | **允许删除**（可复用现有删除），运行期 `openPagePopup` 做悬空引用兜底：目标不存在 → toast「弹窗画面不存在（可能已被删除）」+ log，不开窗；设计期不做引用计数强制（同 openPopup 悬空组件先例） | 后端删除不变 / 前端运行兜底 |
| 弹窗画面订阅差集 vs 主订阅 | 弹窗页设备订阅独立于 `boundDeviceIds`：打开时补订差集、关闭时退订"不再被引用"设备；`onUnmounted` 兜底清理，防残留 | 播放器 / 预览 |
| **趋势图等 history 组件（E1）** | trend-chart 等依赖 history 数据通道的组件，弹窗画面内取数路径需实测；首版不保证，列入回归验证 | 播放器 / 预览 |
| **质量标记（E2）** | `componentQualities` 必做（非可选）：与主画面质量警示行为不一致会造成运行人员误解 | 播放器 / 预览 |
| Popup 页面"设为首页" | 前端弹窗分组不提供该操作；后端 `(ProjectId,Platform)` 唯一首页约束天然兼容，无副作用 | 前端隐藏 |
| `fromProjectFullDto` 归一化丢失 | `fromPageDto` 必须改为三值透传，否则 Popup 页刷新后变 Desktop | 前端 scadaApi |
| **工程导出/导入（E3）** | platform 随页面透传零改动，回归清单显式验证一条 | 回归 |
| **空弹窗画面（E4）** | 打开无组件的弹窗画面正常渲染空壳（验收项列出即可） | 回归 |

## 6. 与现有 openPopup 的兼容

- **动作类型**：不新增 `kind`，仍为 `openPopup`。现有已落库配置的 `params`（含 `sourceComponentId`）原样保留、行为不变。
- **判别**：以新增参数 `popupTargetType` 区分（`'component'` 默认 = 旧行为；`'page'` = 弹画面）。旧配置无该字段，`?? 'component'` 回退旧行为。
- **向后兼容**：`EventPanel` 读取旧动作时 `popupTargetType` 缺省为 `'component'`，渲染旧 UI，不破坏已保存配置。
- **并行**：同一事件动作链可同时含"弹组件"与"弹画面"两个 openPopup 动作（顺序执行），两者互不干扰。
- 后端事件 `PropsJson` 整体透传，**零 schema 影响**。
