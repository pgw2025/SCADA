## 三、实施中的决策偏差

1. **第二个 NormalizePlatform 漏网点（后端导入）**
   - 计划以为仅 ScadaPageAppService 一处。实施时 grep 发现 ScadaProjectAppService 还有一处两值版，
     由工程/画面导入复用，会把 Popup 归一为 Desktop。已改为三值。此为风险清单"Popup 被漏网两值判断吞掉"的实证，
     但在导入路径而非前端解析路径。

2. **HMIWidget 不 emit requestSetValue**
   - PopupHost 改造按计划给 `HMIWidget` 挂 `@request-set-value`；但 HMIWidget 为瘦分发器本身不声明/触发该事件。
     该绑定为无害透传监听（不产生副作用），保留以对齐计划语义；真正设值链路由宿主（播放器/预览）把宿主
     `PopupHost` 的 `@request-set-value` 接到 `handleRequestSetValue`，而 CanvasPanel 侧的 var-display 点击
     分发原生就位，故功能路径不受此影响。

3. **编辑器预览质量标记**
   - 编辑器主画面原本未透传 `componentQualities` 到 CanvasPanel（仅播放器做质量角标）。为与播放器对称，
     弹窗画面在编辑器预览中额外构建并透传 `popupPageComponentQualities`（E2 在新功能上满足，主画面保持原状）。

4. **订阅差集防误退订策略**
   - 因 P2 保证两类弹窗（PopupHost/PopupPageHost）**互斥**，组件弹窗与画面弹窗不同时出现，二者订阅 watch
     分别对主订阅 `boundDeviceIds` 求差即可安全退订，无需额外维护两者设备并集。代码以注释固化该不变量。

## 五、遗留项 / 扩展空间（首版不做）

1. **禁嵌套**：首版单层弹窗，弹窗画面内再开弹窗画面被幂等拦截（D9）。
2. **deviceId 参数化**：`popupDeviceIds` 已预留字段不消费，多设备复用同一弹窗模板留后续。
3. **设值完成自动重开弹窗**：P2 语义是"先关弹窗再设值"，体验上设值完成后需用户重点按钮重开，可作增强。
4. **历史组件入弹窗画面**（trend-chart 等）：未在首版专项验证（E1 允许文档明示结论）。
5. **嵌套 CanvasPanel 性能**：弹窗画面组件数较多时的适配缩放性能，需真机观察，必要时限定组件数。
