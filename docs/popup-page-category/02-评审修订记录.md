## 一、需要修正的设计缺口

### P1（架构级）：弹窗画面内组件的事件目标会解析到**主画面**作用域

**v1.0 原设计**：阶段 D 写"弹窗画面事件向上冒泡，由宿主复用既有处理器"。

**代码核验事实**（证据链）：
- `CanvasPanel.vue` L227-230：事件上抛只带组件对象——`emit('componentEvent', component, 'click')`，**不带页面归属**；
- `ScadaPlayerView.vue` L380-382：`handleComponentEvent` → `dispatchComponentEvent(component, eventType, eventCtx.value)`，而 `eventCtx`（L358）的 `applyRuntimePatch` 在 `currentPage.value?.components`（**主画面**）里找目标（L366-377），`openPopup`（组件模式）的 `sourceComponentId` 同样只在主画面解析；
- `ScadaPlayerView.vue` L385-389：`useHmiDataEvents({ components: () => currentPage.value?.components ?? [] … })` ——**数据事件（valueChange/alarm）也只监听主画面组件**，弹窗画面组件的数据事件根本不生效。

**后果**：弹窗画面里的组件若配了 `setProp{targetComponentId=弹窗页内组件}` 会**静默失效**（主画面找不到目标直接 return）；配了 `openPopup{sourceComponentId}` 会误报"组件不存在"；配了 valueChange/alarm 数据事件则完全不触发。

**v1.1 修订**：
1. **弹窗作用域事件上下文**：播放器/预览宿主各构建第二个 `popupEventCtx`，其 `applyRuntimePatch` / `openPopup` / `openPagePopup` 均在 `popupPageToShow.components` 内解析目标；
2. **交互事件路由**：`handleComponentEvent` 增加归属判断——组件不在 `currentPage.components` 而在弹窗画面 `components` 中 → 分发到 `popupEventCtx`（`dispatchComponentEvent(component, type, ctx)` 签名干净，可直接传第二 ctx）；
3. **数据事件第二实例**：`useHmiDataEvents` 为可多实例 composable（内部 watch 随宿主组件卸载自动清理），为弹窗画面再挂一个实例，传入 `popupPageComponents` + `popupPageComponentValues` + `popupEventCtx`；
4. `writeVar` / `runScript` / `navigate` 为设备级/全局级动作，**不受作用域影响**，共用同一实现（文档明示）；
5. 预览宿主（`previewEventCtx`）对称处理。

### P2：三类模态会互相打架（层级与互斥都没治理）

**v1.0 原设计**：`activePopupId`（组件弹窗）与 `activePopupPage`（画面弹窗）为独立 ref；`SetValueDialog`、`PopupHost`、`PopupPageHost` 全部 `z-[100]`。

**后果**：
- **遮蔽 bug**：弹窗画面里的 var-display 触发设值弹窗时，`SetValueDialog`（模板中 DOM 在前）会被 `PopupPageHost`（DOM 在后、同 z-index）**盖住**——用户点设值却看不到对话框；
- **并存 bug**：组件弹窗与画面弹窗可同时打开，两层模态叠加。

**v1.1 修订**：
1. **单层模态规则**：打开任一弹窗先关闭其它（互斥）——`openPopup` / `openPagePopup` / 设值弹窗打开时统一清理其余二者；
2. **模板层级排序**：CanvasPanel → PopupPageHost → PopupHost → SetValueDialog（SetValueDialog 恒在最上，或提升为 `z-[110]`，实施时二选一）。

**顺带发现一个现网既有缺陷**：`PopupHost.vue`（已上线的组件弹窗）渲染 HMIWidget 时**没接 `@request-set-value`**——组件弹窗内 var-display 的设值请求被静默丢弃。本次实施阶段 3 改造 PopupHost 复用 ModalShell 时**一并补齐**。

### P3：编辑器 `currentPlatform` 三值化的连带改动盘点不全

**v1.0 原设计**：仅提 store L68 一处 cast。

**代码核验事实**——共 **5 处**硬编码两值的位置（`ScadaTopologyView.vue`）：

| 位置 | 现状 | 修订要求 |
| --- | --- | --- |
| L960 | `PAGE_SIZES: Record<'Desktop' \| 'Mobile', …>` | 键类型扩三值，补 Popup 默认尺寸（建议 600×450） |
| L964 | `handleAddPage(platform: 'Desktop' \| 'Mobile' = 'Desktop')` + L983 赋值 | 签名扩三值 |
| L1003 | 选页时 `(target.platform ?? 'Desktop') as 'Desktop' \| 'Mobile'` 强转 | cast 扩三值 |
| L1543-1547 | 平台切换按钮高亮判断 | Popup 时两个按钮都不亮——定义行为：**选中弹窗页时禁用端切换按钮** |
| L1650-1652 | 移动端视口包装判断 | `'Popup' !== 'Mobile'` 天然走桌面式渲染，**明示为预期**并写入文档 |

外加 store 侧：`currentPlatform`（L47）类型扩展 + `watch(selectedPageId)`（L66-69）cast 同步三值。

## 三、经核验确认成立的部分（无需修订）

- ✅ **零迁移结论**：`ScadaPage.Platform` 纯 string 列（`HasMaxLength(16)`），`NormalizePlatform`（L142）确只认 Mobile；
- ✅ **`fromPageDto` L246 吃掉 Popup**：已实证 `platform: d.platform === 'Mobile' ? 'Mobile' : 'Desktop'`——全方案最有价值的预警点；保存链路（L193 `pg.platform ?? 'Desktop'`）为透传、无需改，判断准确；
- ✅ **Popup isHome 无副作用**：`UnsetOtherHomePagesAsync`（L167-173）确按 `(ProjectId, Platform)` 分域，Popup 自成首页命名空间；
- ✅ **runtimePages 天然排除 Popup**：`desktopPages`/`mobilePages` 过滤（store L60-63）已核，播放器端探测逻辑不受影响；
- ✅ **popupPageComponentValues 严格模式**与 `componentValues`（L151-177）设计一致（复合绑定 + 裸 key 禁止）；
- ✅ **兼容策略**：`popupTargetType ?? 'component'` 回退旧行为，旧 openPopup 配置零影响；
- ✅ **权限三层复用**（requireWritePermission 门禁 / 控件内置 hasWritePermission / 后端 Authorize）。
