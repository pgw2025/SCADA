# 03 · 详细设计

> 代码块均为**设计草图**（接口签名与关键逻辑以 C# 表达意图），实施时以现仓风格为准（注释中文、XML 文档注释沿用既有惯例）。
> 所有路径基于 `Server/` 目录。

***

## 1. 目标架构总览

```
RuntimeManager
 ├─ ConnectionSessions : ConcurrentDictionary<int /*ConnectionId*/, ConnectionSession>
 │     ├─ ConnectionSession (IRuntimeConnection)          ← 一个连接配置一条物理连接
 │     │     ├─ Driver : IProtocolDriver                 ← 唯一驱动实例（S7/OpcUa/Virtual）
 │     │     ├─ MountedDevices : ConcurrentDictionary<int /*deviceId*/, DeviceRuntime>
 │     │     └─ 会话状态（连接级）+ 扇出 + 重连闸门
 │     └─ ...
 ├─ DeviceRuntimes : ConcurrentDictionary<int /*deviceId*/, DeviceRuntime>   ← 保留，对外快照/写链路不变
 │     └─ DeviceRuntime
 │           ├─ Session : ConnectionSession?             ← 新增：设备→会话反向引用
 │           ├─ Driver  => Session?.Driver                ← 改造：转发属性（原实例字段删除）
 │           └─ Variables / 报警计数 / RunState / Lock / Worker 生命周期  ← 全部不变

DeviceScheduler / DeviceWorker                              ← 结构不动
 └─ 每设备一个 Worker，轮询本设备变量，调用 session.Driver（并发安全由驱动自身保证）
```

**不变式（改造后必须恒真）**：
1. 同一 `ConnectionId` 至多一个 `ConnectionSession`、至多一个驱动实例、至多一条物理连接；
2. 任一时刻每个 `DeviceRuntime` 至多挂载于一个会话（重载期间旧挂载先卸载）；
3. 设备运行时（变量值/报警计数/RunState）不随会话重建而重建；
4. 快照 DTO、历史写入（InfluxDB tag：`device_key`+`variable_key`）、SignalR 推送格式零变化。

## 2. IRuntimeConnection（P1）

```csharp
namespace ScadaServer.Domain.Interfaces
{
    /// <summary>
    /// 连接运行时只读视图（"RuntimeConnection"）。
    /// 连接级单例改造的领域抽象：驱动连接时只依赖本接口，不再感知设备。
    /// 多设备共享同一物理连接；连接参数真相源为 DeviceConnection。
    /// </summary>
    public interface IRuntimeConnection
    {
        /// <summary>连接配置 ID（DeviceConnection.Id）。</summary>
        int ConnectionId { get; }

        /// <summary>连接配置业务键（DeviceConnection.Key，日志定位用）。</summary>
        string Key { get; }

        /// <summary>连接配置 JSON（DeviceConnection.ConfigJson，单真相源）。</summary>
        string ConfigJson { get; }
    }
}
```

`IProtocolDriver` 仅两处改动：

```csharp
// 旧
Task<bool> ConnectAsync(IRuntimeDevice device);
// 新
Task<bool> ConnectAsync(IRuntimeConnection connection);

// P3 新增（仅用于重连判定，非读写前置条件）
Task<bool> IsAliveAsync();
```

驱动侧适配面（已核实为全部使用点）：

| 驱动 | 现用成员 | 适配 |
|---|---|---|
| S7Driver | `device.ConfigJson`（L155）、`device.Key`（L191 起，日志与 `_deviceKey`） | → `connection.ConfigJson` / `connection.Key`，`_deviceKey` 更名 `_connectionKey` |
| OpcUaDriver | `device.ConfigJson`（L121）、`device.Key`（L135，日志） | → 同上 |
| VirtualDriver | `device.ConfigJson`（L39）、`device.Id`（L65） | → `connection.ConfigJson` / `connection.ConnectionId` |

P1 过渡期 `RuntimeManager` 用轻量适配对象喂驱动（从 `device.Connection` 取值），P2 起由 `ConnectionSession` 本体取代。

## 3. ConnectionSession（P2）

```csharp
namespace ScadaServer.Runtime.Connections
{
    /// <summary>
    /// 连接会话：一个 DeviceConnection 对应一条物理连接（进程内单例）。
    /// 职责：持有驱动实例；挂载/卸载设备（引用计数生命周期）；
    /// 连接状态扇出到挂载设备；会话级重连归口（闸门+探测+重建）。
    /// 不职责：轮询调度（DeviceScheduler/DeviceWorker）、报警判定、历史落库。
    /// </summary>
    public class ConnectionSession : IRuntimeConnection, IAsyncDisposable
    {
        private readonly DeviceConnection _connection;   // 配置实体（ConfigJson 真相源）
        private readonly string _protocolKey;
        private readonly IProtocolDriverFactory _driverFactory;
        private readonly ILogger _logger;

        // 驱动实例：仅在会话生命周期方法内替换（Connect/Reconnect/Dispose），读写路径经只读引用
        private volatile IProtocolDriver? _driver;
        public IProtocolDriver? Driver => _driver;

        // 挂载设备：key = deviceId。挂载/卸载与会话销毁互斥由 _lifecycleLock 串行化。
        private readonly ConcurrentDictionary<int, DeviceRuntime> _mounted = new();
        private readonly SemaphoreSlim _lifecycleLock = new(1, 1);   // 按项目约定永不 Dispose

        // 会话连接状态：setter 扇出
        private DeviceConnectionState _state;
        public DeviceConnectionState State
        {
            get => _state;
            private set
            {
                if (_state == value) return;
                _state = value;
                StateChangedAt = DateTime.UtcNow;
                foreach (var rt in _mounted.Values)
                    rt.ConnectionState = value;      // 复用设备既有 ConnectionStateChanged 事件链
            }
        }

        // 重连闸门（Interlocked 0/1）与失败聚合计数（P3）
        private int _reconnecting;
        private int _failureSignals;

        public int ConnectionId => _connection.Id;
        public string Key => _connection.Key;
        public string ConfigJson => _connection.ConfigJson ?? "{}";
    }
}
```

### 3.1 状态机

```
Created ──ConnectAsync──► Connected ──断连判定(探测死)──► Reconnecting ──┬─成功──► Connected
   │                        │                                        └─失败──► Fault(待重连，退避)
   └──ConnectAsync 失败──► Fault ──────────退避重试──────────────────────┘
任意状态 ──末位设备卸载──► Disposed（驱动 DisposeAsync，终态）
```

- `Connected/Fault` 语义对齐现有 `DeviceConnectionState`；`Reconnecting` 为会话内部瞬态，扇出到设备仍呈现 `Error`；
- 设备快照的 `ConnectionState` 完全来自扇出，DTO 不变。

### 3.2 挂载/卸载（引用计数生命周期）

```
MountAsync(runtime)：
  生命周期锁内：
    挂载表 Add/Replace(runtime)
    runtime.Session = this
    若驱动已连接：runtime.ConnectionState = Connected（首次挂载即在线）
  （会话不存在则由 RuntimeManager 先建：CreateDriver → ConnectAsync → 成功建会话；失败 → 不建会话，设备走占位路径）

UnmountAsync(deviceId)：
  生命周期锁内：
    runtime = 挂载表 Remove(deviceId)；runtime.Session = null
    runtime.CancelWorker() + 等待 WorkerTask 收尾（沿用 RemoveDeviceAsync 现有顺序）
    若挂载表为空：DisposeAsync 驱动 → 从 ConnectionSessions 移除 → State = Disposed
```

**幂等性**：重复挂载同设备 = 替换引用（重载路径）；卸载不存在的设备 = no-op。

### 3.3 启动装配（RuntimeManager.StartAsync 改造）

```
1. 加载启用设备（含 Connection 导航）→ 过滤 Connection == null（警告+跳过，行为同现状）
2. 过滤 connection.IsEnabled == false（P3.4 生效；P2 期可先不启用该过滤，避免行为耦合）
3. 按 ConnectionId 分组
4. foreach 组：
     session = GetOrCreateSession(connection)   // CreateDriver + ConnectAsync(connection)
     成功 → 组内逐设备 Mount（复用现有变量构建/状态初始化/报警计数回填逻辑）
     失败 → 不建会话；组内逐设备注册占位运行时（NeedsReconnect=true，Error）——语义同现状
```

`BuildAndRegisterDeviceAsync` 拆为两段：**设备运行时构建**（不变）与**驱动获取**（改为 `GetOrCreateSession + Mount`）。运行期单设备注册/重载同路径。

### 3.4 DeviceRuntime 改动（最小化）

```csharp
// 新增
public ConnectionSession? Session { get; set; }

// 旧：public IProtocolDriver Driver { get; set; } = null!;
// 新：转发属性（Worker/WriteVariableAsync 的 Driver 消费点零改动）
public IProtocolDriver? Driver => Session?.Driver;
```

> 转发属性天然覆盖写入门禁 `runtime.Driver == null`：无会话/会话无驱动 → null。
> 注意 `Driver` 返回值是**瞬时快照**——长循环内不得缓存（Worker 现状每次循环重新读 `_runtime.Driver`，满足要求；P5 批读实现时同样遵守）。

## 4. 会话级重连归口（P3）

### 4.1 信号上抛（Worker 侧唯一改动）

```csharp
// DeviceWorker 断线判定点（ConsecutiveFailureCount >= ReconnectAfterConsecutiveFailures）
_runtime.NeedsReconnect = true;
_ = _runtime.Session?.SignalConnectionFailureAsync(_runtime.Device.Id);   // 新增：fire-and-forget
break;
```

### 4.2 会话侧判定与重建

```csharp
public async Task SignalConnectionFailureAsync(int sourceDeviceId)
{
    // 聚合计数（Interlocked）；窗口语义：任一设备连续失败即视为会话候选故障
    Interlocked.Increment(ref _failureSignals);
    if (Interlocked.CompareExchange(ref _reconnecting, 1, 0) != 0)
        return;                                     // 闸门：已有重建在途，去重（多设备并发触发收敛为一次）

    try
    {
        // 探测确认：连接仍活 → 设备级问题（如地址全配错），不重建（修复现状 flapping）
        var driver = _driver;
        if (driver != null && await driver.IsAliveAsync())
        {
            Interlocked.Exchange(ref _failureSignals, 0);
            _logger.LogWarning("连接 {Key} 收到设备 {DeviceId} 断线信号，但探测连接存活，判定为设备级故障，不重建会话。", Key, sourceDeviceId);
            Interlocked.Exchange(ref _reconnecting, 0);
            return;
        }

        await ReconnectCoreAsync(sourceDeviceId);
    }
    catch { Interlocked.Exchange(ref _reconnecting, 0); throw前兜底日志; }   // 实施时按日志约束完整化
}

private async Task ReconnectCoreAsync(int sourceDeviceId)
{
    // 顺序硬约束（D5）：
    // 1. 扇出 Error + 取消挂载 Worker + 等待 WorkerTask 收尾（杜绝「Worker 用着旧驱动时被拆除」）
    State = DeviceConnectionState.Error;            // 扇出
    foreach (var rt in _mounted.Values) { rt.NeedsReconnect = true; rt.CancelWorker(); }
    await Task.WhenAll(_mounted.Values.Select(rt => rt.WorkerTask ?? Task.CompletedTask));

    // 2. Dispose 旧驱动
    if (_driver != null) await _driver.DisposeAsync();

    // 3. 新驱动建连（连接参数从 _connection 取，配置热更新后即新值）
    var newDriver = _driverFactory.CreateDriver(_protocolKey);
    var ok = false;
    try { ok = await newDriver.ConnectAsync(this); } catch (Exception ex) { 日志(Warning, 含 Connection 上下文); }
    if (!ok) { await newDriver.DisposeAsync(); 退避排期重试（ReconnectIntervalMs）; return; }

    // 4. 换驱动 + 扇出 + 复位（设备运行时不重建 → 变量值/报警计数/RunState 存活）
    _driver = newDriver;
    Interlocked.Exchange(ref _failureSignals, 0);
    foreach (var rt in _mounted.Values)
    {
        rt.ConsecutiveFailureCount = 0;
        rt.NeedsReconnect = false;      // Worker 已停；调度器按 IsRunning=false 自然重派
    }
    State = DeviceConnectionState.Connected;
    Interlocked.Exchange(ref _reconnecting, 0);
}
```

### 4.3 调度器协作（零结构改动）

- 调度器发现 `NeedsReconnect` → `ReconnectDeviceSafelyAsync(deviceId)`（现状不变）；
- `RuntimeManager.ReconnectDeviceAsync(deviceId)` 改为**转发**：`runtime.Session?.ReconnectAsync()`；无会话（初始建连失败）→ 走原「重建会话再挂载」路径；
- 多设备同时触发 → 闸门收敛为一次重建；退避期间重复触发被闸门吞掉。

### 4.4 进程级 ReconnectCount（对齐 N-2 基线）

- 语义从「设备重连次数」升级为「会话重建次数」，仍由 RuntimeManager 进程级维护、不复位；
- 设备快照的 ReconnectCount 取会话重建计数（同连接设备共享同值）——回归用例 N-2 校验口径同步更新。

## 5. 生命周期与门禁细节

### 5.1 设备启停（D3）

| 操作 | 行为 |
|---|---|
| 设备禁用/删除 | `Unmount`；同连接其他设备与物理连接不受影响 |
| 末位设备离场 | 停 Worker → Dispose 驱动 → 移除会话 |
| 设备重新启用 | `GetOrCreateSession`（会话不在则建）→ Mount |
| 设备编辑（变量/模型变化） | 卸载 + 重新挂载（会话复用）；协议/连接变更 → 卸载后按新 ConnectionId 挂载 |

### 5.2 写入门禁（P4.1，D8）

`WriteVariableAsync` 代码零改动（转发属性天然生效），但需**用例覆盖**重建窗口：
- 会话重建中（扇出 Error）→ 写入被「设备未连接」拒绝 ✅（现有门禁第 723 行生效）；
- 会话无驱动/无会话 → `Driver == null` 拒绝 ✅；
- 写入超时兜底（`_deviceWriteTimeoutMs`）与审计链路原样。

### 5.3 配置热更新（P4.2，D6）

```
DeviceConnectionAppService.UpdateAsync（ConfigJson/ReconnectIntervalMs 变更）
  → RuntimeManager.ReloadConnectionAsync(connectionId)
      → 会话存在：ReconnectAsync()（= 4.2 闸门路径：旧驱动 Dispose → 新参数建连）
      → 会话不存在且 IsEnabled：建会话 + 挂载其下已启用设备
DeviceConnectionAppService.UpdateAsync（IsEnabled: true→false）
  → 停止会话：卸载全部设备（设备占位离线）→ 销毁会话
```

- 应用层→运行时单向调用，与 `RegisterDeviceAsync` 现有模式一致；
- 「主数据库配置重启生效」的既有约束不受影响（这是连接配置表数据，非连接串）。

### 5.4 `_reconnecting` 占位字典的归宿

会话级重连**不移除**设备运行时（对比现状 `ReconnectDeviceAsync` 先移除再重建），「重连窗口快照 404」根因消失。`_reconnecting` 仅剩「初始建连失败后运行期重建会话」路径可能短暂触达。**P6 步骤 6.1 以回归证据决定去留：无触发场景 → 删除；有 → 保留并在本文档补记。**

### 5.5 服务关停

`RuntimeManager.StopAsync`：先 `DeviceScheduler.StopAsync`（聚合等待全部 Worker 退出，现状不变）→ 再逐会话 `DisposeAsync`（Dispose 驱动）。顺序保证与现状一致：驱动释放不发生在 Worker 使用期间。

## 6. Worker 批读改造（P5）

### 6.1 现状

```csharp
foreach (var vr in due)
    var newValue = await _runtime.Driver.ReadAsync(vr);   // 逐变量一次网络往返
```

### 6.2 目标（含降级）

```csharp
IDictionary<string, object>? batch = null;
try { batch = await _runtime.Driver.ReadBatchAsync(due); }
catch { batch = null; }                                    // 整体失败 → 走逐变量降级

foreach (var vr in due)
{
    object? raw;
    if (batch != null && batch.TryGetValue(vr.Key, out var v))
    {
        raw = IsErrorMarker(vr, v) ? null : v;             // S7 错误标记 → null（走现有无效路径）
    }
    else
    {
        raw = await _runtime.Driver.ReadAsync(vr);          // 缺项/降级：逐变量补读
    }
    // ……以下与现有逐变量路径完全一致（工程换算/锁内更新/历史/快照/报警/通知）
}

// 单次锁收敛：批读成功路径将 foreach 内的逐变量 Lock.WaitAsync 改为
// 一次 Lock.WaitAsync 内完成全部变量的内存态赋值（值/PreviousValue/UpdateTime/Quality/IsChanged），
// 后续换算/历史/报警在锁外逐变量处理（与现状相同的顺序语义）。
```

### 6.3 契约要点（实施时确认）

- **S7 `ReadBatchAsync` 错误标记**：返回字典中以标记对象（非 null）表示单变量失败（`S7Driver.cs:355` 注释明确「与接口 ReadAsync 以 null 表示失败的语义不同」）——步骤 5.1 需精读判别方式后实现 `IsErrorMarker`；
- `anySuccess` 口径：批读中任一变量成功即轮次成功（与现状一致）；
- `vr.NextPollTime` 推进、`LastError` 记录、质量跃迁通知语义全部保留；
- 批读**不做**跨设备合批（D9 明确本期范围）。

### 6.4 并发安全依据

- S7：驱动内部 `_plcLock` 串行化所有 IO，多 Worker 并发调用同一驱动实例安全（排队）；
- OpcUa：`AcquireSessionForIoAsync` 引用计数保证会话不被脚下关闭；
- Virtual：无状态。

## 7. 明确不做清单

| 项 | 原因 |
|---|---|
| Worker 合并到连接级 | D1（过设计，01 文档问题 A） |
| 跨设备变量合批 | 收益递减、地址归属风险高；列后续可选优化 |
| OPC UA 订阅路径重构 | 休眠代码（无调用方），D10 |
| 数据库迁移 | D11（零迁移） |
| 双轨兼容开关（共享/独立可配置） | 项目惯例「避免两份实现漂移」；一刀切 |
| `_reconnecting` 连接级化 | 保留 per-device；会话级重连不产生移除窗口（§5.4） |
| 快照 DTO / SignalR / 前端改动 | 对外契约零变化 |
